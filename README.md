# 統合小説執筆環境（VSCode拡張機能）

**書くこと以外、引き受けます。** プロットづくり・設定資料づくり・見直し・投稿の準備・電子書籍とPDFでの出版までを、**原稿に手を触れないAI**と一緒に片づけるVS Code拡張機能です。

> **※現在テスト中です。** 動作の確認（実機テスト）が済んでいない機能が含まれます。大切な原稿は、必ずバックアップ（GitHub同期など）を取ったうえでお使いください。

このリポジトリの版：**0.41.0**（0.40.1〜0.40.9 を含む配布版）。Marketplace に出ている版はこれより遅れることがあります。

- 原稿を書き換えるAIはいません。提案を適用するのは、いつもあなたです。
- 手元AI（Ollama / LM Studio）なら無料で、原稿はパソコンの外へ出ません。
- 原稿はただのテキスト/Markdownファイルです。他のエディタとも共存できます。

---

## できること

| 場面 | できること |
|---|---|
| 始める | プロットから／本文から新規作品を作る。既存のフォルダーやGitHubの作品を登録する |
| 書く | 文字数の自動集計、原稿用紙換算、執筆量の記録とグラフ、縦書き／横書きの原稿エディタ、ルビ・傍点、用語の色分け、シーンメモ、読み上げ |
| 資料をためる | 本文から登場人物・能力・組織・場所・世界観を抽出する。名前の点検と付け替え、人物相関図、年表 |
| 整える | 本文からプロットを起こす。各話あらすじ・作品紹介文・キャッチコピー・更新告知文。感情曲線 |
| 直す | 誤字脱字・表記ゆれ・推敲・矛盾・プロット逸脱・伏線の検知。指摘は1件ずつ確認して適用する |
| 相談する | 開いている画面についてAIに日本語で質問する。この拡張機能の使い方も聞ける |
| 持ち運ぶ | GitHubで複数の環境を行き来する。1つのリポジトリ（書庫）に複数の作品を置ける |
| 投稿する | 投稿サイトごとのルビ・傍点記法へ変換してコピーする。投稿状況・ランキングの記録 |
| 出版する | EPUBエディター（表紙・目次・挿絵・奥付）、印刷用のPDF出力 |
| 書き出す | 設定資料集のMarkdown（提供先別にも）、IME辞書（Google日本語入力・MS-IME・ATOK） |

## インストール

VS Codeの拡張機能ビュー（`Ctrl + Shift + X`）で「**統合小説執筆環境**」を検索してインストールしてください。更新はVS Codeが自動で行います。**対応バージョンはVS Code 1.90.0以降です。**

```powershell
code --install-extension nonahisa.novel-ai-assistant
```

再読み込みすると、左端のアクティビティバーに**キーボードと万年筆のアイコン**が追加されます。

<details>
<summary>VSIXファイルから入れる（配布前の版を試す場合）</summary>

GitHubのReleaseに置いたVSIXからも入れられます（新規・上書き更新の両方）。

```powershell
$v = (gh release list --repo nonahisa/novel-ai-assistant --limit 1 --json tagName | ConvertFrom-Json).tagName
gh release download $v --repo nonahisa/novel-ai-assistant --pattern "*.vsix" --clobber
code --install-extension ".\novel-ai-assistant-$($v.TrimStart('v')).vsix" --force
```

画面から入れる場合は、「拡張機能」ビュー右上の `...` →「VSIXからのインストール」で同じファイルを指定します。

</details>

### 必要なもの

作品の管理・文字数・執筆量のグラフは、入れただけで使えます。**AIを使う機能には準備が要ります。** 詳細メニューの「拡張機能の設定 → セットアップを開始 → **セットアップ（必要なものを入れる）**」で、足りないものを一覧から選んで入れられます（取得量を先に表示し、途中で中止できます）。

| 何 | 何のために | 要否 | 大きさ |
|---|---|---|---|
| **Ollama本体** | 手元のパソコンでAIを動かす（無料・原稿を外へ送らない） | 必須 | 約1GB |
| **会話モデル**（`gemma4:e4b`） | 抽出・生成・校正・相談 | 必須 | 約9.6GB |
| **埋め込みモデル**（`bge-m3`） | 相談の意味検索 | 任意 | 約1.2GB |
| **Git** | 複数のパソコンで書く。過去の版へ戻す | 任意 | 約60MB |
| **GitHub CLI** | 非公開リポジトリの作成・取り寄せ | 任意 | 約12MB |

クラウドAIだけを使うならOllamaとモデルは要らず、1台だけで書くならGitとGitHub CLIも要りません。

## 使い方

### 画面

左端のアイコンを押すと4つのビューが並びます。

- **作品一覧**：登録した作品と話数ファイル。右クリックで作品ごとの操作ができます
- **簡単ステップメニュー**：執筆の流れに沿った8つのステップ。迷ったらこちらから
- **詳細メニュー**：全操作の一覧。**分類 → 小分類 → 操作**の3階層です
- **AIに相談**：開いている画面についてAIと話す窓

```
執筆データ      執筆統計／編集履歴／文字数／目標／年表・時期の編集
作品管理        GitHubで作品管理／編集部とやり取り／新作開始／既存作追加
執筆AI支援      相談・プロット／校正・校閲／広報支援／原稿づくり／投稿・書き出し
資料管理        資料抽出／設定資料閲覧
拡張機能の設定  作者／編集者の切り替え／設定管理／AI／セットアップを開始／AI相談の強化
ヘルプ          使い方／ログ／相談のログ／動作を診断／バージョンを確認
```

項目末尾の「**AI**」はAIを呼ぶ操作（クラウドAIは実行のたびに課金）、**数字**は承認待ちの件数です。作品を登録していない間、作品が要る操作は灰色になり理由が出ます。

### 作品を登録する

- **フォルダから追加**：すでに原稿があるフォルダーを指定します。カクヨム・小説家になろうからダウンロードしたファイルでも構いません
- **GitHubから追加**：別の環境で書いている作品を取り寄せます。非公開リポジトリは GitHub CLI（`gh`）経由です
- **新規作品を作成**：**プロットから始める**（`設定/plot.md` を用意）か、**本文から書き始める**（`本文/001.txt` を作る）かを選びます。あとからどちらへも移れます

```
作品名/
├─ 本文/       ← 原稿
├─ 設定/       ← plot.md・設定資料・icons/
├─ .aiwriter/  ← 拡張機能の管理領域
└─ .gitignore
```

**書庫**：既定では1つのGitHubリポジトリに複数の作品を置きます。「作品管理 → GitHubで作品管理 → **GitHubに置く（はじめて）**」で、隣に作品があればまとめるか聞きます。別々に作った作品は「**作品を書庫にまとめる**」で寄せられます（写すだけで、元のフォルダーは消しません）。

### 話数の自動認識

| ファイル名 | 認識 |
|---|---|
| `001.txt` | 第1話 |
| `007_湖畔の誓い.txt` | 第7話「湖畔の誓い」 |
| `003-005_合本.txt` | 第3〜5話 |
| `第12話 再会.md` | 第12話「再会」 |
| `プロローグ.txt` / `幕間1.txt` | プロローグ／幕間 |

全角数字と `〜` の範囲指定にも対応します。**全話が1ファイルにまとまった形式**（小説家になろうのダウンロード）は、中を読んで話ごとに分けて扱います（後書き・リアクションは本文に含めず、文字数にも数えません）。

作品を右クリック →「**新規話数ファイルを追加**」で、最大話数 + 1 のファイルを作れます。

### 文字数と執筆量

ツリーにファイルごと・作品ごとの文字数、ステータスバーに開いているファイル（と選択範囲）の文字数が出ます。ツールチップには総文字数・段落数・原稿用紙換算が出ます。原稿用紙の枚数は、20字×20行に組んだときの行数から数えます。

**本文を保存するたびに、前回からの増減をその日の執筆量として記録します。**「執筆データ → **執筆統計を表示**」でパネルが開きます。

- **執筆量**タブ：日次30日・週次12週・月次12か月・年次のグラフ。目標線・達成率・連続日数
- **話ごと**タブ：話数・タイトル・文字数・枚数・平均比の一覧（押すとその話が開きます）

初回の測定、ファイルの増減、競合件数の変化、pull による増減は執筆量に数えません。記録は `.aiwriter/stats/<環境名>.json` に環境ごとに置き、読むときは合算します。「執筆データ → **全作品の執筆統計を表示**」で全作品の合計を見られます。

### 原稿エディタ（縦書き・横書き）

作品一覧から本文を開くと、この画面（横書き）で開きます。上のバーの「縦書き」か、右クリックの「縦書きで開く」で縦書きになります。

- **ルビは振り仮名、傍点は圏点として組んだまま打ち込めます**（`.md` の `{漢字\|かんじ}` も、`.txt` の `｜漢字《かんじ》`・`《《強調》》` も表示します）
- **登場人物（青）・場所（緑）・能力（紫）・組織（橙）を色分け**します。カーソルを合わせると設定の要点が出て、右クリックで設定資料を開けます。設定の食い違いは「変化かもしれない（外見）: 黒髪（第1〜3話）→ 銀髪（第7話）」のように話数と並べて出ます
- 上のバー：縦書き／横書き・ルビ／傍点（`.md` のみ）・投稿用にコピー・書体・文字の大きさ。下：前の話／次の話、作品の総字数・このファイルの字数・今日書いた字数、「最新話を書く」
- **保存・元に戻す・外部ツールで書き換えられたときの読み直しは、ふつうのエディタと同じです**（文字コードと改行も変わりません）。ファイルの関連付けも変えないので、エクスプローラーから開けば従来どおりです

**読み上げ（音読推敲）**：ツールバーの「読み上げ」→「▶ 読む」でOSの声が読み上げ、読んでいる文が光ります（AIも通信も使いません）。「⚑ 引っかかった」でその文の前にシーンメモを残して一時停止します。

**シーンメモ**：行頭に `//`（全角 `／／` も可）で書くと付箋になります。最初の語がタグです（TODO・要確認・伏線・アイデア・自由）。

```
// TODO ここに潮の匂いの描写を足す
```

蛍光黄色で示され、**字数・投稿用コピー・PDF・プレビュー・AIへ渡す本文には入りません。**「執筆AI支援 → 原稿づくり → **シーンメモを開く**」で一覧が開き、「次へ」「戻る」で話をまたいで飛べます。

### ルビと傍点

本文を範囲選択して**右クリック →「ルビを振る」「傍点を付ける」**。漢字の直後にカーソルがあれば、選ばなくても拾います。**振れるのは Markdown（`.md`）だけ**です。

| | 書き方 | 表示 |
|---|---|---|
| ルビ | `{漢字\|かんじ}` | 漢字の上に「かんじ」 |
| 傍点 | `{{強調}}` | 各文字の右上に点 |

**投稿サイト用に変換**：右クリック →「**投稿サイト用に変換してコピー**」。クリップボードへ入れるだけで、**原稿は書き換えません**。

| サイト | ルビ | 傍点 |
|---|---|---|
| カクヨム／ネオページ | `｜漢字《かんじ》` | `《《強調》》` |
| 小説家になろう／アルファポリス | `｜漢字《かんじ》` | `｜強調《・・》` |

**取り込む**：「執筆AI支援 → 投稿・書き出し → **投稿サイトのルビを取り込む**」で、サイトの記法を拡張機能の書き方へ読み替えます（件数を先に表示）。

**読み仮名からまとめて振る**：設定資料パネルの「**ルビを追加**」。範囲（すべての話／開いている話／話数を選ぶ）と、最初の1回だけか全部かを選べます。

### テキストをMarkdownにする

「執筆AI支援 → 原稿づくり → **本文を .md にする**」、または話数を右クリック。**中身は変えず、名前だけ変えます**（投稿サイト記法のルビ・傍点だけ読み替えます）。戻すときは名前を `.txt` に戻すだけです。

## AI機能

### AIを設定する

サイドバー右上の歯車、コマンドパレット（`Ctrl+Shift+P`）の「小説執筆: AI設定」、または「拡張機能の設定 → AI → **AI設定**」。使うAIを選ぶと接続テストが走り、モデルの一覧から選べます。

| AI | 費用 | APIキーの発行元 |
|---|---|---|
| Ollama | 無料・オフライン可 | 不要 |
| LM Studio | 無料・オフライン可 | 不要 |
| Gemini | 無料枠あり。超えると課金 | aistudio.google.com |
| さくらのAI Engine | 無料枠あり。超えると課金 | さくらのクラウド コントロールパネル |
| ChatGPT | 実行するたびに課金 | platform.openai.com |
| Claude | 実行するたびに課金 | console.anthropic.com |

**APIキーはOSの資格情報ストアへ保存し、`settings.json` や作品フォルダーには書き込みません。** ログでは伏せ字にします。クラウドAIでは、呼び出しの多い処理の前にトークン量の目安を表示します。

- **Ollama**：事前に起動してモデルを取得します（`ollama pull gemma4:e4b`）。「セットアップを開始 → **Ollamaのセットアップ**」で足りないところだけ案内します
- **LM Studio**：モデルを読み込み、左の「Developer」からローカルサーバーを開始してから使います（APIキー不要）
- **コンテキスト長**：ChatGPT・さくらのAI Engine・LM Studio はAPIから取得できないため、下記の `contextWindow` に実際の値を入れてください。**実際より大きいと、入力が黙って切り捨てられます**
- **機能ごとにAIを割り当てる**（拡張機能の設定 → AI）：8つの単位（抽出／誤字脱字／推敲／矛盾／逸脱／伏線／生成／相談）で使い分けられます
- **AIが実際に読める長さを測る**（同上・AIを使います）：合言葉を入れた詰め物を送り、実際に読める上限を割り出します。結果は「設定に書く」を押したときだけ設定へ入ります

### 設定資料をためる

- **まとめて抽出**（資料管理 → 資料抽出）：全話から登場人物・能力・組織・場所・世界観を1回の応答でまとめて取り出し、`設定/characters/` などのJSONと、読み用の `characters.md`・`abilities.md`・`organizations.md`・`locations.md`・`world.md` を作ります
- **設定資料集を出力**（執筆AI支援 → 投稿・書き出し）：JSONから上の5つのMarkdownを作り直します（AIを呼びません）
- **設定資料集を閲覧**（資料管理 → 設定資料閲覧）：左が一覧、右が詳細。名前・読み・別名・性別・役割・性格・外見・説明・作者メモをその場で直せます。**保存した項目は、以後の抽出で上書きされません**
- **名前の点検**：響きの近い名前を強さと理由つきで並べます（AI不要）。「候補を出す」で新しい名前を10件（AIを使います）、「付け替える」で本文の登場箇所を提案パネルに並べ、1件ずつ／まとめて適用できます
- **人物相関図**：「関係」と「呼称」から図を作ります（AI不要）。人物ごとの中心図とSVGの書き出しもできます
- **年表**（執筆データ → 年表）：1行が1話で、登場人物・作中の変化・能力の習得・呼称・伏線・あらすじが並びます。「時期・系統を編集する」で時期を割り当てると時系列順に並べ替えられます
- **一覧に項目を増やす**：誕生日・身長などを人物設定に足せます（定義は `設定/custom_fields.json`）
- **AIで再読込**：各項目に入れる内容をAIが提案します。**空欄を埋める提案だけが最初からチェックされ**、既存の内容を置き換える提案には警告が付きます
- **AIに相談する**（設定資料パネル）：人物についての質問や掘り下げ。承認したものだけが `aiNotes` へ追記されます
- **重複をまとめる**：「リン」と「リンセップ・アウクト」のような重複を1件にします（自動では統合しません）
- **更新分を反映**：再抽出で見つかった既存人物への変更は**承認待ち**になり、何が変わるかを見てから取り込めます

抽出するもの：名前、別名、役割、性格、外見、一人称、**呼称**（誰が誰をどう呼ぶか。相手ごと・呼び方ごと）、関係、登場話数。**同じ相手への複数の呼び方は、話数付きで全部残します。** 保存は1人1ファイル（`char_001_月島灯.json`）で、変更のないファイルは再処理しません。

**他のAIに頼む**：`設定/_schema/` にAI向けの定義（日本語の `README.md` と JSON Schema）を書き出しています。Copilot・Claude Code などに「`設定/_schema/README.md` を読んでから `設定/characters/` を更新して」と頼めます。外部から設定JSONが書き換えられると通知するので、内容を確認してから取り込めます。

### 整える・直す・相談する

- **本文からプロットを起こす**：各話あらすじを材料に、ログライン・テーマ・世界観・舞台・人称・行動原理・あらすじ・主要人物を `設定/plot.md` へ書きます。**作者が書いた項目は、確認せずに書き換えません**
- **各話あらすじを生成**：あらすじと一緒に**感情曲線**（盛り上がり0〜10・明暗−5〜+5）を測り、`設定/synopsis.md` にグラフで入ります
- **作品紹介文・キャッチコピー・章立て**：本文から下書きを作ります
- **更新告知文を作る**（広報支援）：ネタバレしない告知文を3種（X用・活動報告／近況ノート用・後書き用）。**貼るのは作者です**（サイトへ自動で書き込みません）
- **誤字脱字・推敲・矛盾・プロット逸脱・伏線の検知**（校正・校閲）：候補を「提案」パネルに並べ、**1件ずつ確認して適用します**。方言や口癖は「**直さない語**」に登録して守れます
- **表記ゆれを検知**：「良い／よい」のような揺れを作品全体から探します（**AIを使いません**）。どちらに揃えるかを選ぶと、少数派の箇所が提案パネルに並びます
- **AIに相談する**：左サイドバーの「AIに相談」、本文の右クリック、または「執筆AI支援 → AIに相談する」。いま開いているファイルについて日本語で質問できます（範囲を選ぶとそこについての相談になります）。プロット・紹介文・キャッチコピー・各話あらすじは、確かめてボタンを押すと書き込めます（**本文は対象外**）

**AIに渡す本文**：長い作品はそのまま渡せないため、その名前が出てくる場面だけを集めて渡します（既定で30箇所・12,000字まで、作品全体から均等に）。相談では、質問に近い場面を本文・設定資料・各話あらすじから探し、出どころ（`《本文／第105話》`）を添えて渡します。「拡張機能の設定 → AI相談の強化 → **意味検索（ベクトルDB）の準備**」を入れると言い換えでも見つかりやすくなります（埋め込みモデル約1.2GB、手元のOllamaで作るので無料。**既定は「切」**）。

### ログ

「ヘルプ → **ログを開く**」。`.aiwriter/logs/actions.log` にも保存されます（Gitの同期対象外）。本文そのものは書かず、APIキーらしき文字列は伏せ字にします。

## 編集部の方と一緒に使う

設定 `novelai.mode` を `editor` にすると、**本文の校正・校閲だけ**が使える状態になります（誤字脱字・表記ゆれ・推敲・直さない語・同期と競合解決・文字数・設定資料の閲覧）。設定資料の抽出や更新、プロット、あらすじ、執筆統計、新規作品の作成は押せなくなり、理由が出ます。

- **編集部は本文を書き換えません。**「適用」を押しても提案として置かれます。作者側で「校正・校閲 → **編集部からの提案を見る**」を開き、1件ずつ採るか見送るかを決めます（採る直前に本文と照らし合わせます）
- **校閲ロック**：「校正・校閲 → **校閲を始める／終える**」で、いま開いているファイルが「校閲中」になります。ファイル単位なので同時に別の話を書け、作者はいつでも外せます
- **編集履歴**：「執筆データ → **編集履歴を見る**」で、作者（●）・編集者（▲）・AI（■）を色分けして並べます（`.aiwriter/history/edits.jsonl`。GitHubで同期されます）
- **競合**：それぞれの版を最後に触った人の名前（gitの `user.name`）が出ます
- 編集部がGitHub経由で設定資料を直したときは、通知の「**この変更を守る**」で以後AIに上書きさせません

「作品管理 → GitHubで作品管理」から、同期・競合解決・復元を行います。Gitの言葉は要りません。

**復元**：日時と件名の一覧から版を選ぶと、**戻すと何が起きるか**（内容が戻る／消える／復活するファイル）を先に見せます。いまの原稿は戻す前に履歴へ自動で残すので、やり直せます。

## 投稿・出版・書き出し

- **投稿サイト用に変換してコピー**（上記「ルビと傍点」）
- **投稿状況の記録**：投稿サイトごとの投稿状況・作品情報・ランキングを手元に記録します（手入力のみ。**サイトへの自動アクセスはしません**）
- **EPUBエディター**：表紙・目次・挿絵・奥付・人物紹介を、プレビューで確かめながら組みます。飾り（SVG）は `設定/書籍/飾り/` か `novelai.epub.ornamentFolder` から足せます
- **PDF出力**：印刷用の組版
- **設定資料集のMarkdown**：編集部向け・イラスト発注向けなど、提供先別にも出せます
- **IME辞書**：Google日本語入力・MS-IME・ATOK 用

**文字コード**：UTF-8（BOMの有無どちらも）と Shift_JIS を自動判別して読み込み、**同じ文字コード・改行コードのまま書き戻します**。

## 注意

- **AIの結果は作者が確認してください。** 抽出結果は本文との逐語照合で根拠のないものを除きますが、精度を保証するものではありません
- **本文（原稿）をAIが勝手に書き換えることはありません。** 適用は作者が1件ずつ押したときだけです。書き戻す前に本文が変わっていないかを照合し、変わっていれば中止します
- **安全対策**：Gitの未解決競合（`<<<<<<<`）を含むファイルは処理しません。未保存の変更が残る場合は開始せず、壊れたJSONがあれば上書きせず中止します
- **対応する投稿サイトの記法**：カクヨム・ネオページ・小説家になろう・アルファポリス
- **実データで確かめたAIは Ollama・Gemini・さくらのAI Engine の3つです。** LM Studio・ChatGPT・Claude は実サービスへ繋いだ確認をしていません
- **ブラウザ版（vscode.dev / github.dev）** は作品の登録と一覧表示までを確認済みです。AI接続・書き込み・GitHub同期は未確認で、外部プロセスを使う操作は押せなくなり理由が出ます
- **未実装**：提供先別の設定資料エクスポート、プロットモード専用画面、相談パネルからの設定資料への書き込み

## 開発者向け

```powershell
npm install          # 依存の取得
npm run build        # ビルド
npm run watch        # 監視ビルド
npm run check        # 型検査＋単体テスト＋本番ビルド
```

VS Codeで `F5` を押すと拡張機能開発ホストが起動します。

```powershell
npm run package:vsix     # release/ にVSIXを作る（リリースゲートを通ります）
npm run verify:vsix      # 中身・隔離インストール・版を検証する
npm run release:github   # タグを押して Release を作り、VSIXを添付する
```

`release:github` は、作業ツリーがきれいで `main` が `origin/main` と同じで `gh` にログイン済みでなければ止まります。ノートは `docs/releases/vX.Y.Z.md`、無ければ `CHANGELOG.md` の先頭の節を使います。**Marketplaceへの公開（`npm run publish:marketplace`）は別の操作です。**

さくらのAI Engine のスモークテストは GitHub Actions の **Sakura AI Engine Smoke Test** で走ります（シークレット `SAKURA_AI_ACCOUNT_TOKEN` が要ります）。設計・仕様の文書は `docs/` にあります。
