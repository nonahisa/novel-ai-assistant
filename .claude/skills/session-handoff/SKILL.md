# 要約の前の引き継ぎ

会話が上限の約97%（このリポジトリでは設定で60%）に達すると、Claude Code が会話を要約（コンパクト）する。**要約は自分では起こせない**（作者の `/compact` か自動だけ）。要約では細部が落ちるので、**その前に、続きに要るものを引継ぎ書へ書き出しておく**（作者の依頼、2026-10-04「スキルにオートコンパクト組み込めませんか？」→「進めて」）。

## いつ

- 長い作業の区切りで `mcp__ccd_session_mgmt__get_usage` を見る。`context.percentUsed` が **50%を超えたら**書き出す（作者の指示、2026-10-05「60％ぐらいで仕掛けてください」。要約そのものを 60% で起こす設定〔`.claude/settings.local.json` の env `CLAUDE_CODE_AUTOCOMPACT_PCT_OVERRIDE`〕を入れたので、その手前で書き出す）
- 55%を超えたら、新しい大きな作業（担当を何人も立てる・長い読み込み）を始める前に必ず書き出す
- 作者が「寝ます」「外出します」と言ったときも書き出す（戻ったときの要約の質が上がる）

## 何を書くか（引継ぎ書8章の末尾に `### 【引き継ぎ】<日時>：会話の要約の前に`）

1. **動いている担当**：担当の印（agentId）・作業場の枝・何を頼んだか・報告待ちか
2. **取り込み待ち**：push 済みで main に入れていない枝と、入れる条件（例：ノートPCの E2E が通ったら）
3. **ほかのセッションへの頼みごと**：ノートPCのテスト環境などに何を頼んでいて、返事待ちか
4. **作者の判断待ち**：選択肢で訊く予定のもの（短く）
5. **作者の手待ち**：開発ホストで見てもらう項目・試してもらうページなど
6. **次にやること**：順番つきで3〜5行
7. **数字**：版（手元・GitHub Release・Marketplace）、実機確認の進捗率、今週の使用量
8. **片づけ待ち**：残っている作業場（`node_modules` がジャンクションのものは必ず印を付ける）

書いたら `node scripts/handoverToc.mjs`、パス指定でコミットして push する。

## 書かないもの

- 考えた過程・経緯の語り（スキル docs-sync の書き方）
- 引継ぎ書の別の節にもう書いてある細部（節の名前で指せば足りる）
