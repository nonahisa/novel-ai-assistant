# 実機確認の進め方

## 守ること

- **開発ホスト（F5）で操作するときは、名前の末尾が `_確認用` の作品だけを使う**（`Documents\確認用コピー\` 配下）。作者の原稿では試さない
- **作者に頼むのは、画面の自動テストでも computer-use でもできないものだけ。** 打ち込み・キー・右クリック・修飾キーは画面の自動テスト（スキル `e2e`）で届く。残るのは **IMEの本物の変換・ほかのアプリとのキーの取り合い・組み上がりの見た目の良し悪し・F5の開発ホストそのもの**。頼むときは `AskUserQuestion`（選択肢）で出し、「Esc を押してください」を文章で書かない
- **「作者の手が要る」と書く前に、一度は試す**（フォルダー選択の窓はクリックで辿れる、設定に残る操作はソースで確かめられる、のように試さずに渡しかけたことがある）
- **確かめる手だては、この順で選ぶ。上にあるものでできるなら、下は使わない。**
  1. **ファイル**——書かれたもの・印・ログ（`.aiwriter/logs/actions.log`、`.gitignore`、`.mcp.json`）
  2. **テスト**——既存のテストが覆っていないか先に探す。無ければ足す
  3. **MCP**——`novel.material` / `novel.detect` / `novel.prompt` / `novel.validate` / `novel.run`。**中身の確認はここでほとんど届く**
  4. **画面の自動テスト（E2E。スキル `e2e`）**——**押して起きること**はここ。キー・打ち込み・右クリック・タブの数・カーソルの位置・ダイアログの文言・パネルの行。**作者の画面を取らない**。書いたテストは残って毎回見張る
  5. **computer-use**——E2E で起こせないもの（作者の実際の開発ホスト・作者の環境でしか起きない状態）だけ。**作者が画面を使っているときは使わない**
  6. **作者**——IMEの本物の変換・見た目の良し悪し・F5。**ここだけ**
- **このセッションの MCP サーバーが古いとは限らない。** `mcp.version` の `bundle.stale` を見る。古ければ別プロセスから撃つ（下の節）
- **機械にできる確認はテストへ移す。** 覆った項目は `- [x]（機械で確認：test名）` に、作者が押したものは `- [x]（日付 作者が確認）` に。**済んだ記録は引継ぎ書2章へ写してから、一覧から消す**（不具合・判断待ちは残す）
- **平日は作者の手が要らないテストを優先。** 手が要る項目は溜めて、休みの日にまとめて頼む
- **不具合・使いにくさを見つけたら、原則として自分で直さず渡す。** 例外は「本体が Opus 以上で、かつ1か所の文言・条件の付け足し程度」。**台帳の形・書き込む道・数字の決め方が変わるものは渡す。** 揃えるのは再現手順・画面の文言そのまま・ログの該当行・「何が起きるべきか」。見つけた人がそのまま直すと、その人の見立てが検算されないまま製品へ入る（見積もりが23倍過大な件で実際そうなった）
- **棚卸しでは「この画面はまだあるか」ではなく「この項目のとおりに押したら何が起きるか」を読む。** 消えた画面は自分から名乗るが、**古い前提は名乗らない**（3巡で落とせたのは3件、前提が古かったのは8件）。ずれるのは決まって**どこに出るか／どれだけ待つか／どの道順で行くか**
- **壊れていると言う前に**：探し方を変えて2通り／押せたことを確かめる／痕跡の作り主を訊く（印・記録に痕跡があるか見る）
- **AIの出力が悪いとき、プロンプトのせいだと結論する前にモデルを差し替える**

## 作者と一緒に確かめる形

作者の手は F5 と「出た／出ない」の返事だけで済ませる。

1. 手順と「何が出るはずか」を先に書く
2. `AskUserQuestion` で「準備できた」の合図をもらう
3. こちらから撃つ（下の「MCP を別プロセスから撃つ」）か、画面を撮って一緒に見る
4. 記録・印をこちらで読んで裏付ける（作者の返事と機械の痕跡の両方）
5. 済んだ項目をその場でリストに反映し、コミットする

## 画面の自動テストへ移す（画面の確認の第一の道）

**起点は仕分けの表 `docs/measurements/2026-10-12-field-triage.md`。** 未済の項目を F（ファイル）・T（既存テスト）・E（E2E へ移せる）・H（作者の手が要る）に分けてあり、**E は「束」（1本のテストで覆える組。E1〜E13）にまとめてある**。書き方・部品はスキル `e2e`。

1. **束ごとに選ぶ**：表の「E の束」から、済みの印の無い束を1つ取る（易→中→難の順）。束の行に、項目の行番号・使う部品・見本の作り方が書いてある
2. **書くのは implementer**（何を見張るかを決める仕事）。リーダーは束の名前・項目・「何が起きるべきか」を指示に書く。1人に1束
3. 母艦で作者がいる間は走らせない。ノートPCに頼むか、作者が離れているときに回す
4. 通ったら、実機確認リストの各項目を `- [x]（日付 機械で確認：e2e/<ファイル>「<テスト名>」）` に、仕分けの表の束の行に「済み（日付・どこで通過）」を添える。**製品の不具合で落ちたら直さず、`- [ ]` のまま再現の手順とテスト名を添えて報告**（直すのは別の implementer）
5. 走らせたあと、`novelai-e2e-` を引数に含む `Code.exe` が残っていないことを確かめる
6. 新しく仕分けるときも同じ形（区分・束・確かめ方の列）で `docs/measurements/` に日付つきで置く

## 画面は、こちらで押せる（computer-use。E2E の次の道）

**作者の画面を押すのは E2E で届かないときだけ**（作者が同じ機械で作業していると前面が取れずに止まり、`open_application` が空の窓を作者の画面に出す）。それでも**作者に頼む前に、まず自分で押す。** 開発ホストが開いていれば、クリックで辿れる（AIを呼ばなければ課金ゼロ）。

```
request_access({ apps: ["Visual Studio Code"], reason: "…" })
switch_display({ display: "<VS Code のあるモニター名>" })   ← 2画面。許可の返り値が教えてくれる
screenshot({ scale: 0.6 })
```

**できること・できないこと**（VS Code は階級 `click`）。

| | |
|---|---|
| できる | 左クリック・スクロール・ホバー・スクリーンショット・ズーム |
| **できない** | **打つ・キーを押す・右クリック・修飾クリック・ドラッグ**。`Ctrl+Shift+P` も `Esc` も **F5** も押せない |

**だから、コマンドパレットではなくサイドバーの詳細メニューから辿る。** 迂回しない。

### つまずいた点（同じ轍を踏まない）

- **座標は「フレーム」で渡す。** `scale: 0.6` の絵を見て座標を読むと**0.6倍ずれる**。返り値の `coordinate frame: 1456x819` がフレームで、**絵の座標 ÷ 0.6** がそれに当たる
- **ダイアログの外を押すと Windows がはねて、作者の耳に「エラー音」が鳴る。** **押す前にボタンの位置をズームで確かめる**（モーダルは閉じないので、外し続けると鳴り続ける）
- **サイドバーが狭いと進まない。** 「作品一覧」と「簡単ステップメニュー」の見出しを押して**畳む**と、詳細メニューが一望できる（見た目だけの操作なので戻せる）
- **作品は一覧の名前で決めない。** ホバーすると**道が出る**ので、`確認用コピー` の下かどうかを必ず読む——**同じ題の原稿が `novel` の下にある**
- **「矛盾を検知」と「矛盾検知」は別の機能。** 詳細メニューで隣り合っている。`package.json` のコマンド名で確かめてから押す
- **クリック1回でクリップボードが空になる**（3回誤診しかけた）。コピー→取り込みの確認は、こちらが画面に触らずに作者の手だけで通す
- **VS Code が開いているときに `open_application` を呼ぶと、空の窓がもう1つ開く。** 前に出すだけなら呼ばない。デスクトップが前に出てクリックが止まったら、`File Explorer` をクリックだけの許可で足して窓を押す
- **拡張機能の再起動のあと、拡張機能の一覧が並び直る。** 同じ座標を続けて押すと別の拡張機能を開く。押す前に毎回ズームで確かめる
- **選ぶ画面（QuickPick）は、作者がこちらの会話へ答えに来ると閉じる。** 「選んでから答えてください」と最初に頼む
- **Chrome の拡張の右クリックの項目は、2つ以上あると「拡張の名前 ›」の中にまとめられる**
- **作者の Chrome が読み込んでいるフォルダー（novel-post-helper）を担当が書き換えている間は、拡張の再読み込みを頼まない**
- **作者が「知らせが出ない」と言ったら、まずステータスバーと通知の箱（ベル）を見てもらう。** 知らせが遅れて出ることがある（③-3）
- **前提を確かめる：記録していない変更が残っていると、開いたときの点検は合わせずに止まる**（③-1 の1回目）
- **作者が答える問い（作家タイプ診断・ターゲット読者の「書き方の判断」など）には答えない。** 出てきたら「取りやめる」で閉じる

### 押してはいけないもの

- **課金のかかる実行**（さくらのAI・Gemini など）。確認画面で止めて作者に聞く
- **作者の原稿**（`novel` の下）を対象にした操作。**名前が同じでも道で見分ける**
- **許可の取り消し。** 戻すには外部AIからノックさせる必要があり、作者の手が要る

### それでも作者の手が要るもの

**F5**（開発ホストの起動）、**IMEの変換**、**組み上がりの見た目の良し悪し**。computer-use で押せない打ち込み・右クリックは、作者へ回す前に E2E で届かないかを見る。

## ブラウザ版は作者の手なしで確かめられる

`npx @vscode/test-web --browser none --port 3111 --extensionDevelopmentPath=. test/fixtures/web-work` で起こし、内蔵ブラウザ（右の枠）で `http://localhost:3111` を開く。決まった流れは `npm run test:web` が見張っている。終わったらプロセスを止める。

## MCP で何が届くか

**このセッションから直接叩ける。** まず `mcp.version` の `bundle.stale` を見る——`false` なら最新なので、別プロセスを起こす必要はない。

| 確かめたいこと | 道具 | どこを見るか |
|---|---|---|
| **突き合わせなかった人物** | `novel.material`（feature=contradiction、filePath、numCtx） | `chunks[].missedCharacters`。**あわせて `previousSynopses` を読むと、その人が直前の話に居たことまで裏が取れる** |
| 渡る材料の量・巻き戻し | 同上 | `settingsCount` / `characterDetails` / `carriedOverChapters` |
| 引き継ぎが効いているか | 同上 | `carriedOverChapters` が空か |
| プロンプトの中身 | `novel.prompt` | 送る文字列そのもの。**AIは呼ばない** |
| 検算が何を落とすか | `novel.validate` | 落とした理由つき |
| 実際の結果 | `novel.run` | **AIを呼ぶ＝有料なら課金**。作者の許可を取ってから |
| 走査の結果（話数・ファイル） | `novel.scan` | 画面の一覧と突き合わせられる |

**許可の印が要る。** `.aiwriter/external-access.json` に `claude-code` が居て、その道具（または `"*"`）が並んでいること。作品ごとに許した道具が違うので、先に印を読む。**印はこちらで書かない**——拡張機能だけが書く。

## 届かないなら、届く道を足す

**「画面を押すしかない」で止めない。** 押すしかないのは、**組まれた見た目**と**押して初めて起きること**だけである。それ以外で届かないなら、**届く道を足すことを検討する**。実例：実行前の確認の断りと目安は `views/` で組み立てていて MCP から届かなかったので、`ai/` へ移して **`novel.notice`**（走らせずに断りと目安を返す道具）を足した。

**足すときの線引き**：

- **AIを呼ばない・本文を送らない道具にする。** 読むだけなら、課金も待ち時間も増えない
- **許可の印は、ほかの道具と同じ作法で通す。** 試験のために迂回路を作らない
- **製品の文言を、試験用に複製しない。** 同じ関数を呼ぶ形にする——複製すると片方だけ古くなる
- **`vscode` を持ち込まない**（実装ルール7）。持ち込んだ瞬間に MCP から届かなくなる

## MCP を別プロセスから撃つ

**このセッションに繋がっている MCP サーバーは、セッション開始時の古い束のまま**である（`mcp.version` で分かる）。新しい束を使うには別プロセスを起動する。

```powershell
$env:ELECTRON_RUN_AS_NODE = $null
$text = Get-Content -Raw -Encoding utf8 <指示ファイル>
$text | claude -p --mcp-config .mcp.json --allowedTools "mcp__novel-ai-assistant__<道具>,ToolSearch" --model claude-haiku-4-5-20251001
```

- **指示ファイルは UTF-8 で Write する**（日本語パスを引数に直接書かない）。指示は英語で短く、「結果だけ報告・userPrompt は出さない・ほかの道具は呼ばない・再試行しない」を書く
- 道具名は `.` を `_` にした形（`opening.prompt` → `mcp__novel-ai-assistant__opening_prompt`）
- `ToolSearch` を allowedTools に入れないと、Haiku が道具を呼べないことがある
- **束を作り直してから撃つ**（`npm run check` か `npm run build`。`dist/mcp-server.mjs`）

**印と記録の場所**：

| 何 | どこ | 誰が書く |
|---|---|---|
| 許可の印 | `.aiwriter/external-access.json` | **拡張機能だけ**。こちらで書き換えない（設計違反で、分類器も止める）。試すなら**一時フォルダーに作り物の作品**を作って印を置く |
| ノックと利用の記録 | `.aiwriter/history/external.jsonl` | MCP が追記。`ok:false`＋「許可が無いので断りました」がノック |
| 検算の結果 | 道具の返り値 | — |

## AIの出来を実データで測る

**モデルを比べる・頼み方の工夫を比べる・手元の Ollama を複数の担当で使うときは、スキル `ai-bench` を読む**（正解の作り方・製品と同じ道・採点・手元のAIの札・MCP を起こすときの保管庫）。

- **見逃しと誤検出の両方を数える。** 片方だけでは、何も指摘しない実装が満点になる
- **製品と同じ経路を通す**（`runner: "ollama"`、`*.run`）。`prompt` だけ呼んで `validate` を通さない測り方は、製品に無い不具合を見つけたことになる
- 仕込み（わざと入れた矛盾・誤字）は**一時フォルダーの写し**に入れる。確認用コピーも作者の作品の写しなので、書き換えない
- 測った結果は引継ぎ書8章に「何を・どのモデルで・何件中何件」で残す。実機確認リストの該当項目には `→ **MCP で測れる**：道具名` の道しるべが付いている
