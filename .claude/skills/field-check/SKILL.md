# 実機確認の進め方

## 守ること

- **開発ホスト（F5）で操作するときは、名前の末尾が `_確認用` の作品だけを使う**（`Documents\確認用コピー\` 配下）。作者の原稿では試さない
- **作者に頼むのは、computer-use でできないものだけ**（作者の指示、2026-09-21）。できないのは **F5・打ち込み・右クリック・修飾クリック・ドラッグ・IMEの変換・組み上がりの見た目の良し悪し**——**それ以外は自分で押す。** 頼むときは `AskUserQuestion`（選択肢）で出し、「Esc を押してください」を文章で書かない
- **「作者の手が要る」と書く前に、一度は試す。** 2026-09-21 に、フォルダー選択の窓（クリックで辿れる）・プロットの有無（試していない）・設定に残る操作（ソースで確かめられる）・26b（他の大きいモデルで代われる）を、**試さずに作者へ渡しかけた**
- **ファイル優先。** 画面を撮るのは「組まれた見た目」と「押して初めて起きること」だけ。ファイル・記録・印で確かめられるものは、こちらで確かめる
- **機械にできる確認はテストへ移す。** 覆った項目は `- [x]（機械で確認：test名）` に、作者が押したものは `- [x]（日付 作者が確認）` に。**済んだ記録は引継ぎ書2章へ写してから、一覧から消す**（不具合・判断待ちは残す）
- **平日は作者の手が要らないテストを優先。** 手が要る項目は溜めて、休みの日にまとめて頼む
- **不具合・使いにくさを見つけたら、自分で直さない**（作者の指示、2026-09-21）。**揃えるところまでがテスト担当の仕事**——再現手順・画面の文言そのまま・ログの該当行・「何が起きるべきか」。そこまで書いて **implementer へ渡す**。見つけた人がそのまま直すと、**その人の見立てが検算されないまま製品へ入る**（2026-09-21、見積もりが23倍過大な件で実際そうなり、最初の見立てが不正確だった）
- **壊れていると言う前に**：探し方を変えて2通り／押せたことを確かめる／痕跡の作り主を訊く（「やってるはず」と言われたら、印・記録に痕跡があるか見る——2026-09-16、`tools: ["*"]` と時刻で裏付けが取れた）
- **AIの出力が悪いとき、プロンプトのせいだと結論する前にモデルを差し替える**

## 作者と一緒に確かめる形（F-105 で通した型）

**MCP を別プロセスから撃って確かめる形**（画面の操作は、いまは computer-use でこちらが押せる——下の節）。作者の手は F5 と「出た／出ない」の返事だけで済む。

1. 手順と「何が出るはずか」を先に書く
2. `AskUserQuestion` で「準備できた」の合図をもらう
3. こちらから撃つ（下の「MCP を別プロセスから撃つ」）
4. 記録・印をこちらで読んで裏付ける（作者の返事と機械の痕跡の両方）
5. 済んだ項目をその場でリストに反映し、コミットする

## 画面は、こちらで押せる（computer-use。2026-09-20 に通した）

**作者に頼む前に、まず自分で押す。** これまで「作者が F5、こちらは見るだけ」と書いていたが、**開発ホストが開いていれば、こちらがクリックで辿れる。** 実際に A-3・B-1・B-2a・B-4 をこちらだけで通した（**AIは1回も呼ばず、課金ゼロ**）。

```
request_access({ apps: ["Visual Studio Code"], reason: "…" })
switch_display({ display: "<VS Code のあるモニター名>" })   ← 2画面。許可の返り値が教えてくれる
screenshot({ scale: 0.6 })
```

**できること・できないこと**（VS Code は階級 `click`）。

| | |
|---|---|
| できる | 左クリック・スクロール・ホバー・スクリーンショット・ズーム |
| **できない** | **打つ・キーを押す・右クリック・修飾クリック・ドラッグ**。`Ctrl+Shift+P` も `Esc` も **F5** も押せない |

**だから、コマンドパレットではなくサイドバーの詳細メニューから辿る。** 迂回しない。

### つまずいた点（同じ轍を踏まない）

- **座標は「フレーム」で渡す。** `scale: 0.6` の絵を見て座標を読むと**0.6倍ずれる**。返り値の `coordinate frame: 1456x819` がフレームで、**絵の座標 ÷ 0.6** がそれに当たる
- **ダイアログの外を押すと Windows がはねて、作者の耳に「エラー音」が鳴る。** 2026-09-20 に実際に鳴らして、作者から「エラー音が鳴っています」と言われた。**押す前にボタンの位置をズームで確かめる**（モーダルは閉じないので、外し続けると鳴り続ける）
- **サイドバーが狭いと進まない。** 「作品一覧」と「簡単ステップメニュー」の見出しを押して**畳む**と、詳細メニューが一望できる（見た目だけの操作なので戻せる）
- **作品は一覧の名前で決めない。** ホバーすると**道が出る**ので、`確認用コピー` の下かどうかを必ず読む——**同じ題の原稿が `novel` の下にある**
- **「矛盾を検知」と「矛盾検知」は別の機能。** 詳細メニューで隣り合っている。`package.json` のコマンド名で確かめてから押す

### 押してはいけないもの

- **課金のかかる実行**（さくらのAI・Gemini など）。確認画面で止めて作者に聞く
- **作者の原稿**（`novel` の下）を対象にした操作。**名前が同じでも道で見分ける**
- **許可の取り消し。** 戻すには外部AIからノックさせる必要があり、作者の手が要る

### それでも作者の手が要るもの

**F5**（開発ホストの起動）、**打ち込み**（相談の質問・原稿の入力）、**右クリック**（設定資料の呼び出し）、**IMEの変換**、**組み上がりの見た目の良し悪し**。

## MCP を別プロセスから撃つ

**このセッションに繋がっている MCP サーバーは、セッション開始時の古い束のまま**である（`mcp.version` で分かる）。新しい束を使うには別プロセスを起動する。

```powershell
$env:ELECTRON_RUN_AS_NODE = $null
$text = Get-Content -Raw -Encoding utf8 <指示ファイル>
$text | claude -p --mcp-config .mcp.json --allowedTools "mcp__novel-ai-assistant__<道具>,ToolSearch" --model claude-haiku-4-5-20251001
```

- **指示ファイルは UTF-8 で Write する**（日本語パスを引数に直接書かない）。指示は英語で短く、「結果だけ報告・userPrompt は出さない・ほかの道具は呼ばない・再試行しない」を書く
- 道具名は `.` を `_` にした形（`opening.prompt` → `mcp__novel-ai-assistant__opening_prompt`）
- `ToolSearch` を allowedTools に入れないと、Haiku が道具を呼べないことがある
- **束を作り直してから撃つ**（`npm run check` か `npm run build`。`dist/mcp-server.mjs`）

**印と記録の場所**：

| 何 | どこ | 誰が書く |
|---|---|---|
| 許可の印 | `.aiwriter/external-access.json` | **拡張機能だけ**。こちらで書き換えない（設計違反で、分類器も止める）。試すなら**一時フォルダーに作り物の作品**を作って印を置く |
| ノックと利用の記録 | `.aiwriter/history/external.jsonl` | MCP が追記。`ok:false`＋「許可が無いので断りました」がノック |
| 検算の結果 | 道具の返り値 | — |

## AIの出来を実データで測る

- **見逃しと誤検出の両方を数える。** 片方だけでは、何も指摘しない実装が満点になる
- **製品と同じ経路を通す**（`runner: "ollama"`、`*.run`）。`prompt` だけ呼んで `validate` を通さない測り方は、製品に無い不具合を見つけたことになる
- 仕込み（わざと入れた矛盾・誤字）は**一時フォルダーの写し**に入れる。確認用コピーも作者の作品の写しなので、書き換えない
- 測った結果は引継ぎ書8章に「何を・どのモデルで・何件中何件」で残す。実機確認リストの該当項目には `→ **MCP で測れる**：道具名` の道しるべが付いている（2026-09-16、14件）
