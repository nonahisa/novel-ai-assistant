# 内蔵ブラウザの原稿エディター（desk）

作者の依頼（2026-09-26）「統合小説執筆環境互換の原稿エディターとその周辺機能を組みこんで、この画面で動かすことは可能でしょうか？ ファイル保管同期、AIと連携とできる機能があれば足ります」。作者の選択「今、小さく試作する」、「スキルは新規に起こしてください」。

**VS Code を開かずに、この Claude のアプリの中で書く**ための道。原稿エディター（設計書 6.25・6.34）の画面をそのまま使い、VS Code の代わりに手元の小さな読み書き役（`desk/`）が作品フォルダーを読み書きする。

## いまの段階

| 段 | 中身 | 状態 |
|---|---|---|
| 1 | 作品を開いて書き、保存できる | 試作中（2026-09-26） |
| 2 | 同期（GitHub。いまの同期と同じ git の操作を読み書き役が行う） | 未着手 |
| 3 | AIとの連携（下の「Claude が手伝うとき」と、エディターから手元の Ollama・さくらの機能を呼ぶ） | 未着手 |

段が進んだら、この表と「起動」を直す。

## 決まり（崩さない）

- **読み書き役が書き込むのは、作者が打った文字だけ。** AI（このチャットの Claude を含む）が原稿を書き換える口は作らない。外部AIは原稿を書き換えない決まり（MCP は読む・測る・提案するだけ）と同じ
- **保存は原稿を壊さない形で**（実装ルール1）：読み込み時のハッシュ照合・文字コードと改行の保持・変わった所だけの書き戻し。ほかで書き換えられていたら上書きせず止める。競合マーカーのあるファイルは開くだけで書かない
- 読み書き役は **localhost だけ**で待ち受ける
- `desk/` は配布物（VSIX）に入れない（`.vscodeignore` の `desk/**`）
- **試す作品**：段1〜3を実機で確かめ終えるまでは、確認用コピーの作品をさらに scratchpad へ写したものだけで開く。作者の原稿（`Documents\novel\`）で開くのは、作者が明示したときだけ

## 起動

- `.claude/launch.json` の `desk` の設定を、右の枠の `preview_start`（名前 `desk`）で開く。作品フォルダーは設定の引数で渡す
- 設定の中身・ポート・引数は、試作が出来たらここへ書く

## Claude が手伝うとき

作者がこの画面で書いているとき、チャットの Claude は次のことをする（書き換えはしない）。

- **読む**：作者が開いている話をファイルから読む（`Read`）。設定資料・プロットも同じ作品フォルダーから読む
- **提案する**：直したい所は、チャットで「どこを・どう・なぜ」を示すか、MCP の `novel.propose` で承認待ちへ置く。作者が画面で採る
- **機能を回す**：誤字脱字・推敲・矛盾検知などは MCP の `novel.run` で回し、結果を提案として出す（製品と同じ検算を通る道）
- 作者が「直して」と言っても、Claude が原稿ファイルを直接書き換えない。直す文を示し、作者が画面で打つか採る
