# 内蔵ブラウザの原稿エディター（desk）

作者の依頼（2026-09-26）「統合小説執筆環境互換の原稿エディターとその周辺機能を組みこんで、この画面で動かすことは可能でしょうか？ ファイル保管同期、AIと連携とできる機能があれば足ります」。作者の選択「今、小さく試作する」、「スキルは新規に起こしてください」。

**VS Code を開かずに、この Claude のアプリの中で書く**ための道。原稿エディター（設計書 6.25・6.34）の画面をそのまま使い、VS Code の代わりに手元の小さな読み書き役（`desk/`）が作品フォルダーを読み書きする。

## 配り方（作者の決定、2026-09-26「両方」）

**Claude Code のプラグイン**と**拡張機能（VSIX）への同梱**の両方から、同じ中身を配る。配るのは段1〜3が揃い、実機で確かめてから。

- そのため `desk/` は中で閉じた形にする：リポジトリの絶対パス・scratchpad の場所を埋め込まない。作品フォルダー・ポートは起動の引数か環境変数で受ける。束（`desk/dist/`）は Node だけで動き、画面も束の中から配る
- **配るスキルはこのスキルとは別に書く**（書き手向け：開き方・保存の決まり・Claude の手伝い方だけ。このスキルの開発の決まり〈scratchpad・確認用コピー〉は入れない）
- 使う人の機械に Node が要る。右の枠（内蔵ブラウザ）は Claude のデスクトップアプリだけの機能なので、ターミナルの Claude Code ではふつうのブラウザで開く案内にする
- claude.ai に上げるスキルでは動かない（手元のファイルを読み書きできない）

## 決まり（崩さない）

- **読み書き役が書き込むのは、作者が打った文字だけ。** AI（このチャットの Claude を含む）が原稿を書き換える口は作らない。外部AIは原稿を書き換えない決まり（MCP は読む・測る・提案するだけ）と同じ
- **保存は原稿を壊さない形で**（実装ルール1）：読み込み時のハッシュ照合・文字コードと改行の保持・変わった所だけの書き戻し。ほかで書き換えられていたら上書きせず止める。競合マーカーのあるファイルは開くだけで書かない
- 読み書き役は **localhost だけ**で待ち受ける
- `desk/` は配布物（VSIX）に入れない（`.vscodeignore` の `desk/**`）
- **試す作品**：段1〜3を実機で確かめ終えるまでは、確認用コピーの作品をさらに scratchpad へ写したものだけで開く。作者の原稿（`Documents\novel\`）で開くのは、作者が明示したときだけ

## 起動

- `.claude/launch.json` の `desk` の設定を、右の枠の `preview_start`（名前 `desk`）で開く。中身は `node desk/start.mjs --work <作品フォルダー> --port 4870`（環境変数 `NOVELAI_DESK_WORK`・`NOVELAI_DESK_PORT` でも渡せる）。`.claude/launch.json` は git の管理外で、**担当の作業場からは書けない**（リーダーが足す）
- `desk/start.mjs` は起こすたびに束（`desk/dist/desk.mjs`、Node だけで動く1ファイル）を作り直す。esbuild が無い機械では今ある束で起こす
- 画面の上の帯で話を選び、Ctrl+S か「保存」で保存。未保存のまま移る・閉じるときは確かめる
- 作り（2026-09-26 の試作、0.89.26 の後、設計書 6.112）：`desk/server.mjs`（読み書き役。Host・Origin が自分でない要求、作品フォルダーの外、JSON でない書き込みは断る）／`desk/pageShim.mjs`（`acquireVsCodeApi` の代役と上の帯）／`desk/vscodeShim.mjs`（`vscode` の代役。保存は拡張機能と同じ `writeTextFilePreservingFormat` をこの代役越しに使う）
- 試作の残り：話の一覧は .txt／.md を並べるだけ（作品の登録を使わない）／色は明るい1組だけ／`manuscriptEditorHtml.ts` が `views/actionList.ts` を読むので束に要らない部品が入る（文言を core へ切り出せば軽くなる）

## Claude が手伝うとき

作者がこの画面で書いているとき、チャットの Claude は次のことをする（書き換えはしない）。

- **読む**：作者が開いている話をファイルから読む（`Read`）。設定資料・プロットも同じ作品フォルダーから読む
- **提案する**：直したい所は、チャットで「どこを・どう・なぜ」を示すか、MCP の `novel.propose` で承認待ちへ置く。作者が画面で採る
- **機能を回す**：誤字脱字・推敲・矛盾検知などは MCP の `novel.run` で回し、結果を提案として出す（製品と同じ検算を通る道）
- 作者が「直して」と言っても、Claude が原稿ファイルを直接書き換えない。直す文を示し、作者が画面で打つか採る
