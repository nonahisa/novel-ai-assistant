# シェルと文字列の落とし穴

**この作品で実際に壊した順に並べる。** どれも単体テストでは気づけず、ファイルを開いて初めて分かった。

## 壊さない書き方（結論）

| したいこと | やり方 |
|---|---|
| 日本語や記号を含むスクリプトを走らせる | **`Write` でファイルに書いてから `node <file>`**。`node -e "..."` に日本語・バッククォート・`%` を入れない |
| 複数行の文章をファイルへ書く | `Write` か、`cat > file <<'EOF'`（**クォートした heredoc**）。`$` や `\` は展開されないが、**`node -e "..."` の中に heredoc の文字列を渡す**のはだめ |
| 既存ファイルの一部を置き換える | `Edit`（Read してから）。日本語ファイルに `sed -i`・`perl -0pi` を使わない |
| 制御文字が要る | `String.fromCharCode(0)` のように**コードで作る**。`\u0000` を書くと生の NUL が入る |
| PowerShell でファイルを書く | `Set-Content`／`Add-Content` は既定が ANSI。**`-Encoding utf8` を付ける** |

## 壊した記録

1. **`perl -0pi -e` が UTF-8 を壊した**（`episode.ts` のコメント全部が `ä½åãã©ã«ãã¼` に）。Latin-1 として読んで UTF-8 で書き戻す二重符号化。復旧は「Latin-1 → UTF-8 の二重符号化を戻すスクリプト」で済んだが、気づくまで時間が掛かった
2. **`node -e "..."` の中のバッククォートがシェルに食われた。** `EXTERNAL_ACCESS_DENIED_DETAIL = \`...\`` と書いたら、定数の値が空になってファイルに書かれた。**`node -e` にバッククォートを渡さない**
3. **テンプレートリテラルの中のコメントにバッククォート**（`manuscriptEditorHtml.ts` は HTML/JS をテンプレートリテラルで持つ）→ リテラルがそこで終わり、型検査が `';' expected` で落ちる。**2回踏んだ。** JS を文字列の中に書くファイルでは、コメントにも記号を使わない
4. **`Edit`/`Write` の `\u0000` が生の NUL 文字になった**（2回）。`sourceHygiene.test.ts` が止めるが、`Bash` も「control characters」で拒む。鍵を作るなら `JSON.stringify([a, b])`、どうしても要るなら `String.fromCharCode(0)`
5. **`sed` の一括置換が過去の記録まで書き換えた**（版を `0.11.2` → `0.12.0` にしたら、引継ぎ書の過去の作業記録の版番号まで変わった。1日に2度）。**置換のあとは必ず `grep` で、意図した行だけが変わったか確かめる**。版の置換は**元の状態から1回だけ**（2回に分けると1回目で直した番号を2回目がもう一度変換する）
6. **`export { X } from "..."` はローカル束縛を作らない。** 再輸出したファイルの中で `X` を使うと「Cannot find name」。**`import` を併記する**
7. **Bash の `$SP/script.mjs a b` で引数の順を取り違えた**（`process.argv[2]` に `x` を渡していた）。引数はスクリプトの冒頭で名前を付けて受け取る

## エージェントへ指示を出すとき

上の表の「壊さない書き方」を、指示に**そのまま写す**。エージェントは会話の文脈を持たないので、この記録を知らない。

## PowerShell の WriteAllLines は改行を CRLF にする（2026-11-04）

`[IO.File]::WriteAllLines` は行の終わりに CRLF を付ける。LF のファイル（`docs/実機確認リスト.md` など）を行の配列で書き直すと、ファイル全体が CRLF になる（git は差分を小さく見せるが、作業場のファイルは変わっている）。**読むのも書くのも `ReadAllText`／`WriteAllText`（UTF-8・BOM なし）で文字列のまま扱い**、行を足すなら元の改行（`"`n"` か `"`r`n"`）を調べて合わせる。
