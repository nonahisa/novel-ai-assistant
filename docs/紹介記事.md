# 小説を書くための道具を、自分のために作りました（VS Code拡張「統合小説執筆環境」）

私は小説を書いています。プログラマではありません。

ただ、仕事ではシステムを発注する側にいて、仕様書を書いていたことがあります。ですから「どう作るか」は分かりませんが、「何が必要で、何をされたら困るか」なら書けました。この道具は、その書き出しから始まっています。

書くときに困ることが、いくつもありました。設定資料がどこへ行ったか分からなくなる。何話まで書いたか、いま何字あるかを数え直す。登場人物の呼び方が話ごとにぶれる。前に書いた設定と食い違っていないか不安になる。書く時間より、書くための管理に取られる時間のほうが長い日がありました。

そこで、自分にとって理想の執筆環境を作り始めました。それがこの「統合小説執筆環境」です。

これは製品ではありません。自分の執筆のために作っているものを、同じことで困っている方がいるかもしれないと思い、おすそ分けとして公開しています。

## 何をするもの

VS Code（無料のテキストエディタ）に入れて使う拡張機能です。テキストファイル（.txt / .md）で書いた小説をそのまま扱います。専用の形式に変換しません。使い慣れたエディタで書いたファイルや、投稿サイトからダウンロードしたファイルを、そのまま置けます。

執筆の流れに沿うと、こうなります。

・始める ── プロットから、または本文から新規作品を作る。すでにあるフォルダや、GitHubに置いた作品を登録する

・書く ── 話数と文字数の自動集計、原稿用紙換算、執筆量の記録とグラフ、本文の用語ハイライト

・資料をためる ── 本文から登場人物・場所・スキル・組織・世界観を抽出して設定資料にする

・整える ── 本文からプロットを逆算する。各話あらすじ、作品紹介文、キャッチコピーを作る。各話の盛り上がりを感情曲線で見る

・直す ── 誤字脱字の検知、表記ゆれの検知。指摘は1件ずつ確認して適用する

・相談する ── いま開いている画面について、AIに日本語で質問する。質問に近い場面を作品全体から探して答える

・持ち運ぶ ── GitHubで複数のパソコンを行き来する。同じ話を2台で書いてしまったときは、並べて見比べて解決する

・書き出す ── 設定資料集のMarkdown、IME辞書（Google日本語入力・MS-IME・ATOK）

## いちばん大事にしたこと。原稿を壊さない

道具に原稿を壊されたら、それまでの時間が消えます。ここだけは徹底しました。

本文はAIが勝手に書き換えません。誤字脱字や表記ゆれの指摘は、こちらが1件ずつ「適用」を押したときだけ入ります。

書き戻す前に、読み込んだ時点から内容が変わっていないかを確かめます。AIの応答には数十秒かかります。その間に別のエディタで本文を触っていたら、書き込みを中止します。

文字コードと改行コードを保ったまま、変更箇所だけを差し替えます。UTF-8やLFへ勝手に変換しません。Shift_JISのファイルもそのままです。

作者が手で書いた内容は上書きしません。設定資料の項目を自分で直して保存すると、その項目は以後の抽出で書き換えられなくなります。作者メモは何があっても触りません。

Gitの競合マーカーが残っているファイルは、処理の対象から外します。

AIが出した設定が既存の記述と食い違ったときも、勝手に選びません。話数を見て扱いを分けます。違う話の値どうしなら「作中で変わった」と読んで両方残し、同じ話の中で矛盾していれば「変化かもしれない」として作者に判断を求めます。どの経路でも値は消えません。

## 見どころ

### 文字数と、原稿用紙の枚数

ステータスバーに現在のファイルの文字数、ツリーに話ごと・作品ごとの合計が出ます。純文字数（改行と空白を除いた数）と総文字数の2種類で、投稿サイトの表示と一致することを確認しています。

原稿用紙の枚数は、文字数を400で割った値ではありません。原稿用紙は20字×20行で、1行20字で折り返すため段落の最終行に余白が残り、空行も1行分の場所を取ります。会話文の多い小説ではこの余白が積み上がります。実際に測ると、割り算より70%以上多くなりました。4万3千字の作品で、110枚ではなく190枚です。行ごとに数えて合算しています。

### 執筆量の記録とグラフ

保存するたびに、前回からの増減をその日の執筆量として記録します。今の文字数はいつでも数えられますが、「いつ、どれだけ書いたか」は記録しておかないと二度と分かりません。日次・週次・月次・年次で切り替えて見られます。

1日と1か月の目標を決めると、達成率と「残りの日で1日あたり何字必要か」が出ます。連続して書いている日数も出ます。今日まだ書いていなくても、昨日まで続いていれば途切れた扱いにはしません。

書かなかった日も0として並べます。書いた日だけを並べると、毎日書いているように見えてしまうからです。

投稿サイトからダウンロードした本文をフォルダに入れたときなど、執筆ではない増減は数えません。数えてしまうと「今日30万字書いた」ことになります。

### 設定資料が、本文から育つ

本文をAIに読ませて、登場人物・場所・スキル・組織・世界観を取り出します。1人1ファイルのJSONとして保存し、読みやすいMarkdownの資料集も作ります。

AIには「本文から取り出す」ことだけをさせています。既存の資料とどう統合するかは、こちら側のプログラムが決めます。AIに任せると、同じ人物への複数の呼び方を1つにまとめたがるからです。「白瀬さん」と「澪」は、呼び分けそのものが情報なので、両方を話数付きで残します。

性別は「男性」「女性」の2語に揃えます。ただし埋めるのは本文で確認できる場合だけです。名前の響きや一人称からは推測しません。根拠がなければ空欄のままにします。誤った断定より、空欄のほうが害が少ないと考えています。

### 本文の用語に色が付き、カーソルを合わせると設定が出る

登録済みの名前が本文中で色分けされます。人物は青、場所は緑、スキルは紫、組織は橙です。カーソルを合わせると、その設定の要点がその場に出ます。書いている手を止めて、資料を探しに行かなくて済みます。

食い違いもここに出ます。「変化かもしれない（外見）：黒髪（第1〜3話）→ 銀髪（第7話）」のように話数と並べて出るので、「第7話で銀髪にしたんだった」と思い出せて、直す必要がないとその場で判断できます。

### 誤字脱字と、表記ゆれ

誤字脱字は、明らかな入力ミス（誤変換・脱字・衍字）だけをAIで拾います。指摘は下のパネルに並び、1件ずつ確認して適用します。「無視」した指摘は覚えていて、次からは出しません。

表記ゆれ（「良い」と「よい」など）はAIを使いません。作品全体から2通りの書き方を探し、どちらに揃えるかを選ぶと、少数派の箇所が指摘として並びます。料金はかかりません。

### 感情曲線

各話あらすじを作ると、一緒にその話の盛り上がり（0〜10）と明暗（マイナス5〜プラス5）を測り、話数順のグラフにします。文字だけでも読めるようにしてあります。

```
盛り上がり ▃▆███▆▁▆  (5〜8)
明暗       ▅▁█▁▁▁▅▁  (-2〜+3)
```

山と谷、平坦な区間、クライマックスの位置、暗い話が続いていないかが見えます。あらすじと同じ1回の呼び出しで測るので、AIの費用は増えません。AIが測った目安なので、数値そのものではなく形を見るものです。

### AIに相談する

いま開いているファイルについて、日本語で質問できます。本文でもプロットでも設定資料でも構いません。範囲を選んでから聞けば、そこについての相談になります。

質問に近い場面を作品全体から探してAIに渡します。探す先は本文、設定資料、各話あらすじの3つです。渡すときには出どころ（「本文／第105話」など）を添えます。設定資料は本文からAIが作ったものなので、本文と食い違うときは本文を優先します。

この拡張機能の使い方も聞けます。「誤字脱字ってどうやるの」と聞けば答えます。

### 過去の版に戻す

書き直して失敗したとき、送信済みの過去の版へ原稿を戻せます。戻すと何が起きるかを、先に見せます。

```
2026-08-13 09:15 の版に戻しますか？

  12 個のファイルが、その時点の内容に戻ります。
  2 個のファイルが消えます（その版より後に作ったもの）:
    本文/013.txt、本文/014.txt
  1 個のファイルが復活します:
    設定/plot.md

  いまの原稿は、戻す前に履歴へ自動で残します。あとから戻し直せます。
```

履歴は消しません。戻す前に今の原稿を自動で記録し、戻したこと自体も記録します。やり直したくなったら、もう一度「復元」で1つ前の版を選べば戻せます。取り返しのつかない操作にはしていません。

## お金の話

無料で全部動きます。Ollamaという仕組みで、AIを自分のパソコンの中で動かせます。この場合、原稿は1文字も外に出ません。インターネットに繋がっていなくても使えます。

使えるAIは4つです。

・Ollama ── 無料。原稿は自分のパソコンの中だけで処理されます

・Gemini ── 無料枠があり、超えると課金。原稿はGoogleのサーバーへ送られます

・ChatGPT ── 実行のたびに課金。原稿はOpenAIのサーバーへ送られます

・Claude ── 実行のたびに課金。原稿はAnthropicのサーバーへ送られます

無料で使う場合、はじめにOllama本体（約1GB）とAIモデル（約9.6GB）の取得が必要です。回線によっては数十分かかります。拡張機能の中から、案内付きで入れられます。

有料のAIを使うときは、実行前に処理量の目安を出し、相談画面には「有料・送るたびに課金」と表示します。知らないうちに課金されることがないようにしています。

APIキーはOSの資格情報ストアに保存し、設定ファイルや作品フォルダには書きません。GitHubへ同期されて漏れることを避けるためです。ログに出るときは伏せ字になります。

## 入れかた

VS Code の拡張機能ビュー（Ctrl + Shift + X）で「統合小説執筆環境」を検索して、インストールを押してください。

対応バージョンは VS Code 1.90.0 以降です。

入れただけでは、AIを使う機能は動きません。作品の管理、文字数の集計、執筆量のグラフはそのまま使えます。AIを使う場合は、操作メニューの「拡張機能の設定 → セットアップを開始」から、足りないものを確認して入れてください。何を、どれだけ、何のために入れるのかを一覧で見せてから実行します。勝手に入れることはありません。

私の環境はWindowsです。導入の案内はWindows向けの記述が中心になっています。

## できないこと

正直に書いておきます。

推敲、プロット逸脱の検知、矛盾検知は未実装です。作りたいものの一覧には入っています。

ルビ機能（投稿サイト記法への変換）、締切からの逆算、提供先に合わせた設定資料の書き出しも未実装です。

相談画面から書き込めるのは、プロット、作品紹介文、各話あらすじだけです。設定資料への書き込みはまだできません。小説の本文は、そもそも書き込みの対象にしていません。

AIの結果は必ず確認してください。本文との逐語照合で根拠のないものは除いていますが、特に小型のローカルモデルでは、代名詞や話者の取り違え、抽出漏れが残ります。

感情曲線の数値はAIが測った目安です。測り直すと多少変わります。
