> **済んだものは消していく。** 残っているものだけが並んでいる状態を保つ。

### D-1. 画面の使い勝手（2026-09-06、作者の依頼「境界が分からずクリックしにくい・名称が分かりにくい・ダサい も見る」）

**すべて作者の判断待ち。** 実機で触っていて気づいた点を並べたもので、直すかどうかは作者が決める。

#### 押しにくい・境界が薄い
- 詳細メニューの項目は、**同じ項目を続けて押しても再実行されない**（VS Code のツリーの性質）。作者からは「押しても何も起きない」に見える。実機確認では別の項目を挟んでから押し直す
- **情報通知が積み上がりすぎる**（作者の指示 2026-09-06「不要な通知等も消していってください」）。1回の検知で「完了しました」「AIを設定しました」「解消を確認しました」「中止しました」などが順に残り、通知センターが6件以上になる。**押したい確認カード（「実行」）が下へ押し出されて埋もれ**、古い通知を新しい結果と読み違える。直し方の案：①用の済んだ情報通知は自動で閉じる ②進捗は1件を上書きで更新する（1/7→2/7）③重要でないものは通知にせず出力パネルかステータスバーへ

- **提案パネルのボタン列（適用／無視／今後直さない／再チェック／戻す）が小さく、余白も狭い。** 0.6倍のスクショから換算した座標で20px外れて空振りした。人の操作でも隣（無視・今後直さない）を押しやすい。「今後直さない」は取り消しにくい判断なので、間隔か大きさに差をつけたい
- **トースト通知の「実行」「中止」が小さく、数秒で隠れる。** 通知センターを開かないと確実に押せない。確認は通知ではなくモーダル（`showInformationMessage` の `modal: true`）か QuickPick にする案
- **ツリーのグループ（作品管理・4. 自己校正 など）が行クリックで展開されないことがある**（矢印をクリックする必要）。「執筆データ」は行クリックで展開した。挙動の違いは VS Code の選択状態だが、作者から見ると「押しても開かない」に見える
- **出したものが、開いている別の節の下に隠れる。** 「名前の点検」で「登場箇所」を展開したまま「候補を出す（AI）」を実行すると、10件の候補は**登場箇所の一覧の下**に付くので画面に現れない。80秒待って何も起きないように見え、実機確認でも一度「候補が出ない不具合」と読み違えた。候補ができたら**登場箇所を畳む**か、**候補の位置へ画面を送る**か、少なくとも「候補が出ました」と知らせたい
- **字下げした「//」はメモにならない。** シーンメモは**行頭が `//`** のときだけ効く。小説では段落の頭に全角空白を置くのが普通なので、作者が同じ調子で「`　// ここは書き直す`」と字下げして書くと、**メモではなくただの本文**になり、字数にも入り、投稿用のコピーにも混ざる（実機で確かめた：行頭 `//` の行は字数に入らないが、全角空白を1つ置いた行は 14字ぶん字数が増えた）。**気づきにくい**ので、①字下げがあっても `//` で始まる行はメモとして扱う ②せめて字下げした `//` の行に印を出して「メモになっていません」と知らせる、のどちらかにしたい
- **メニュー名が途中で切れて読めない。** 「投稿・書き出し」の中は名前のうしろに「AIを使わない」の注記が付くため、サイドバーの既定の幅に収まらず「読者の反応を貼り付けて取り込む AIE…」「提供先を選んで設定資料を書き出す…」のように**名前のほうが切れる**。注記より名前を優先して残す（注記は説明文か印に回す）案
- **前提が足りないだけなのに「失敗しました」と言う。** プロットの無い作品で「校正をまとめて実行」を走らせると、完走の知らせに「…推敲3件・**プロット逸脱は失敗しました**・矛盾0件」と出る。同じ文の後半で「プロットがまだ無いため実行しませんでした」と正しく説明しているので、前半だけ「実行しませんでした（プロットが無いため）」に揃えたい。作者は「失敗」を見た時点で不具合を疑う
- **「走らせるもの」の数と「選んだN機能」の数が1つずれて見える。** 確認の1枚に「走らせるもの（この順）：表記ゆれ・誤字脱字・推敲・プロット逸脱・矛盾」（5つ）と書いた直後に「選んだ**4**機能それぞれが本文をチャンクごとに送ります」と出る。表記ゆれはAIを使わないので数としては正しいが、読み手には食い違いに見える。「うち**AIを使う4機能**が…」と書けば通じる
- **矛盾の指摘は、1件でもボタンが下段からはみ出す。** 「設定では／本文では」の対比に加えて4行の説明が付くため、既定の高さの提案パネルでは「本文を見る／設定資料を見る／無視／伏線として登録／再チェック」の列が枠の下に隠れる。スクロールすれば押せるが、初見では「ボタンが無い」に見える。説明を折りたたむ（「くわしく」で開く）か、ボタン列を上に置く案
- **進捗の分母がスキップ込みで、止まったように見える。** 「7チャンク中 1 件を処理します（処理済み 6 件はスキップ）」と断ったうえで、進捗は「誤字脱字を検知しています... **1/7** チャンク」と出る。実際に動くのは1件なので、3分間ずっと「1/7」のまま変わらない。作者には「止まった」に見える。分母を**実際に処理する件数**にするか、「1/1（ほか6件はキャッシュ）」のように書き分けたい
