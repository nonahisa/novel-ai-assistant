# 実機（F5）確認リスト

0.6.13 から 0.10.16 までに足したもののうち、**実機でまだ触っていないもの**を並べる。

**上から順に潰す必要はない。危ないものから並べてある。**

> **済んだものは消していく。** 残っているものだけが並んでいる状態を保つ。
> 確かめた中身は `進捗と引継ぎ.md` へ書き移してから消すこと（消しただけでは、
> 何を確かめたのかが残らない）。

起動は VS Code で **F5**。「拡張機能開発ホスト」が立ち上がる。

> **拡張機能開発ホストは、ビルドし直しても `Ctrl+R` するまで古いコードで動く。**
> 直して試すときは必ず再読み込みすること。

## A. 原稿が壊れうるもの（最優先）

**ここだけは、作品のコピーで試すこと。**

### A-1. 誤字脱字・推敲の適用

提案パネルの「適用」

- [ ] 適用したあと、**その1か所だけ**が変わっているか
- [ ] **本文が二重になっていないか**（0.10.10で直した。「夢で夢で…」の形）
- [ ] 適用したファイルを開いていたとき、画面が更新されるか
- [ ] 適用のあとに本文を直してから、もう一度別の指摘を適用できるか
- [ ] 「本文が変更されているため…」が出る場合、**本文が変わっていないか**

#### 「戻す」（0.10.12で追加。**一度も動かしていない**）

適用済みの指摘に出る「戻す」。**本文を書き換えるので、作品のコピーで試すこと。**

- [ ] 戻したあと、**その1か所だけ**が元の語に戻っているか
- [ ] 適用 → 戻す → 適用 と往復できるか
- [ ] 戻したあと、指摘が**未処理に戻っているか**
- [ ] 適用後にその行を手で直してから戻そうとすると、**書き換えずに理由が出るか**
- [ ] 戻したあと、**次の検知でその指摘がまた挙がるか**（往復ループ防止から外れているか）
- [ ] 編集部が校閲中のファイルでは、**戻せないか**（理由が出るか）

#### まとめて送るようになった（0.10.8／0.10.9）ぶん

**ここが今いちばん危ない。** 複数の話を1回でAIへ送るようになり、返ってくる行番号は**まとめた本文の通し番号**になった。それを元のファイルの行へ戻してから使う（`locateChunkLine`）。**戻し方を間違えると、別の話のファイルの、まったく違う行が書き換わる。**

単体テストでは、振った番号すべてについて戻り先の行文が元の本文と一致することを確かめてある。だが**実データで通したことは一度も無い。**

- [ ] 進捗の分母が、**話数より小さくなっているか**（19話なら6前後）
- [ ] **2話目以降の指摘を適用したとき、その話のファイルが変わるか**（1話目が変わっていないか）
- [ ] 指摘の「該当箇所へ移動」で、**本当にその文がある行へ飛ぶか**
- [ ] 「まとめて適用」のあと、**各ファイルが1か所ずつだけ**変わっているか
- [ ] 話をまたいだ指摘（前の話の文を後の話の指摘として出す）が**出ていないか**
- [ ] 確認画面に「今回はすべて送り直します」が出るか（**初回だけ**）
- [ ] 2回目に実行したとき、**処理済みとしてスキップされるか**
- [ ] 一度「無視」した指摘が、**本文を1文字直しても復活しないか**（0.10.8で鍵をファイル基準にした）

**まとめる幅は設定 `novelai.mergeChunkChars`（既定6,000字）。** 疑わしいときは `0` にすれば、1話ずつ送る以前の動きに戻せる。**戻して直るなら、原因はまとめ方にある。**

#### 作品の作法を渡すようにした（0.10.16）

**効果は「除外 N件」で測れる。** 前回の記録（いじめられっ子で 指摘104件／除外11件）と比べる。

- [ ] 一人称の入れ替え（僕→私）が、**そもそも出てこなくなったか**
- [ ] じいちゃんの自分史で、**文語体を現代表記へ直す提案が減ったか**
- [ ] 「直さない語」を登録した語が、**指摘に出てこないか**
- [ ] 除外の件数が、前より**減っているか**（増えていたら作法が悪さをしている）

### A-2. 表記ゆれ（0.10.17で直した）

**選んだのに0件になっていた。** 14組を選ぶと14回聞かれ、途中で閉じると全部捨てていた。

- [ ] 組を選んでOKすると、**「どう決めますか」が1回だけ出るか**
- [ ] 「多い方の表記に揃える」で、**14回聞かれずに指摘が出るか**
- [ ] 「1組ずつ選ぶ」でも、これまで通り選べるか
- [ ] 終わったときに、**何組を揃えて何件出したかが出るか**
- [ ] 1組も選ばずOKを押すと、**選ばれていないと言われるか**
- [ ] 0件のとき、**理由が出るか**（閉じた／すべて揃えない／全部が直さない語）

### A-3. 編集部の提案を採る

- [ ] 採ったあと、本文の**その1か所だけ**が変わっているか
- [ ] 提案が届いてから本文を直した場合、**書き換えずに理由が出るか**

### A-4. .txt → .md の変換（ルビを使おうとしたとき）

- [ ] **中身が1文字も変わっていないか**（名前だけ変わる）
- [ ] 同じ名前の `.md` があるとき、**変換しないか**
- [ ] 「まとめて変換」で、1件失敗しても残りが進むか

### A-5. 編集部へ渡す（0.10.4で追加。**一度も動かしていない**）

操作メニュー →「作品管理」→「編集部とやり取り」→「編集部へ渡す」

**本文と設定を編集用フォルダーへ写す。写す前に消す**ので、ここが最優先。

- [ ] **元の作品フォルダーが一切変わっていないか**（写す側であって、書かれる側ではない）
- [ ] 編集用フォルダーに、本文と設定が**そのまま入っているか**（文字コードと改行も）
- [ ] キャッシュ・ログ・回復用の退避が**入っていないか**
- [ ] 作品フォルダーの中を置き場所に選んだとき、**断られるか**（入れ子のリポジトリになる）
- [ ] 2回目に「送り直す」を押したとき、作品側で消した話が**編集用からも消えるか**
- [ ] 2回目でも、提案のやり取りが**消えていないか**（提案だけは混ぜる）
- [ ] `gh` が無い環境で、フォルダーだけできて**理由が出るか**

### A-6. 編集部の提案を取り込む

- [ ] 取り込んだあと、**本文が変わっていないか**
- [ ] 同じものを2回取り込んで、**二重に並ばないか**
- [ ] 作者が見送った記録が、次に渡したとき**編集部へ伝わるか**
- [ ] まだ渡していない作品で押したとき、**その旨が出るか**

### A-7. ファイル名にサブタイトルを付ける

- [ ] 話数の部分が**変わっていないか**
- [ ] 既に題が付いているとき、**重ならないか**（`episode_0001_転生_出会い` にならない）
- [ ] **話数が二重に入らないか**（`episode_0015_第15話　イジメっ子襲撃` にならない。0.10.10で直した）
- [ ] 題が話数だけの話で、**その旨が出るか**

## B. 実機でしか動かない道

**単体テストでは1行も通っていない。**

### B-1. ルビのプレビュー

`.md` を開いて `Ctrl+Shift+V`

- [ ] `{漢字|かんじ}` が**振り仮名として出るか**
- [ ] ルビの無い本文が、そのまま出るか
- [ ] `<` や `&` を含む本文で、**表示が壊れないか**

### B-2. 作品集の一括登録（0.10.3で追加）

「フォルダから作品を追加」で、**作品が並んだフォルダー**（`HisasNovels` など）を選ぶ。

- [ ] 一覧が出て、**中の作品が全部並ぶか**
- [ ] チェックを外したものが**登録されないか**
- [ ] 作品そのもののフォルダーを選んだとき、**これまで通り1作品として登録できるか**
- [ ] 「GitHubから作品を追加」で作品集のURLを入れたとき、**中の作品がまとめて登録されるか**
- [ ] 登録済みの作品集をもう一度選んだとき、**二重に登録されないか**
- [ ] 編集者モードで、**2作品目が断られるか**（理由が出るか）

### B-3. 提案パネルが開くか

**改名でビューIDを変えた**（`novelai.aiIssuesView` → `novelai.proposalsView`）。

- [ ] 「適用」「無視」「今後直さない」が**押せるか**

#### 未処理の印（0.10.14で追加）

- [ ] 検知したあと、**下段の「提案」タブに件数が出るか**
- [ ] ターミナルや出力へ切り替えても、**印が見えているか**
- [ ] 適用・無視をするたびに、**数が減るか**
- [ ] 全部片付けると、**印が消えるか**
- [ ] 見出しの件数と、タブの印の数が**一致しているか**

#### 表示の切り替え（0.10.7で直した）

**設定資料の更新を出したあと、以後の検知がすべて隠れていた。** 見出しと件数だけ変わり、中身は前のままだった。入れ替えを1か所に集めたので、どの順で出しても前のものは残らないはずである。

- [ ] 設定資料の更新 → 誤字脱字 の順で出して、**誤字脱字が見えるか**
- [ ] 誤字脱字 → 設定資料の更新 の順でも、**更新が見えるか**
- [ ] 矛盾・プロット逸脱・編集部からの提案でも、**前の中身が残らないか**
- [ ] 結果が0件のとき、**「まだ検知結果がありません」に戻るか**（前回の結果が残らない）

#### 記号がそのまま出ていないか（0.10.1／0.10.9で直した）

**見出しや強調の記号が、画面にそのまま出ていた。** ダイアログもパネルもMarkdownを解釈しない。

- [ ] 設定資料の更新の差分に、`###` や `##` が**出ていないか**
- [ ] AIを使う操作の確認画面（課金の警告）に、`**` が**出ていないか**
- [ ] 「編集者にする」の説明に、`**` が**出ていないか**（【できること】の形になっているか）

### B-4. 編集履歴の色分け

「執筆データ」→「編集履歴を見る」

- [ ] 作者（●）・編集者（▲）・AI（■）が**色分けされているか**
- [ ] 種別で絞り込めるか
- [ ] **記号が出ているか**（色が分からなくても区別できるように）

### B-5. はじめて開いたときのAI選択

**一度出ると次から出ない**（`globalState` に印が残る）。試すには**新しいプロファイル**で拡張機能開発ホストを起動する。

- [ ] 案内が出るか
- [ ] 「AIを選ぶ」で選択画面が出るか
- [ ] 断ったあと、**次の起動で出ないか**

## C. 編集部と一緒に使う（一連の流れ）

**2つの環境が要る。** 1台で試すなら、同じ作品を2つのフォルダーへ取り寄せて、片方を編集者モードにする。

- [ ] 「拡張機能の設定」→「**作者／編集者を切り替える**」で切り替わるか
- [ ] 編集者モードで、**設定資料の抽出などが押せなくなる**か（消えずに理由が出るか）
- [ ] 編集者モードで「適用」を押すと、**本文が変わらず提案になる**か
- [ ] 同期したあと、作者側で「**編集部からの提案を見る**」に届くか
- [ ] 採る／見送るが効くか。**見送ったことが編集部にも伝わるか**
- [ ] 「**校閲を始める**」でファイルを押さえられるか
- [ ] 押さえたファイルを作者側で直そうとすると、**誰がいつからか出るか**
- [ ] 作者が**ロックを外せる**か
- [ ] 競合したとき、**それぞれの版に名前が出るか**
