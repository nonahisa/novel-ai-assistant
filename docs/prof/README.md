`NOVELAI_STARTUP_PROFILE=1 code --extensionDevelopmentPath=…` として起動し、

**この拡張機能が使っている CPU は、自分の起動の窓のうち約5%しかありません。**
残りは拡張機能ホストそのもの、モジュールの読み込み、ネイティブの仕事
（`spawn` が合計1秒超）、そしてほかの拡張機能です。

走査の「読み」42秒はディスクの速さではありません——**同じ機械で同じファイルを素の Node に読ませると 0.2秒**です（698ファイル・6.77MB・4並列）。
**ループの遅れが 14.2秒**あることと合わせると、`await` が返っても
**順番待ちで再開できていない**という読みになります。

## 追記（2026-09-21）：素の Node で測り直した

**先に「1.9MB」と書いたのは誤りでした**（数え方の誤り）。同期と非同期の
両方で数え直し、**698ファイル・7,102,423バイト（6.77MB）で一致**しました。

| 測り方 | 時間 |
|---|---|
| 非同期4並列（いまの走査と同じ形）＋復号 | **171〜193ms** |
| 同期で全部を一息に読む＋復号 | 469〜867ms |
| 再帰 `readdirSync`（下ごしらえ） | 54ms |
| `existsSync`／`statSync` 88回 | 7ms |

**作品ごとに1回の同期読みにすると**（`await` が576回から22回へ）——
**合計 469ms、いちばん長い塊は 91ms**（226ファイル・2.4MB の作品）。
ホストを握るのは**一度に最長でも0.1秒**で済む計算です。
