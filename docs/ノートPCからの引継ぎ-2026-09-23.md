## 1. 見つけた不具合（まだどこにも記録されていません）

### ブラウザ版で、生成文書が保存できない

**症状**：ブラウザ版（`vscode.dev` / `@vscode/test-web`）で「動作を診断」を押すと、診断結果は開くが**保管庫へ保存できず、無題文書になる**。操作ログに次が残る。

```
種類: 動作の診断
置き場: \User\globalStorage\nonahisa.novel-ai-assistant\generated
理由: Error: No file system handle registered (\User)
```

**原因**：`src/views/openDocument.ts` の `setGeneratedStorageRoot`。

```ts
generatedStorageRoot =
  root.scheme === "vscode-userdata" ? root.fsPath : path.fromUri(root);
```

`vscode-userdata:` を **OS のパスへ倒している**。これは**手元では正しい**手当てで、コメントにも経緯が書かれている——そうしないと `mkdir "C:\vscode-userdata:"` で落ち、**生成文書がすべて無題文書へ落ちていた**（2026-09-05 に実機で発見）。

**ところがブラウザ版でも `globalStorageUri` は `vscode-userdata:` で来る。**ブラウザには実体が無いので、OS のパスへ倒すと `\User\globalStorage\…` という**どこにも無い道**になり、書き込みが落ちる。**手元の不具合を直した手当てが、ブラウザ版では逆に効いている。**

判定が `scheme` だけを見ていて、**そこが手元かブラウザかを見ていない。**

**直し方の見当**：`canRunProcesses()` を条件に加える。

```ts
generatedStorageRoot =
  root.scheme === "vscode-userdata" && canRunProcesses()
    ? root.fsPath
    : path.fromUri(root);
```

**実害**：2026-09-05 に直したはずの症状が、ブラウザ版では再発している。対象は生成文書を開く8か所——執筆再開の1枚・使い方・冒頭診断・伏線の一覧・反映待ちの更新・IME辞書の取り込み手順・セットアップの内訳・**動作を診断そのもの**。

**同じ形が他にもあるかもしれない。**`extension.ts` の 602行にも同じ判定がある（`fallbackLogRoot`）。ログの置き場も同じ理由で落ちている可能性がある——**未確認**。

## 2. ブラウザ版の確認を、作者の手を借りずに進める手だて

**これが今回いちばん大きい収穫です。**これまで「ブラウザ版は作者の手が要る」としていた項目の多くが、機械の側で潰せます。

### 立て方

```powershell
npm run build
npx @vscode/test-web --browser none --port 3111 --extensionDevelopmentPath=. test/fixtures/web-work
```

`--browser none` で**サーバーだけ**立ち、`http://localhost:3111` を普通のブラウザで開くと**拡張機能を読み込んだブラウザ版 VS Code** が動く。`npm run test:web` と違い、**立てたまま触れる。**

### なぜ効くか

| | デスクトップ版（computer-use） | ブラウザ版 |
|---|---|---|
| 打ち込み | **不可**（VS Code は「クリックのみ」の階級） | **可能** |
| 右クリック | **不可** | **可能** |
| 初回状態 | 作れない（`globalState` に印が残る） | **起動のたびに真っさら** |

**「初回の案内が出るか」は、これで確かめられる。**実際に出た（2026-09-22）——

> はじめまして。いくつかお答えいただくと、あなたの書き方に合わせて次にすることを案内します（AIは使いません）。途中でやめられます。　［診断する］［あとで］［出さない］

### 注意

- **木が仮想化されている。**項目が「無い」ように見えても、**送ると出てくる**。実際に「動作を診断が無い」と報告しかけた。**送ってから言うこと。**
- **至近で拡大しないと判断を誤る。**ダッシュの4本続きは、広い倍率では切れ目があるように見えるが、至近では継ぎ目が無い。
- **GitHub のサインインは作者の手。**個人情報・ログイン・APIキーに触れる操作はしない。

## 7. 起動の速さ（参考）

**ノートPCの数字は「作者がふだん見る速さ」ではない。**同じ 0.75.0 が母艦では **380ms**、このノートPCでは 18,864ms。作品もファイルも母艦のほうが多いのに、**ループの遅れだけが153倍**違う（102ms 対 15,640ms）。**混んだ拡張機能ホストの試験場**として読むこと。

0.75.4 の時点で、`pathExists` の直しにより下ごしらえは 46.3秒 → 34.0秒。**ただし一覧はほとんど動かない**（18.9秒 → 18.6秒）。**残る34秒も待ち**で、下ごしらえに残るのはどれも Node の読み口なのに遅い——**`await` の回数が減っていない**ため（作品ごと3回×16作品で約48回）。読みで効いたのと同じ手（1回の `await` にまとめる）を当てる余地がある。**作者の実機では既に 0.38秒なので、急ぐ話ではない。**
