この文書は、Android 版の**画面の作り・入口・Android と Capacitor の API の使い方**と、共通設計書7章の問いへの答えを持つ。

## 2. 作りの骨組み

### 2.1 Capacitor と WebView

**【案】** アプリは Capacitor で作り、画面は Android の WebView（Android System WebView。Chromium）に出す。

- 拡張機能の画面（原稿エディターなど）も Chromium の上の HTML なので、組み方の知見と画面の部品を持っていける
- 共有するコード（2.2）は TypeScript のまま動く
- iOS へも同じ形で広げられる（投稿キットは既に「クリップボードと URL を開くだけ」で作ってあり、方式を変えずに移せる。設計書 6.68）

Android System WebView は端末ごとに版が違う。**動かす下限は Chromium 105**（CSS Custom Highlight API が使える版。5.7）とし、下回る端末では用語の色だけを出さない。

### 2.2 拡張機能と共有するコード

拡張機能の `src/models/`・`src/core/`・`src/ai/`・`src/prompts/` を共有する。共通設計書 1.3 の見立てでは約2.3万行がそのまま使える。**同じコードを使えば、共通設計書2章の決まりの多くは同じに守られる。**

**【案】** 共有は写しを作らず、拡張機能のリポジトリのソースをそのまま取り込む（npm のワークスペース、または固定した版のパッケージとして参照する）。写しを持つと、拡張機能で直した不具合が Android に届かない日が来るためである。どちらの取り込み方にするかは最初の試作で決める。

依存の向きは拡張機能と同じにする：`画面` → `機能` → `core` → `models`。Android の画面のコードは `core` を呼ぶだけで、`core` の側に Android の事情を入れない。

### 2.3 差し替える部品

端末の機能に触れる部品だけを、Android 用に差し替える。**差し替えた部品も共通設計書2章を守る。** 守れていることは、拡張機能の同じ部品が通しているテストを、Android の部品にも通して確かめる（9章）。

| 部品 | 拡張機能 | Android | 守る決まり |
|---|---|---|---|
| ファイルの場所（`core/paths.ts`） | `vscode.Uri` | Capacitor のファイルの場所（`Directory.Data` の下） | 作品フォルダーの形（共通設計書 3.1） |
| 本文の読み書き（`core/textFile.ts`） | `vscode.workspace.fs` | `@capacitor/filesystem` | ハッシュの照合・文字コードと改行の保持・変わった所だけ・退避（共通設計書 2.1）。`writeTextFilePreservingFormat` の中身は共有し、下の読み書きだけを差し替える |
| 端末の識別（`core/device.ts`） | VS Code の機械ID | アプリを入れたときに作る ID を端末の設定に置く | 端末ID は同期しない（共通設計書 3.4・3.6） |
| git（`core/git.ts`） | `git` コマンド | `isomorphic-git` | 共通設計書 2.8（6章） |
| AI への通信（`ai/httpClient.ts`） | `fetch` | `CapacitorHttp` | 鍵を URL に載せない（共通設計書 2.9） |
| 待ち時間（`ai/fetchTimeouts.ts`） | undici | 時計と中止の印で組み直す | 既定300秒（共通設計書 4.5） |
| 鍵の保管（`SecretStorage`） | VS Code の `SecretStorage` | Android Keystore で暗号化した保管 | 平文の設定ファイルに置かない（共通設計書 2.9） |
| 端末の設定（`globalState`） | VS Code の `globalState` | `@capacitor/preferences` | 作品フォルダーに置かない |

### 2.4 端末で使えない部品の見張り

**【踏襲】** 拡張機能の `test/unit/cross/browserReach.test.ts` と同じ形で、Android の入口から `import` を静的にたどり、`vscode`・`node:` で始まるもの・`undici` を取り込んでいないかを見張るテスト（`androidReach.test.ts`）を置く。静的な `import` は呼ばれなくても読み込まれ、端末では起動した瞬間に落ちるためである（CLAUDE.md の失敗6）。

## 4. 画面の作り（幅で3段）

**【決定】** 2026-10-29 作者「幅で3段」。画面の幅で、1枚・2枚・3枚の並べ方を切り替える。

### 4.1 段の境目

| 段 | 窓の幅 | 端末の例 | 並べるもの |
|---|---|---|---|
| 狭い | 600dp 未満 | スマホの縦 | 1枚ずつ。下のタブで切り替える |
| 中 | 600dp 以上 840dp 未満 | スマホの横・小さいタブレット・折りたたみを開いた状態 | 2枚：話の一覧と原稿 |
| 広い | 840dp 以上 | 大きいタブレット・タブレットの横 | 3枚：話の一覧と原稿と横の板（提案・資料・メモ） |

境目の 600dp と 840dp は、Android が窓の大きさを分ける区分（compact・medium・expanded）と同じ値にする。ほかのアプリと同じ所で並べ方が変わるので、回転や分割画面で作者が戸惑わない。

**段は窓の幅だけで決める。** 端末の種類（スマホかタブレットか）では決めない。同じタブレットでも、分割画面で半分にすれば中や狭いになる。

**画面の部品は1つずつ作り、段では並べ方だけを変える。** 同じ原稿エディターを段の数だけ作らない。作ると、直したときに片方だけ直る。

### 4.2 画面の一覧

| 記号 | 画面 | 中身 |
|---|---|---|
| A | 作品一覧 | 作品ごとに、題・話数・字数・最後に書いた日・同期の状態（送っていない話の数・競合の印） |
| B | 話の一覧 | 章ごとに話を並べる。各話の字数と印（送っていない・校閲中の鍵・競合・話数の重複や欠番）。いちばん新しい話を書く入口を先頭に置く |
| C | 原稿エディター | 5章 |
| D | 提案 | 誤字脱字・推敲・矛盾・逸脱・編集部の提案・設定資料の更新を1か所に集める（共通設計書 5.6）。1件ずつ［採る］［見送る］。まとめて採る操作は、拡張機能と同じ決まりで置く |
| E | 設定資料 | 人物・場所・組織・能力・世界観・伏線の一覧と1件の表示。作者の書いた欄（`authorNotes` など）にはそれと分かる印を付ける |
| F | AI を走らせる | 機能を選ぶ → 範囲を選ぶ → **処理量と費用の見積もり** → 走らせる → 進み具合と［中止］（7章） |
| G | 同期 | GitHub と同期・状態・競合のときの選び方（6章） |
| H | 設定 | AI・GitHub・表示（書体・文字の大きさ・縦横の既定） |
| I | 執筆統計 | 今日・今週の字数。端末ごとに記録して、表示のときに足す（共通設計書 3.4） |

### 4.3 段ごとの並べ方

**狭い（スマホの縦）**

- 下のタブは4つ：**作品**（A→B）・**書く**（C）・**提案**（D）・**ほか**（E〜I）
- ［書く］は最後に開いた話を開く。作品を開いたあとは、ほぼこのタブにいることになるため、押す回数を減らす
- ［提案］には未決の件数を付ける
- 原稿エディターを開いているあいだ、下のタブは隠してよい（キーボードが出ると狭いため）。上のバーの［戻る］で戻る

**中（スマホの横・小さいタブレット）**

- 左に話の一覧（幅 280dp）、右に原稿エディター
- 提案・資料は右から出す引き出しにする。原稿を隠さず、半分の幅で重ねる
- 左の一覧は畳める。畳むと原稿が全幅になる

**広い（大きいタブレット）**

- 左に話の一覧（260dp）、中に原稿エディター、右に横の板（320dp）
- 横の板は［提案］［資料］［メモ］のタブで切り替える。原稿で選んだ語の資料・指摘の場所へ、横の板から飛べる
- 左と右は別々に畳める

### 4.4 入口（右クリックの代わり）

拡張機能の入口は右クリックとコマンドである。Android には両方とも無い。

- **長押しの品書き**：原稿で字を選ぶと、選んだ範囲の近くに帯を出す。中身は［ルビ］［傍点］［資料を見る］［AI に訊く］と、Android の［コピー］［貼り付け］。Android の文字選択の帯に項目を足せるか（ネイティブの側の作業）は【確かめる】。足せなければ、選んだ範囲の下に自前の帯を出す
- **上のバーの［…］**：作品と話の操作（新しい話・章を立てる・書き出し・AI を走らせる）
- **キーボードの付いたタブレット**：拡張機能と同じショートカット（設計書 6.25.10。Ctrl+S・Ctrl+Z など）を効かせる

### 4.5 回転・分割画面・キーボード

- 回転や分割画面で段が変わっても、開いている話・カーソルの位置・書きかけは保つ
- キーボードが出たら原稿の見える高さを縮め、カーソルを見える所へ動かす。段は変えない（キーボードは窓の幅を変えないため）
- 段が変わる瞬間に変換中の字があれば、変換が確定するまで並べ替えを待つ。並べ替えで入力欄が組み直されると、変換中の字を失うためである（設計書 6.25.1 と同じ考え方）

## 5. 原稿エディター

作者がいちばん長く触る画面である。**壊れたときの被害が原稿そのもの**なので、拡張機能で積んだ守り（設計書 6.25・6.34）を、そのまま持っていく。

### 5.1 面と向き

面は拡張機能と同じ2つ。どちらにも縦と横がある。

| 面 | 作り | 役目 |
|---|---|---|
| **組んで書く**（既定） | `contenteditable` | ルビ・傍点を組んだまま打てる |
| **書く** | `<textarea>` | 記法をそのまま見せる（`{漢字|かんじ}`）。日本語入力を細工せずに効かせる土台 |

**【案】** 拡張機能の原稿エディターの画面（`views/manuscriptEditorHtml.ts`）は、VS Code との受け渡し（送る・受け取る）を除けば、端末に依らない HTML である。受け渡しの口だけを差し替えて、画面の中身は共有する。別に作り直すと、拡張機能で直した日本語入力の不具合（設計書 6.25.1〜6.25.11）を、もう一度踏むためである。共有できる形に分けられるかは最初の試作で確かめる。

### 5.2 縦書きで打つ

**【決定】** 2026-10-29 作者「縦でも書ける」：スマホでも縦書きのまま打てるようにする。

- 組み方は拡張機能と同じ：`writing-mode: vertical-rl`・`text-orientation: mixed`・半角1〜2字の縦中横・行末の約物を詰めない（`text-spacing-trim: space-all`。設計書 6.34.5）。組む規則は `core/manuscriptRender.ts` を共有する
- 行は右から左へ進み、画面は横へ送る。打っているあいだは、カーソルのある行が見える位置へ自動で送る
- 文字の大きさは、2本指で広げる・つまむ操作で変える。変えた大きさは端末ごとに覚える
- **書体【案】**：明朝を既定にする。Android の端末には明朝が入っていないことが多いので、**Noto Serif JP（SIL Open Font License）をアプリに同梱する**。原稿にはどの字も出うるので、字を間引いた軽い版にはしない（アプリが十数MB重くなる）

**Android の日本語入力で縦書きの入力欄が崩れないかは、まだ誰も確かめていない。** 拡張機能でも縦書き×`contenteditable`×日本語入力は実機でしか確定しなかった（設計書 6.34.1）。最初の試作で、次を作者の実機で確かめる。

| 確かめること | 日本語入力 |
|---|---|
| 変換中の字が消えない・二重にならない | Gboard を先に。作者が使う日本語入力があればそれも |
| 変換の候補を選んで確定したとき、カーソルが飛ばない | 同上 |
| 改行・1字消す・範囲を選んで消す | 同上 |
| 長押しで選んだ範囲が、縦の行に沿って伸び縮みする | — |
| キーボードの上下で、カーソルの行が隠れない | — |
| 組んで書く面で、ルビの直前・直後に打てる | 同上 |

### 5.3 崩れたときの道

縦書きで打てない端末と日本語入力の組み合わせがあっても、作者が書き続けられるようにする。

1. **上のバーに［横で書く］を常に置く。** 押すと、同じ話の同じ位置のまま横書きの面へ移る。戻すのも同じボタン
2. **打った字が本文へ届いたかを、便ごとに確かめる**（設計書 6.25.9 と同じ仕組み）。食い違いを見つけたら、その場で「この端末では縦書きの入力が崩れることがあります。横で書くと確実です」と出し、［横で書く］へ案内する。**自動では移さない。** 打っている最中に面が変わると、変換中の字を失うためである
3. **組んで書く面は、入る前に「記法 → 表示 → 記法」の往復が本文と完全に一致するかを確かめ、一致しなければ開かない**（設計書 6.34.5 と同じ）。書く面（textarea）へ回す
4. **書きかけは打鍵ごとに端末に控える**（`.aiwriter` の外、同期しない場所）。面を移っても、アプリが止められても、字を失わない。控えは保存が済んだら消す

崩れた組み合わせは、端末の型と日本語入力の名前で端末に覚え、次からは開いたときに一度だけ知らせる（勝手に横へは開かない）。

### 5.4 保存

拡張機能は保存を VS Code に任せていた。Android では自分で持つ。

- **自動で保存する。** 打つのを止めて2秒たったとき、話を移るとき、アプリが裏に回るとき【案】
- 保存は必ず `writeTextFilePreservingFormat` を通す（共通設計書 2.1）。保存のたびに退避が積まれると5世代がすぐに埋まるので、**退避は話を開いて最初の保存のときだけ**にする【案】。2秒ごとの退避で、開く前の本文が5回で押し出されるためである
- 保存の直前のハッシュが読んだときと違えば（同期で本文が入れ替わったなど）書かずに止め、書きかけを控えに残したまま「外で変わりました」と知らせる。作者が［あちらを見る］［こちらで上書きしない］から選ぶ。上書きの道は置かない
- 上のバーに保存の状態を小さく出す（「保存済み」「保存待ち」）

### 5.5 取り消し

拡張機能は取り消しを VS Code の文書に任せ、画面は自前の取り消し履歴を持たない（設計書 6.34.4）。Android には任せる先が無い。

**【案】** アプリが本文の中身を持ち、打鍵ごとに「変わった1か所」を手として積む。取り消しはその手を1つずつ戻す。ブラウザの取り消し（`contenteditable` の取り消し）は使わない。組み直すたびにブラウザの履歴は壊れるためである。ルビ・傍点を振る操作も1手として積む。

### 5.6 キーボードの上の道具帯

スマホのキーボードで打ちにくいものを、キーボードのすぐ上の1列に置く【案】。

［取り消し］［やり直し］［ルビ］［傍点］［「」］［――］［……］［横で書く／縦で書く］

- 「――」と「……」は2字を1押しで入れる
- ［ルビ］は選んだ範囲に振る。選んでいなければ、カーソルの前の漢字のまとまりに振る
- 道具帯は横へ送れる。並びは作者が変えられる（後の段）

### 5.7 用語の色・ルビ・傍点

- 用語の色は CSS Custom Highlight API（設計書 6.34.3 と同じ）。使えない WebView では色を出さない。本文の組み立てには影響しない
- ルビ・傍点は「編集できないかたまり」として置く（設計書 6.34.2）。消すときは1つで消える
- 語を長押しして［資料を見る］を押すと、狭い段では資料を下から半分の高さで出し、中・広い段では横の板に出す

## 6. 同期

決まりは共通設計書 2.8。ここでは Android の動きだけを書く。

- **取ってくるのは自動**：アプリを開いたとき・前に出たとき。早送りできるときだけ取り込む
- **送るのは作者が押したとき**：作品一覧と話の一覧に「送っていない話」の数を出し、押し忘れに気づけるようにする
- **競合したら、両方とも残す**：話ごとに［こちら］［あちら］［両方残す］を選ぶ画面を出す。選ぶまで、その話には AI を当てない
- **通信が無くても書ける**。同期は通信が戻ってから
- **初めて取ってくるときは、新しい1つ分の歴史だけを取る**（浅い取得）。スマホの容量と通信量を節約するためである。古い歴史は要るときに取る
- `isomorphic-git` で「競合の印を書く合流」ができるかは【確かめる】。できなければ、競合した話は両方の中身をファイルに分けて残し、作者に選んでもらう

## 7. AI

- 機能ごとの AI の割り当て・落とし先・有料の AI の前の確認は、共通設計書 4.2〜4.4 のとおり
- **走らせる前に、処理量と費用の見積もりを出す**（画面 F）。スマホは画面が狭いので、見積もりは1枚に「何話・約何字・どの AI・費用の目安」の4行で出す
- **長い処理のあいだにアプリが止められる。** Android は裏に回ったアプリの通信を止めることがある。【案】処理中は通知に進み具合を出し、裏でも続けられる形（前面のサービス）にする。それでも切れたら、チャンクの控え（共通設計書 2.4）があるので、次に走らせたとき済んだ所は飛ばす
- 結果はすべて提案（画面 D）へ。作者が採ったものだけを当てる

## 8. 鍵・端末の記録・ログ

- 鍵（AI の API キー・GitHub のトークン）は Android Keystore で暗号化して保管する。全作品で共通に持つ（共通設計書 2.9）
- 端末ID・AI の選び方・表示の設定は端末の設定に置き、同期しない
- ログは作品フォルダーの `.aiwriter/logs/`。既定7日で消す。同期しない（`.gitignore`）
- 書きかけの控え（5.3）はアプリ専用の領域の、作品フォルダーの外に置く

## 9. テスト

**【踏襲】** 拡張機能と同じ3つの層で確かめる（共通設計書 6章）。

| 層 | Android での道具 | 確かめること |
|---|---|---|
| 単体テスト | Vitest | 共有するコードは拡張機能と同じテストをそのまま通す。**差し替えた部品（2.3）には、拡張機能の部品と同じテストを通す**（読み書きの部品なら、文字コードと改行の保持・ハッシュの照合・退避） |
| 画面の自動テスト | Playwright で、画面をパソコンの Chromium にスマホの幅とタッチで出して押す。幅は3段の代表として 360×800・800×1280・1280×800 | 段の切り替え・タブ・長押しの帯・道具帯・提案の採る見送る・保存の状態・知らせの文言 |
| 実機確認 | `docs/実機確認リスト.md`（novel-ai-android に置く）。3段階で進める：パソコンのブラウザ → 同じ Wi-Fi のスマホ → USB でつないだ実機 | **本物の日本語入力**（5.2 の表）・見た目・アプリが止められたとき・回転と分割画面 |

- 日本語入力は機械では起こせない。5.2 の表は実機確認リストへ入れる
- Android のエミュレーターの WebView を Playwright で押せるか（Playwright の Android 向けの道具は実験段階）は【確かめる】。押せれば、WebView の版の違いも画面の自動テストで見られる
- **作者の原稿では試さない。** 試すのは名前の末尾が `_確認用` の作品だけ
- 不具合を直すときは、先に再現テストを足す
