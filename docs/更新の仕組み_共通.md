# 更新の仕組み（全製品の共通の決まり）

2026-11-20、作者の依頼「全製品共通ですが、アップデートの仕組みを作ってください」から母艦が起こした。製品ごとの作りは各製品の設計書が正で、ここは製品のあいだでそろえる決まりだけを置く。

## 1. 共通の決まり

1. **新しい版の出どころは、各製品の GitHub Release の最新だけ**にする。手元の気づき（ほかの置き場・ほかの人の配布）からは取らない
2. **Release に「更新の札」`update.json` を添える**（形は2章）。札には版・中身の要約・置き場・SHA-256 を書く。札の SHA-256 は、Release ノートの末尾の `SHA-256：…` と同じ値にする
3. **確かめるのは、起動したときと1日に1回まで**。送るのは GitHub への GET だけにする。作品・原稿・学習・設定・機械の名前は送らない。設定で切れるようにする
4. **入れ替えは作者が押したときだけ**。知らせには、新しい版・中身の要約（2〜3行）・［入れる］［あとで］［この版は飛ばす］を出す。勝手に入れ替えるのは、ストア（Marketplace・Chrome ウェブストア・App Store・Google Play）が自分で更新する所だけ
5. **入れる前に SHA-256 を照らし、合わなければ止める**。止めたら理由を1行と、次の一手を1つ出す
6. **作者のデータに触らない**。原稿・作品の設定・学習の記録・辞書は入れ替えの対象にしない。入れ替えの前に、製品の設定と学習の控えを取る
7. **戻せるようにする**。前の版を1つ残し、［前の版へ戻す］の道を持つ（ストアの製品は除く）
8. **落ちたら学習しない・決めつけない**（統合の実装ルール5と同じ）。通信の失敗で次の確かめまで黙る。エラー文から原因を当てない

## 2. 更新の札 `update.json` の形

```json
{
  "product": "rittoku-ime",
  "version": "0.4.0",
  "date": "2026-11-20",
  "summary": ["作品の辞書を作品ごとに切り替えられるようにしました", "…"],
  "assets": [
    { "platform": "windows-x64", "name": "Rittoku-IME-Setup-0.4.0.exe", "url": "https://github.com/…/releases/download/v0.4.0/…", "sha256": "…", "bytes": 123456 }
  ],
  "minimumFrom": null
}
```

- `product`：英字の名前（novel-ai-assistant・novel-post-helper・novel-ai-mobile・rittoku-ime・novel-ai-community-bot）
- `summary`：作者向けの短い文（CHANGELOG の新しい版の要約。yomiyasu を当てる）
- `minimumFrom`：この版から直に上げられない古い版があるときだけ、その下限を書く

## 3. 製品ごとの道

| 製品 | 新しい版の届き方 | この仕組みで足すもの |
|---|---|---|
| 統合小説執筆環境 | Marketplace・Open VSX が自分で更新する | GitHub Release に `update.json` を添える（ほかの製品が統合の版を知る口）。VSIX を手で入れた人向けの知らせは、Marketplace に無い版のときだけ |
| 投稿ヘルパー | Chrome ウェブストアが自分で更新する（1.0.0 の審査のあと） | 審査が通るまでは、zip を手で入れた人へ、拡張機能の設定の画面に知らせを出す |
| モバイル版 | Android：GitHub Release の APK を、アプリの中の知らせから端末のインストーラーへ渡す。iOS：知らせだけ（入れ替えは Mac・TestFlight） | アプリの中の確かめと知らせ。Android はインストーラーへ渡すところまで |
| Rittoku IME | 設定のアプリが確かめ、インストーラーを取ってきて照らし、作者が押したら動かす | インストーラー（置く・登録する・外す・前の版へ戻す）と、設定のアプリの確かめ。非公開のリポジトリからは取れないので、配る置き場は作者が決める |
| Discord のボット | サーバーで動くので、セッションが入れ替える | 新しい版が出たら、各製品の `update.json` を読んで案内の部屋へ知らせる（作者の了承の範囲で） |

## 4. 作者が決めること（パネルへ）

- Rittoku IME とモバイル版の Android の APK を、どの公開の置き場から配るか（リポジトリを公開する／配るためだけの公開リポジトリを作る）
- 確かめの既定を「オン」にするか「オフ」にするか
