# この作品を扱うAIへの指示書（統合小説執筆環境）

この指示書は、**作者の作品フォルダーに置かれる**。読んでいるあなた（Claude Code・Codex・Gemini CLI・ローカルLLMなど、どの AI でも同じ）は、この作品について作者から相談を受けたときに、次の決まりで動く。

（雛形の置き場：拡張機能のリポジトリ `docs/skills/novel-assist.md`。作品へは拡張機能が書き出す。設計書6.87.15 柱5・6.87.16）

## いちばん大事な決まり

**この作品について判断するときは、自分で本文を読んで答えず、統合小説執筆環境の MCP サーバーの道具を通す。**

理由：あなたが本文を読んで「伏線は回収されている」「誤字は無い」と言うのは**あなたの読み**であって、本文に無い記述を作ることがある。MCP の道具は製品の検算（本文に実在するかの照合、字数、実在する話数、既存の名前との衝突）を通した答えを返す。作者はその違いを知っていて、**製品の判断を通した答え**を求めている。

- 誤字脱字・推敲・矛盾・伏線・あらすじ・逸脱・表記ゆれ・冒頭診断・名前・章立て・紹介文 → **必ず対応する道具を呼ぶ**
- 道具が無いことを聞かれたら、「その機能は製品に無い」と言う。**作り出さない**
- 道具が返した `note` と `failures` を読み、**通していないものを「通した」と言わない**

## 本文をどこへ出すか（`runner`）

`novel.run` は `runner` を必ず指定する（既定は無い）。

| `runner` | 本文の行き先 | いつ使うか |
|---|---|---|
| `ollama` | **作者の機械から出ない**（手元の Ollama で検算まで通す） | **基本はこれ。** `model` は作者に聞くか、作品の設定にあるものを使う |
| `claude` | プロンプトだけ返る。**あなたが読んで答え、`validate` へ戻す**（本文があなたの提供元へ渡る） | 作者が「あなたに読ませてよい」と言ったときだけ |
| `sampling` | あなたの側の AI に考えさせる（対応している呼び出し元だけ） | 作者が別に許可したときだけ |

**迷ったら `ollama`。** 本文が外へ出る選択は、作者に一言確かめてからにする。

## 許可の仕組み（断られたら、作者に伝える）

道具は**作者が許可した相手・許可した機能（`feature`）しか通らない**（既定は拒否）。断られたら、返事に「どうすれば許可できるか」が書いてある。**それをそのまま作者に伝える。** 自分で許可の印（`.aiwriter/external-access.json`）を書き換えない——それは作者が VS Code の画面で決めるものである。

同じ道具を続けて呼んで断られても、作者の画面には1回しか出ない。断られたら止まって、作者の判断を待つ。

## 設定資料を直したいとき

**台帳（`設定/characters/*.json` など）を直接書き換えない。** 人物の更新案は `novel.propose` で**承認待ちへ置く**——作者が VS Code の「更新分を反映」で採否を決める。`reason`（なぜそう提案するか）を必ず添える。受け付けられない欄（作者の覚え書き、固定された呼称など）は道具が断るので、そのまま作者に伝える。

本文（`.txt`／`.md`）は**書き換えない**。直したい箇所があれば、道具の指摘として作者に見せる。

## 道具の早見表

**道具は14本で、何をするかは `feature` の引数で決まる**（0.66.7）。ほとんどの用は `novel.run` に `feature` を渡せば足りる。

| したいこと | 道具 |
|---|---|
| 作品の構造を知る（話数・字数・相対パス） | `novel.scan` |
| 誤字脱字／推敲／設定資料の抽出／矛盾／伏線 | `novel.run`（`feature: typo`／`proofread`／`settings`／`contradiction`／`foreshadow`。**`filePath` と `numCtx` が要る**） |
| 各話あらすじ／プロット逸脱／単話プロット | `novel.run`（`feature: synopsis`／`deviation`／`episodePlot`） |
| 表記ゆれ | `novel.detect`（`feature: notation`）→ 返った組の1件を `novel.run` の `options.group` へ |
| 名前の衝突／候補 | `novel.detect`（`feature: name`）／`novel.run`（`feature: name`） |
| 矛盾の材料だけを見る | `novel.material`（`feature: contradiction`） |
| 相談／冒頭診断／プロット逆算／章立て／紹介文／キャッチコピー | `novel.run`（`feature: chat`／`opening`／`plotReverse`／`chapter`／`blurb`／`catchphrase`） |
| プロンプトだけ・検算だけ | `novel.prompt`／`novel.validate`（同じ `feature` で） |
| 人物の更新案を置く | `novel.propose` |
| **実行前に画面へ出る断りを、走らせずに読む** | `novel.notice`（`feature` とモデルを渡す。**AIは呼ばず、本文も読まない**。0.72.0） |
| **押す場所を作者の画面で光らせる** | `guide.spotlight`（`command` か `label`。**2回点滅するだけで、操作は実行しない**。0.75.6） |
| 手元の Ollama のモデルを知る | `ollama.models` |
| サーバーの版と、あなたの名乗り・どの機械のサーバーか | `mcp.version`（`machineName` が機械の名前） |
| この機械で開いている VS Code の窓と、それぞれの拡張機能の版・開いている作品・開発ホストか | `windows.list`（**読むだけ**。`machineName` がどの機械の一覧か。別の機械の窓は出ない。`probablyClosed` は閉じたときに消し損ねた札） |
| 初期設定の1段（AIの導入・作品の作成／登録など）を作者の画面に頼む | `setup.request`（**確認が出るだけで、押すのは作者**。手順はプロンプト `setup`。0.82.1） |

feature ごとの追加の指定（`mode`・`group`・`plotPath`・`question`・`characterName` など）は `options` に入れる。**一覧は `novel.run` の説明にある。**

道具の細かい引数は、道具の説明文にある。**`mcp.version` が「束が古い」と言ったら、作者に Claude Code（またはあなたの基盤）を開き直してもらう。**

## しないこと

- 本文・設定資料・プロットを**直接書き換えない**
- 許可の印・記録（`.aiwriter/`）を書き換えない
- 道具を通さずに「誤字は無い」「矛盾は無い」と言わない
- 作者の作品の本文を、作者に確かめずに外部へ出さない（`runner: "claude"` を黙って使わない）
