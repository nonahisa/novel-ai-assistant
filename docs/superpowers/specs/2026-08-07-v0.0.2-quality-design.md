# v0.0.2 品質改善設計

## 目的

v0.0.2では新機能の数ではなく、既存機能を安心して日常利用できる品質を作る。重点は、作者データの保護、登場人物抽出の誤検出削減、失敗時の説明可能性、常時実行される品質ゲート、再現可能な配布である。

対象は既存の作品管理、文字数計測、AI設定、登場人物抽出である。プロット生成、本文生成、推敲、Git同期などの新機能は対象外とする。

## 品質目標

1. 原稿と作者編集済み設定を、文字コード変換、同時編集、壊れたJSON、Git競合のいずれでも暗黙に上書きしない。
2. 登場人物抽出で、代名詞、役職だけの語、集団名、地名を人物として保存しない。
3. 主要な正常系と失敗系をローカルとGitHub Actionsの双方で再現できる。
4. v0.0.2のVSIXが検証済みの同一成果物としてGitHub Releaseから取得できる。

## データ安全性

### テキスト形式の保存

`src/core/textFile.ts`はUTF-8、UTF-8 BOM、Shift_JIS、LF、CRLF、CR、末尾改行の有無を保持する。Shift_JISをUTF-8へ暗黙変換する現在の挙動は廃止し、Shift_JISへ再エンコードする。エンコード不能な文字がある場合は保存を中止し、対象ファイルと理由を通知する。

保存前には読み込み時のSHA-256と現在のバイト列を比較する。不一致、削除、競合マーカー、未保存のエディタ変更がある場合は書き込まない。保存は同一ディレクトリの一時ファイルへ書き、成功後に置換する。失敗時は元ファイルを残し、一時ファイルを可能な範囲で片付ける。

### 人物設定の保存

`CharacterStore.loadAll()`は有効なファイルごとにパスと内容ハッシュを記録する。既存人物の保存時には同じファイルが読み込み後に変更されていないことを確認する。名前変更では、新ファイルの確定後にだけ旧ファイルを削除する。新旧どちらかの競合、重複ID、壊れたJSONがある場合は自動解決しない。

AIマージでは次を不変条件とする。

- `autoGenerated: false` の人物は `appearedChapters` 以外を変更しない。
- `authorNotes` と `exportNote` は常に保持する。
- `authorLocked: true` の呼称は変更しない。
- 既存値を空値で消さず、矛盾は `conflicts` に残す。
- 保存対象は `changedIds` のみとし、無変更ファイルを書き直さない。

### キャッシュ

チャンクキャッシュは作者データではないため、欠損や不正JSONでは処理を継続してよい。ただし読み込み前にメモリ上の内容を初期化し、配列・キー・作成日時を検証して、有効なエントリだけを採用する。保存は一時ファイル経由で置換し、途中書き込みのJSONを次回へ残さない。キャッシュ障害を人物設定の保存失敗と混同しない。

## 登場人物抽出品質

### 入力・出力検証

人物抽出プロンプトを次版へ更新し、プロンプトの `_VERSION` も同時に上げる。人物名には本文中の根拠を要求し、代名詞、一人称、二人称、役職のみ、関係語のみ、集団名、地名、種族名を除外するよう明示する。

AI応答は保存前にコードで検証する。空名、空白だけの名、長すぎる名、文章や句読点を含む名、禁止語だけの名、有限でない章番号を除外する。完全一致、空白・中点差、敬称差、既存別名による照合を行い、曖昧な近似一致は自動統合しない。

### 再現可能な評価

`test/fixtures/character-extraction/`へ、個人情報や実原稿を含まない合成本文と期待結果を置く。少なくとも以下を含める。

- 姓名、名のみ、敬称付き呼称が同一人物になる例
- 一人称や「先生」「兵士たち」を人物にしない例
- 同名別人を根拠なく統合しない例
- 作者確定情報とAI提案が衝突する例
- 複数章で登場話数と呼称期間が更新される例

評価スクリプトは期待人物の再現率、誤検出数、誤統合数、作者保護違反数を出力する。通常CIは固定応答を使い、ネットワークやAIの揺らぎに依存させない。合格条件は期待人物再現率100%、誤検出0、誤統合0、作者保護違反0とする。Sakura AI EngineとOllamaのライブ試験は手動実行のまま維持し、自動再試行しない。

## UIとエラー処理

抽出開始前に対象話数と使用モデルを表示し、完了時に追加、更新、除外、競合、未保存の各件数を表示する。ユーザーキャンセルはエラー扱いにせず、それまでのAI結果を保存しない。

次の失敗を個別の日本語メッセージへ分類する。

- AI未設定、接続不能、モデル未検出、タイムアウト、キャンセル、空・不正応答
- 原稿の外部変更、未保存変更、競合マーカー、文字コード変換不能
- 人物JSONの破損、重複ID、保存時競合

メッセージには復旧操作を一つ示すが、自動再試行や別プロバイダへの切替は行わない。

## テストとCI

単体テストをデータ安全性、マージ境界、キャッシュ破損、AIタイムアウト・キャンセル・不正応答へ拡張する。Extension Host統合テストでは、起動と作品作成に加えて人物抽出の保存、競合時の非保存、作者項目保持を検証する。

GitHub Actionsに通常CIを追加し、pull requestとmainへのpushで以下を実行する。

1. `npm ci`
2. `npm run typecheck`
3. `npm run test:unit`
4. `npm run build`
5. `npm run test:integration`
6. `npm audit --audit-level=moderate`
7. VSIXの作成と `npm run verify:vsix`

重複実行は同じブランチ単位でキャンセルする。Actions権限は `contents: read` とする。Sakuraのトークンを通常CIへ渡さない。

カバレッジは総行数だけを目的化せず、安全性に関わる `textFile`、`characterStore`、`characterMerge`、抽出応答検証を重点対象とする。これらの対象ファイルはファイル単位でlines/statements/functions 90%以上、branches 80%以上を合格基準とする。例外経路を含む重要分岐は数値にかかわらず明示的なテストケースを持たせる。

## 配布と導入

バージョンを0.0.2へ更新し、READMEの現在版、ダウンロード対象、インストール例、変更点、既知の制限を同期する。private repositoryのRelease資産は認証が必要なため、導入手順は次の二段階を正式手順とする。

```powershell
gh release download v0.0.2 --repo nonahisa/novel-ai-assistant --pattern "novel-ai-assistant-0.0.2.vsix" --clobber
code --install-extension ".\novel-ai-assistant-0.0.2.vsix" --force
```

リリース前にクリーン環境で `npm ci` と全ゲートを実行する。生成したVSIXを検証し、その後は作り直さず同じファイルをGitHub Releaseへ添付する。Release本文に主な改善、既知の制限、インストール手順、SHA-256を記載する。タグ `v0.0.2`、`package.json`、VSIX名、内部manifestの版が一致しなければ公開しない。

## 実装順序

1. 安全性の失敗テストを追加し、テキスト・人物保存を堅牢化する。
2. 抽出フィクスチャと評価器を追加し、検証・正規化・プロンプトを改善する。
3. UIの結果要約と失敗分類を整備し、統合テストを拡張する。
4. 通常CIとVSIX検証を追加し、全ゲートを通す。
5. READMEと版を0.0.2へ更新し、正式PRでレビューする。
6. mainへマージ後、同一VSIXをReleaseへ公開してダウンロード・再インストールを検証する。

## 完了条件

- 全テスト、型検査、ビルド、監査、VSIX検証が成功する。
- 合成評価で再現率100%、誤検出0、誤統合0、作者保護違反0を満たす。
- 外部変更、壊れたJSON、競合マーカー、Shift_JISを含む安全性テストが成功する。
- v0.0.2の正式PRがレビュー可能な状態で作成され、CIが成功してmainへマージされる。
- `v0.0.2` Releaseに検証済みVSIXとSHA-256があり、Releaseから再取得した資産のハッシュが一致する。
- 再取得したVSIXを `code --install-extension ... --force` で導入できる。
