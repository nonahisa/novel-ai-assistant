# 0.0.1 初回配布版 設計

## 目的と範囲

0.0.1 は、現在実装済みの Phase 0（作品管理・話数認識・文字数計測）と、AI設定（Ollama / Claude）・登場人物抽出を、作者の原稿や手編集データを壊さず利用できる最初の配布版とする。未実装のプロット、場所・世界観生成、推敲、Git同期などは含めず、READMEで将来機能として明示する。

## 安全性とデータ整合性

- 既存の作品フォルダや壊れた `.aiwriter/config.json` を新規作成・登録処理で上書きしない。
- 設定内の本文・設定ディレクトリは作品ルート内の相対パスだけを許可する。
- AI応答はTypeScript型を信用せず、配列・文字列・ネスト項目を実行時に検証・正規化する。
- 作者が編集した人物JSONは、実際に追加・更新された人物だけを書き戻す。
- 人物ファイル名変更時は新ファイルの保存成功後に旧ファイルを削除する。
- 手編集された人物JSONは全フィールドを実行時検証し、不正形式・重複ID・権限エラーがある間は抽出や保存を行わない。
- 既存作品は設定ファイルの検証に成功してから登録状態を更新する。
- `novelai.chunkChars` が1以上の整数なら自動計算より優先し、分割関数でも進捗不能なサイズを拒否する。
- キャンセル時は完了チャンクのキャッシュだけを残し、人物JSONへ部分結果を反映しない。

## 品質とテスト

Vitestで文字数、話数解析、メタデータ、人物マージ、AI応答正規化を単体テストする。VS Code公式の `@vscode/test-electron` を直接使う軽量ランナーで、拡張機能の起動、コマンド登録、実ファイル走査、人物保存をExtension Development Host内で検証する。`@vscode/test-cli` は現行版の脆弱な推移依存を避けるため使用しない。`npm run check` を型検査・単体テスト・本番ビルドの統一ゲートとする。

## 配布

manifestとlockfileを `0.0.1` に揃え、esbuildの既知脆弱性を解消する。`@vscode/vsce` を固定した開発依存にし、`npm run package:vsix` で `release/novel-ai-assistant-0.0.1.vsix` を生成する。VSIXには実行バンドル、manifest、README、CHANGELOG、LICENSE、必要画像だけを含め、ソース、設計書、ローカル検証スクリプト、資格情報、原稿を含めない。隔離したユーザーデータ／拡張機能ディレクトリへVSIXをインストールし、識別子とバージョンを確認する。

## 完了条件

全自動テスト、型検査、本番ビルド、VSIX生成、VSIX内容監査、隔離インストール、インストール後の拡張機能認識が成功すること。READMEにインストール、初期設定、既知の制約、アンインストール方法を記載し、配布物のSHA-256を提示する。
