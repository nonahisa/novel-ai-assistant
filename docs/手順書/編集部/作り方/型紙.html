統合小説執筆環境　編集者向け

校閲して作者へ返すまでの手順

hisa の作品を、ご自分の VS Code で校閲していただくための手順です。本文は書き換わらず、直しも意見もすべて「提案」として作者に届きます。Live Share や、作者の画面の共有は要りません。

この手順書の見かた

画面の中の赤い〇が、次に押す所です。

画面は見本の作品「春を待つ灯（見本）」で撮りました。お手元では hisa の作品の名前が出ます。メニューの File や Cancel など VS Code 本体の表示が英語で写っていますが、日本語の VS Code では日本語で出ます。

はじめに用意するもの

  • VS Code と Git
  • 拡張機能「統合小説執筆環境」0.127.5 以降（拡張機能の画面で nonahisa.novel-ai-assistant を探して入れるか、［更新］を押す）
  • GitHub のアカウント。VS Code の左下の人の形のアイコンから、GitHub にサインインしておく
  • AI は無くてもかまいません。「表記ゆれ検知」は AI を使わずに動きます

手順

  1. 1. メニューを開く
  2. 2. 編集者として参加する
  3. 3. 校閲する範囲を押さえる
  4. 4. 検知で探す
  5. 5. 自分の言葉で修正を書く
  6. 6. 置いた提案を見る
  7. 7. 校閲を終えて返す
  8. 8. 作者モードへ戻る
1

メニューを開く

左の端の「統合小説執筆環境」のアイコン（ペンとキーボードの絵）を押すと、左の列に「簡単ステップメニュー」が出ます。編集者として参加すると、1〜7 の段が校閲の順に並びます。上から順に進めれば大丈夫です。

画面全体を見る
2

編集者として参加する（最初の1回だけ）

まだ参加していないときは、左の列の「詳細メニュー」→「作品管理」→「編集者連携」→「編集者として参加」を押します。

画面全体を見る

上に入力欄が出るので、hisa から届いたリンク（https://github.com/…）を貼り付けて Enter を押します。招待の受け入れ、作品の取り寄せ、登録、編集者モードへの切り替えまでが1回で済みます。終わると「『作品の名前』に編集者として参加しました。」と知らせが出ます。

画面全体を見る

編集者モードに切り替わると、詳細メニューの多くは押せなくなります。押すと理由が出るので、故障ではありません。

すでに参加が済んでいれば、この段は飛ばしてかまいません。hisa が原稿を直したあとは、簡単ステップメニュー「1. 編集者として参加」の中の「保存・同期」で最新を受け取れます（受け取るだけで、送るのは手順7だけです）。

3

校閲する範囲を押さえる

簡単ステップメニュー「2. 校閲する範囲を押さえる」→「校閲開始／終了」を押し、始めの話と終わりの話を選びます。範囲の話は、hisa の側で書けなくなります（校閲中に本文がずれないようにするためです）。

画面全体を見る（3枚）
4

検知で探す

簡単ステップメニュー「3. 検知で探す」→「表記ゆれ検知」を押すと、書き方の揺れた組が並びます。揃えたい組にチェックを付けて［OK］を押します。AI があれば「誤字脱字検知」「推敲」も使えます。

右に「提案」パネルが開き、直す候補が並びます。直したほうがよいものに［適用］を押してください。本文は書き換わらず、作者への提案として置かれます。

画面全体を見る（3枚）
5

自分の言葉で修正を書く

原稿の本文で直したい所をなぞって選び、右クリックして「修正を提案する」を押します。簡単ステップメニュー「4. 修正を提案する」からも出せます（先に本文を選んでおいてください）。

画面全体を見る

入力欄が2つ続けて出ます。1つ目は修正案です。最初は選んだ字が入っているので、直した形に書き換えて Enter を押します。修正案を空にすると、意見だけを送れます。

2つ目に、直す理由や意見をひと言書いて Enter を押します（空でも送れます）。下の帯に「〜行目に提案を置きました。」と出れば済みです。

画面全体を見る（2枚）

行についての意見だけを伝えるなら、同じ右クリックの品書きの下のほうにある「ここにメモを足す」でも送れます。これも本文には書かれず、意見として作者に届きます。

6

置いた提案を見る

簡単ステップメニュー「5. 置いた提案を見る」→「編集者提案確認」を押すと、置いた提案の数が右下に出ます。採るかどうかは作者が決めるので、ここでは数を確かめるだけです。

画面全体を見る
7

校閲を終えて返す

終わったら、簡単ステップメニュー「6. 校閲を終えて返す」→「校閲を終えて返す」を押します。確認の窓に、外す校閲の範囲の印（ロック）の数と、送る提案の数が出るので、［返す］を押します。提案・ロック・編集履歴が GitHub 経由で作者へ送られ、範囲の印は外れます。本文は送りません。済むと「校閲を終えて、提案 N 件を作者へ返しました。」と出ます。

画面全体を見る

作者が採るか見送るかを決めると、結果が送り返されます。次に VS Code を開いたとき、または簡単ステップメニュー「1. 編集者として参加」の「保存・同期」を押したときに、右下に「作者が提案を決めました（採用 N・見送り N・読まれた N）。」と出ます。「読まれた」は、意見だけの提案を作者が［読んだ］にした数です（採用には数えません）。

画面全体を見る

見逃したときは、右下のベル（通知）を押してください。VS Code を開いているあいだに出た知らせが、一覧に残っています。

画面全体を見る

ベルの一覧は、VS Code を閉じて開き直すと空になり、同じ知らせは二度出ません。開き直したあとに採否を確かめたいときは、簡単ステップメニュー「5. 置いた提案を見る」→「編集者提案確認」を押してください。「未決の提案はありません（これまでに 3 件の提案がありました）。これまでの採否：採用 1・見送り 1・読まれた 1。」のように、これまでの採否の数が出ます。

8

作者モードへ戻る（ご自分の作品で使うとき）

校閲が済んで、ご自分の作品でこの拡張機能を使うときは、簡単ステップメニュー「7. 作者モードへ戻る」→「作者／編集者切替」を押し、［作者に戻す］を押します。

画面全体を見る（2枚）

よくある疑問

前もって clone しておく必要はありますか？

ありません。「編集者として参加」でリンクを貼ると、取り寄せまで拡張機能が行います。リンクを VS Code の外（ブラウザなど）で開くと、エクスプローラーやブラウザが開くだけで参加になりません。

本文を直接書き換えてしまわないか心配です

編集者モードでは、［適用］も「修正を提案する」も、本文を変えずに提案として置きます。作者が採ったときに初めて本文に入ります。

押しても何も起きない・理由が出る

編集者モードでは使えない操作です。出た文をそのまま hisa に送ってください。

迷ったときは

その場の画面の写しを hisa に送ってください。次に押す所をお伝えします。
