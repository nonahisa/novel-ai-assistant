## 0-A. 画面を見る回数を減らす（作者の指定、2026-09-08）

**作者の指定「ファイル優先へ寄せる」。** 実機確認の費用のほとんどは**画面を撮ること**である。
1枚あたり千数百トークンで、1つの確認に5〜10往復かかる。
ログやファイルを読むのは数百トークンで、**桁が2つ違う**。

**画面でしか確かめられないのは2つだけ**である。

1. **組まれた見た目**——ルビが振り仮名になるか、黄色の帯が付くか、ボタンが枠に収まるか、色分け
2. **押して初めて起きること**——ダイアログの文言、選択肢の並び、通知

**これ以外は、必ずファイルかログで確かめる。**

| 確かめたいこと | ✗ 画面 | ○ ファイル・ログ |
|---|---|---|
| 処理が終わったか | 進捗を撮る | `.aiwriter/logs/actions.log` を `tail` |
| 何件できたか | 一覧を撮る | `ls 設定/characters/*.json | wc -l` |
| 中身が正しいか | パネルを撮る | JSON を `node -e` で数える |
| 本文が壊れていないか | エディタを撮る | 控えと `diff -rq` |
| 設定がどうなっているか | 設定画面を撮る | `settings.json` を読む |
| 機能が実装されているか | メニューを探す | `grep` でコマンドIDを引く |

**順序も効く。コードを先に読み、画面は裏取りに1回だけ使う。**
2026-09-08 の夜に見つけた不具合は、**どれもコードとファイルから出た**——
プレビューのルビ（VS Code 本体の `dist` を grep）、思考が流れない（ソース2行）、
傍点が字数に入る（`stripRuby` が2つある）、関係の重複48%（node スクリプト）。
画面はどれも「最後に1回」確かめるために使っただけである。

### 撮るときの作法

- **全画面を撮ってから拡大しない。** 見たい場所を最初から `zoom` で撮る
- 位置を探すだけなら `scale: 0.4` で足りる。読む必要があるときだけ `scale: 1`
- **座標は一度測ったら使い回す**（下の表）。同じ場所を何度も測り直さない
- `computer_batch` で押せるだけ押し、**撮るのは最後の1回**にする

### 開発ホストの立ち上げ（実測の手順、2026-09-08）

```bash
npm run build   # dist を作り直す。Ctrl+R では古いコードのままのことがある
code --extensionDevelopmentPath="C:/Users/nonah/Documents/novel-ai-assistant" \
     --folder-uri="file:///C:/Users/nonah/Documents/確認用コピー"
```

立ち上がった直後は**制限モード**である。上端の黄色い帯の「**管理**」を押し、
出てくる画面の「**信頼する**」を押すまで拡張機能は動かない（帯は 1456×819 の枠で y≈34 付近）。

**`TextInputHost.exe` が前面を握ってクリックが弾かれることがある。** そのときは

```bash
powershell -NoProfile -Command "Stop-Process -Name TextInputHost -Force -ErrorAction SilentlyContinue"
```

**押し先が1行ずれると致命的な場面では、倍率1で撮る**（2026-09-08 に、作品選択の行を外して「押しても何も起きない」と誤報した）。倍率1なら画像の座標がそのまま座標系なので、換算の誤差が入らない。行の高さは全画面で約15px＝0.5倍の画像では7.5pxしかなく、**拡大画像からの換算は1行ぶんずれる**。

**0.5倍で撮った画面の座標は、2倍してから渡す。** 返ってくる画像は 728×410 だが、
クリックの座標系は 1456×819 である（2026-09-08 にここで3回外した）。


## 0. 共通の約束（最初に1回読む）

- 起動：`code --extensionDevelopmentPath=<worktree> --folder-uri=file:///<作品フォルダー>`。
  `--new-window <パス>` はフォルダーが開かないことがある。起動後、制限モードのバナーで
  「管理」→「信頼する」を押す（信頼しないと拡張機能が有効化されない）。
- **作品登録は globalState にあり、コピーを開いても本物を指す。** コピー作品を試すときは
  「1. 作品登録 > フォルダから追加」で別作品として登録し直し、選択作品を明示的に
  コピー側（例：「いじめられっ子_確認用」）へ切り替える。切り替え忘れたまま操作しない。
- **作品一覧を展開するとメニュー全体が下へずれる。** クリック前に必ず `computer zoom` で
  いま見えている位置を確かめてから押す。ずれたまま座標で押すと別の項目に当たる。
- **トースト通知のボタンは座標が当たらないことがある。** 確認ダイアログ（「実行」等）は
  ステータスバー右端のベル（通知センター）を開き、そこに並ぶ大きなカードのボタンを押す。
- **ダイアログ（フォルダー選択）・InputBox は座標クリックで本物を触る危険がある。**
  フォルダー選択ダイアログの操作は作者に依頼し、予期せぬInputBox（新規話ファイル名・
  作品名など）が出たらEnterを押さず作者にEscでの取りやめを依頼する。
- **指摘の照合は必ず `computer zoom` で読む。** 0.6倍などの縮小スクショのまま行番号や
  文言を読み取らない（誤読の実績あり）。
- **本物の作品では押さないボタン**：適用／見送り／今後直さない／反映する／保存／書き出し
  （`設定/`や本文に書くもの）／Git操作（記録・送信・同期・書庫化）／クラウドAI（課金の
  確認が出る操作）。本物では「表示・実行して見るだけ」に留める。
- AIは **LM Studio（google/gemma-4-e4b）** を使う。12b（qat）は遅く300秒でtimeoutしやすい
  ので、AI機能を使う前に `lms ps` で12bが読み込まれていないか確認し、いれば
  `lms unload google/gemma-4-12b-qat` で外す。
- ツリーのグループ（「作品管理」など）は行クリックで展開しないことがある。展開しなければ
  矢印（`>`）をクリックする。「AIに相談」「詳細メニュー」のヘッダーを畳むと簡単ステップ
  メニューの表示領域が広がる。長い一覧を触るときは畳んでおく。
- **ボタンの座標は必ず等倍のスクリーンショットから読む。** 0.6倍などから換算すると
  10〜20px ずれて空振りする（実績あり）。とくに**カードに注記の行が増えるとボタン列が
  下へずれる**（「再チェック（時刻）：…」が付くと約16px）。押して反応が無いときは、
  まず等倍で撮り直して位置を取り直す（機能の不具合と決めつけない）。
- **クリックが全部弾かれたら、IME の常駐を疑う。** Windows の「入力エクスペリエンス」
  （`TextInputHost.exe`）が**画面に何も見えないまま前面を握る**ことがあり、
  「Textinputhost is not in the allowed applications」で止まる。作者にも見えないので
  聞いても解決しない。Bash から `Stop-Process -Name TextInputHost -Force` で止める
  （Windows が必要時に入れ直す）。`open_application` では戻らない。
- **通知は溜めない。** 節の区切りごとに通知センター（ステータスバー右端のベル）を開き、
  用の済んだ通知を「通知をすべてクリア」で消す。溜まると確認カード（「実行」ボタン）が
  下へ押し出されて埋もれ、古い通知を新しい結果と読み違える（実績あり）。
- **画面の使い勝手も見る**（作者の依頼、2026-09-06）。押しにくい（境界が分からない・
  小さい・隣と近い）、名称が分かりにくい・実物と違う、表示が崩れる／ダサい、と感じた点を
  気づいた範囲で記録する。判定は作者がするので、こちらは「どこで・何が・どう感じたか」を
  1行ずつ書けばよい。記録先は `実機確認メモ.md` の「デザインの気づき」節。
- 各節を終えたら `実機確認メモ.md` に「見出し・時刻・結果（合格／不具合／判断案件）」を
  1ブロック追記する形式で記録する（既存の記録の書き方を写す）。

## 8. 仕込み方式で「見逃し」を測る（2026-09-06 に確立）

**なぜ要るか**：これまでの実機確認は「誤った指摘が出ないか」（誤検出）に偏っていた。
AI機能は**見逃し**も測らないと、「何も指摘しない実装」が満点になる（CLAUDE.md の
繰り返した失敗2）。既知の誤りを本文へ仕込んで、拾えるかを見る。

**手順**（コピー作品でのみ行う。本物には仕込まない）
1. 対象ファイルを scratchpad へ退避（`cp`）
2. 誤りを仕込む。**改行コードを保つ**こと（`\r\n` を `split`/`join` で扱う。`file` で確認）
3. 検知を実行する。確認画面の「N チャンク中 M 件を処理します」で、**変えたチャンクだけが
   AIへ行く**ことも同時に確認できる
4. 結果を判定し、**退避から元へ戻す**。最後に作品全体のハッシュを控えと突き合わせて
   差分0を確かめる（`sha256sum` の一覧を `diff`）

**仕込む誤りの例と、2026-09-06 の結果**（LM Studio `gemma-4-e4b`）

| 仕込んだもの | 種類 | 結果 |
|---|---|---|
| 「かもしれ**あ**い」（な→あ） | かな1文字の置き換え | **拾った** |
| 「思わなかつた」（っ→つ） | 促音の誤り。日本語では典型 | **素通り** |
| 「目を覚まさ、」（覚まし→覚まさ） | 活用の誤り／脱字 | **素通り** |
| 「おばあさん」→「お婆さん」 | 漢字とかな | **拾わない**（仕様。固有名詞はカナの入れ替えのみ見る） |
| 「おばあさん」→「オバアサン」 | ひらがな⇄カタカナ | **拾った**（2組。うち1組は部分文字列で重なる） |

**1回では測れない（2026-09-06 に実測）**：同じ入力・同じモデル・temperature 0 でも、
拾える回と素通りの回がある（180字 1/1、1,018字 3/4、5,019字 1/1）。**「N回中M回」で書く。**
1回だけの結果から「拾えない」と断定しない。検証で捨てた件数と理由も必ず出す
（生の指摘が有って通した件数が0になることがある）。

**外から測るときは、拡張機能側でAI処理が走っていないことを確かめる（2026-09-06 に踏んだ）**：
API を直接叩くと、拡張機能の「実行の札」（AI処理を1つずつに絞る仕組み）が効かない。
同時に AIチューニングが走っていて 91,488字の要求でサーバーが埋まり、こちらの要求が
すべて `fetch failed` になった。それを「LM Studio が落ちた」と誤って報告した
（CLAUDE.md の繰り返した失敗5そのもの）。測る前に `lms ps` の状態と、
作品の `.aiwriter/logs/actions.log` の末尾を見る。

**判定のしかた**：拾えなかったものは、**プロンプトの問題かモデルの力か**を切り分けるため、
同じ本文を別のモデル（12b、さくらのAI 等）へ通して比べる。片方だけでは結論が出ない。
