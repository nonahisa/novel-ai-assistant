## 2. 進め方

### 2.1 1回の大きさ

- **1回＝1節（`###`）、400行まで。** 400行を超える節（6.87・6.10・6.8・5.5・6.4・6.5・6.25・6.104・6.107 など）は `####` の束で400行以内に割る（6.87 なら 6.87.1〜6.87.10／6.87.11〜6.87.14／6.87.15〜 の3回以上）
- **密度5未満の節は手を付けない**（点数が低い＝もう決まりだけの節。読む分だけ損）。対象は密度の高い順ではなく**点数の高い順**（削れる量が大きい順）。ただし最初の1回は 6.9（3章）
- 1日に回すのは、その日の使用量の目安の内で**2〜3回**まで（4章）

### 2.2 受け渡しの形

1. **リーダー（Opus）**が light-tester（Sonnet）へ投げる。指示に書くもの：対象の節番号と行の範囲、この計画の2.3節（判定の決まり）、`docs-sync` の冒頭、**shell-safety の要点**（置換は `sed` を使わず Edit で。版番号の一括置換をしない）
2. **Sonnet** は作業場（worktree）の枝で、その節だけを書き直してコミットする。報告に次の3つを付ける
   - **消したものの一覧**（1件1行、元の文の頭10字＋理由の札：感想／経緯／重複／覆った見立て）
   - **移す案**：引継ぎ書8章へ足す行の案（後述の決まりで、要るものだけ）
   - **判断に迷ったもの**：消してよいか分からなかった文（消さずに残しておく）
3. **Opus** が確かめる（次の6点。1つでも外れたら差し戻し）
   - **識別子が落ちていない**：節の中のバッククォートで囲んだ語（関数名・ファイル名・理由の札 `not_long` など）の集合を、前後で比べる。消えたものは「消したものの一覧」に理由つきで載っていること
   - **番号つきの見出しが残っている**：`#### 6.9.1` の形の見出しは番号も順もそのまま（3列目参照）
   - **数字が残っている**：測定の表の「最新の行」（日付・モデル・件数）が残っていること
   - **決まりが落ちていない**：「〜する／〜しない」で終わる文と表の行を、前後で突き合わせる
   - **覆った見立てを残していない**：「裁定待ち」「未確認」「〜かもしれない」の文は、引継ぎ書の冒頭・3章・判断待ちの欄と照らし、すでに決着していれば今の決まりに書き直させる
   - `npx vitest run test/unit/cross/designDocToc.test.ts test/unit/cross/promptDocShape.test.ts test/unit/features/showVersion.test.ts` が通る
4. 通ったらリーダーが本流へ取り込み、8章へ移す行を足し、記録を1件書く（「【整理】設計書6.9：224→◯行」）

### 2.3 判定の決まり（消す・残す・移す）

| 分け | 何か | 例（言い回しの型） | 扱い |
|---|---|---|---|
| **残す** | 決めたこと | 「修正案が空の指摘を受け入れる」 | そのまま |
| **残す（縮める）** | なぜ | 「直しようのない指摘が実在するため」 | 1〜3行に。比べた案は「AとBのうちBにした」まで書かず、選んだ側の理由だけ |
| **残す（縮める）** | 事故でしか言えない理由 | 「作者の報告（2026-09-04）：5連続と指摘された箇所は…」 | 「〇〇が起きたため（2026-09-04）」の1行 |
| **残す** | 測った数字 | 表の最新の行（日付・モデル・件数） | 「前／後」の表は**後の行だけ**残し、前の行は消す（前の数字は8章か `docs/measurements/` に既にある） |
| **残す** | 守る決まり・やらないこと | 「分からないときは黙る」「新しい画面は作らない」 | そのまま |
| **残す** | 作者の裁定の出典 | 「（作者の裁定、2026-09-26）」 | 決まりの後ろに括弧で日付だけ。作者の発言の引用は消す（裁定の言葉が決まりそのものなら残す） |
| **消す** | 感想・語り | 「測る前は起きると思っていなかった」「そのとおりである」 | 消す |
| **消す** | 作業の手順の語り | 「本体の作業木で直す前を束ね、同じ写しに当てた」 | 消す（測り方は `docs/measurements/` やスキル `ai-bench` にある） |
| **消す** | 担当の報告の写し・迷った点 | 「Dの正直な指摘が本質的だった」 | 消す |
| **消す** | 覆った見立て・取り消し線 | 「〜は作者の裁定待ち」（決着済み） | 今の決まりへ書き直す。古い文は残さない |
| **移す** | まだ決まっていないこと・確かめていないこと | 「冗長の適用の道が実データで通っていない」 | 実機確認リスト（画面が要るもの）か、引継ぎ書3章・判断待ちの欄（決める必要があるもの）へ1行。設計書からは消す |
| **移す** | 残す価値のある経緯 | 副産物として見つかった別の不具合 | **8章に同じ日付の記録がすでにあれば移さず消す**。無いときだけ8章へ1行 |

**迷ったら残す。** 消しすぎは決まりを失う（取り返しにくい）、残しすぎは次の回で拾える。

### 2.4 節番号を壊さない

設計書の節番号は、`src/` から3,929か所（「設計書x.y」の形だけで）、引継ぎ書から465か所参照されている。今回の整理では：
