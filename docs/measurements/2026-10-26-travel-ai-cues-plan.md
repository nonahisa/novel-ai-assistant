## 2. AI に抜かせるもの（P-37 は変えない。新しいプロンプト2つ）
- P-37 を広げない理由：版を上げると全作品の抽出の控えが無効になり、既存の台の成績も動く
- **P-51 本文の所要時間**（`src/prompts/travelDistanceExtract.ts`）：台帳の場所の名前か別名を含み、「日・時間・馬・徒歩・船・かかる・道のり」を含むチャンクだけを送る。スキーマ `{distances:[{from,to,value,evidence,line}]}`、maxItems 10、value 20字（`LOCATION_RELATION_VALUE_MAX_CHARS`）、evidence 80字
- **P-52 場面の頭の時の経過**（`src/prompts/sceneTimeCue.ts`）：時計で比べられない所在の組（同じ人物・別の場所・表に1日以上の組）のあいだの場面の頭だけ。前の場面の終わり3段落＋この場面の頭5段落。スキーマ `{kind: simultaneous|sameDay|advance|cut|null, days, evidence}`
- 検算（ルール3）：P-51 は既存の `validateLocationRelations`（settingsExtractionValidation.ts）に `ExtractedLocation` の形で通す＋両端が `buildLocationResolver` で台帳の別々の場所に引ける・入れ子でない・`normalizeTravel` で読める。P-52 は引用がその場面の地の文にあり「」の外・advance なら引用の数（漢数字も）が days と一致・それ以外は小さな語の一覧（翌・明け・頃・同じ日・その日 など）を含む。合わなければ cut。見本の値は本文に出ない語にし、見本と同じ値は落とす
- 版：`TRAVEL_DISTANCE_EXTRACT_VERSION`・`SCENE_TIME_CUE_VERSION` は "1.0"。温度0、割当は `factExtract`。控えの鍵は内容ハッシュ＋プロバイダ＋モデル＋版。Ollama は num_ctx・format・think:false
- P-12b travel に「AIの読み」の見出しを足すなら `CONTRADICTION_VERIFY_TRAVEL_VERSION` を 1.1 に

## 3. 距離を設定資料へ「提案」する道（既存の pending-settings）
- 場所 `from` の記録へ「今回足す関係だけ」の写しを承認待ちに積む（proposeRecord.ts の `applyLocationRelations` と同じ作り）。reason は「事実の照合で本文「…」（第N話）から読んだ所要時間」、台詞なら「台詞」と明記
- 直す3点：①`PendingSettingsUpdateStore.stage` が同じ id の案を差し替える→先の案があれば関係だけ足して合わせる ②出どころ `"fact"` を一式（`PendingUpdateSource`・pendingUpdateFormat.ts の読み側・`pendingSourceLabel`「事実の照合から」・MCP の pending.list）③`mergePendingSettingsRecord` は確定した記録（`autoGenerated:false`）に登場話数しか入れない→fact の案では `relations` だけ `newOnly` で足す道
- 作者の関係・`authorLocked` には触れない（`mergeLocationRelations` がそう作られている）
- MCP は Node の fs で同じ `buildPendingSettingsPayload` を書く（extractCommit.ts・proposeRecord.ts に前例）
