# 教科書チートを Sonnet が内部AIの代わりに一通り（2026-10-01）

## 何をしたか

作品「教科書チート」（実際は 219 話。依頼文の「19話」は誤り）に、拡張機能のAI機能を一通り掛けた。内部のAI（Ollama など）の代わりに、Claude Sonnet が MCP 越しに答えた。

- 使った道具は `novel.scan`・`novel.prompt`・`novel.detect`・`novel.validate` だけ。`novel.run`・`novel.propose` は使っていない。
- 原稿・設定資料・許可の印（`external-access.json`）には何も書いていない。答えは作業場の `sonnet-run\` にだけ置いた。
- 1機能ごとに「プロンプトを取る → Sonnet が JSON で答える → 検算に通す」。**検算が落とした理由が、この測定の主な成果。**
- 束 `dist/mcp-server.mjs` は途中で更新された（最初 0.94.6／リポジトリ 0.94.7、終盤 0.94.7／0.94.8）。毎回「束が古い」と出たが、組み直さずそのまま測った。
- 本文の引用は短く最小限にした（未発表原稿）。

### chat の3問

1. 「塩不足は何話から何話までで解決されますか」→ 渡された材料は第16話あらすじで切れている（`以下省略。needFiles で求めてください`）。「渡された範囲では見えない」と答え、`needFiles: ["設定/synopsis.md"]` を返した。検算は通った。
2. 「第2話の誤字脱字を検知してほしい」→ 会話では答えず `run: checkTyposForFile` を返した。`proposals.run: true` になった。
3. 「第1話の冒頭は読者にどう読めますか」→ 見立てを求められた型。良い所を引用して先に述べ、`options`・`run` は空にした。通った。

### 検算が落とした件の詳細

- **推敲 `formal_noun`**（第1話28行・第110話124行）：「事」→「こと」の形式名詞ひらき。作者の裁定（2026-09-26）で検算は拒否する。
- **推敲 `dialogue_voice`**（第110話182行）：台詞の中の同語反復。台詞を対象にしたのは私のミス。設計どおりの拒否。
- **推敲 `not_repeated`**（第2話152行）：「リナの手を拾い…棒を拾って」。「拾い」と「拾って」は活用が違うので反復と見なされない。なお、この行の「リナの手を拾い」自体は本文の誤り（「離し」か）に見えるが、推敲の枠では拾えない。
- **矛盾 `self_denied`**：第110話の line164 の指摘に、note で「矛盾とまでは言えない」と書いたため落ちた。確信が低い指摘を正直に書くほど捨てられる形になる。
- **設定抽出 `invalid_name`**：「インスタンス（火針,32）」。既知の能力に「インスタンス（小火）」という括弧付きの名前があるので、括弧付きが落ちる理由が分からない。

## 気づいた不具合・食い違い

1. **束が古い**。測定中に 0.94.6 → 0.94.7 と更新されたが、いずれも「リポジトリより一つ古い」と出た。新しい束での再測定はしていない。
2. **推敲プロンプトと検算の食い違い**。`src/prompts/proofread.ts` の177行付近は形式名詞のひらきを勧めるが、検算（`formal_noun`）は同じものを拒否する。AI はプロンプトに従うほど落ちる。
3. **推敲プロンプトの出力例 JSON が壊れた形**。`""（何も入れない）` という例が入っている。スキーマには `reason`・`confidence` の enum が無く、プロンプトが示す7種と合っていない。`line` は number（typo は integer）。
4. **推敲の `suggestion` が黙って空になる**。第2話123行で「痛いところ」→「痛いとこ」と書いたが、通過した結果の `suggestion` は空だった。ひらきではない言い換えとして消されたと見えるが、その旨は結果に出ない。
5. **typo の `trimCarriedContext`／`duplicates_context`**。広い target と、前後の句を抱える suggestion の組は落ちる。起点は私の逸脱で、検算は仕様どおり。
6. **notation の数字の組は「表記1〜20」に割れて長い**（約5,498字）。1回で扱いにくい。
7. **矛盾検知のプロンプトが長大**（39,523字）。人物設定が第1〜33話・58〜88話の時点の情報まで含む。
8. **矛盾検知 `self_denied`**：正しい低確信の指摘まで、note の否定的な言い回しで落ちる。
9. **事実照合は predicate の意味を見ない**。「怪我」に別の事柄を入れても通る。22件全部が通ったのは、検算が緩いか私の答えが良かったかの区別がつかない。
10. **設定抽出の `invalid_name` と既知の括弧付き能力名の食い違い**（上記）。設定抽出は作品全体では前のチャンクの既知名を足していくため、単発では出来ばえを測れない。
11. **chat のプロンプトが内容の質問にも使い方の目次を付ける**。「塩不足」の質問で `topic: howto / reason: matched` となり、約4KB の操作の目次と GitHub 作品管理の説明が付いた。プロンプト自身は「作品の内容についての質問では、この目次に触れないこと」と書いている。
12. **chat の材料は第16話で切れる**。各話あらすじ全体が23,299字あるため。`needFiles` で求める作りだが、「作品全体について」の質問は最初の一回では答え切れない。
13. **名前の既存一覧に読みの誤り**。「叡智の天使」が「じしょうてんし」、「マイナ様」が「まいなせんせい」と出る。一覧に場所・組織まで入っている（171件）ため、プロンプトも長い。
14. **chapter の検算は話数が実在するかだけ**。既存の章の始まりを動かす提案（第102話→第100話、第128話→第129話）も、動かす理由の妥当性は見ずに通った。「既存の区切りを尊重する」は検算では守られない。
15. **プロット逆算の登場人物一覧にノイズ**。「クソ親父」「木こり」「狩人さん」など呼称・役割が人物として並ぶ（作品の設定資料側の問題）。
16. **各話あらすじの範囲**：第1話のあらすじ検算で通した範囲は150字以内の確認までで、本文との照合は無い。
17. **deviation と episodePlot は前提不足で断られた**。作品にプロットも単話プロットも無いので正しい動きだが、断りの文から次の一手（プロット逆算を先にやる）へ繋ぐ案内は返らない。
18. **依頼文の「19話」は実際は 219 話**。
19. **PowerShell の標準出力が文字化けする**（表示側の問題）。`[Console]::OutputEncoding = UTF8` が要る。

## 測れていないこと

- 内部のAIそのものの出来ばえ。これは「Sonnet が答えた場合の検算の挙動」の測定で、gemma などの出力品質ではない。
- 第2話・第219話の矛盾検知・事実照合・伏線・設定抽出・あらすじ。第110話か第1話のみの実施。話ごとの機能の「4話程度」は typo と proofread だけが満たしている。
- 複数チャンクにまたがる処理（各話1チャンクだった）。
- 新しい束（リポジトリと同じ版）での再測定。

## 認証の要るMCPについて

Canva・Hugging Face・asana・atlassian・guru・slack・bigquery の各MCPは認証が必要で、非対話セッションでは認可できなかった。この測定には無関係。
