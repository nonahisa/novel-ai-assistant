# 製品の目次（どこに何があるか）

統合小説執筆環境とそのまわりの製品の、リポジトリ・文書・作業場の置き場を一枚にまとめた目次。母艦や新しいセッションは、ここから上から辿る（実装の残り #119。作者の決定 2026-11-14 夜、着手 2026-11-16）。

- ここに書くのは**置き場と、最初に読む文書**だけ。中身（版・いまの状態・次にやること）は各製品の引継ぎ書が正
- 手元の場所は `%USERPROFILE%\Documents\` から書く
- 製品のセッションの名前は「製品：◯◯」で、版を付けない（分担はスキル `team` の「母艦と製品ごとのセッション」）
- 置き場が変わったら、変えたセッションがこの表を直す

## 2. 製品のあいだの約束

| 約束 | 正の置き場 | 見張り |
|---|---|---|
| 統合と投稿ヘルパーの受け渡し（封筒の欄） | novel-post-helper の `docs/設計書.md` 4章 | 統合の設計書の投稿ヘルパーの節と食い違わないかを母艦が見る |
| 統合から Discord のボットへ渡す案内の形 | 統合の `src/core/guideExport.ts` | `guideExport.test.ts`。変えるときは先に「製品：Discord」へ知らせる |
| 統合とモバイル版で共有する部品（`core`・`models`） | 統合の `src/core`・`src/models` | 入れたら母艦へ1行。モバイル版は引継ぎ書1章の決まりで同じ版を取り込む |
| 守る決まり（原稿を壊さない など） | 統合の `docs/共通設計書.md` 2章 | 各製品の CLAUDE.md が写しを持つ |
| 更新の仕組み（新しい版の知らせ・更新の札 `update.json`） | 統合の `docs/更新の仕組み_共通.md` | 各製品の設計書が製品ごとの作りを持つ。札の形を変えるときは母艦が全製品へ知らせる |

## 3. 作業場の置き場

| 置き場 | 何か | 片づけ |
|---|---|---|
| `novel-ai-assistant\.claude\worktrees\agent-*` | 統合のエージェントの作業場（枝は `worktree-agent-*` か作業の名前） | 取り込んだら cleaner。`node_modules` の連結を先に外す |
| `nrel<版>`（例 `nrel119`） | 母艦が配布の前の全件を回す作業場 | 配布が済んだら母艦が片づける |
| `確認用コピー`・`確認用コピー_GitHub試験*` | 作者が F5 で押す台・同期の試験の台（作り物の作品） | 消さない |
| `novel-ai-bench`・`novel-ime-bench` | AI の比べと IME の測定の材料・結果（git の外） | 正解に作品の手がかりがあるのでリポジトリへ入れない |
| スクラッチパッド | セッションごとの一時のファイル | 作者が触る台には使わない |

## 4. 製品の外の置き場

| 置き場 | 何か |
|---|---|
| `novel`・`小説` | 作者の原稿（読むだけ。実接続の測定には環境変数 `NOVELAI_WORKS` で場所を渡し、ソースに書かない） |
| `%USERPROFILE%\.claude\mods\progress-panel` | 母艦の横の進捗パネル。急がない問いは `inbox\` に1件1ファイル |
| `%USERPROFILE%\.claude\projects\<プロジェクト>\memory\` | セッションをまたぐ覚え（`MEMORY.md` が索引） |
| 各リポジトリの `.claude\skills\` | 作業の手順（統合は `team`・`release`・`docs-sync` など） |
| Google ドライブの「母艦への受け渡し」 | 別の機械（ノートPC・Mac）とのファイルの受け渡し。取り込んだらごみ箱へ |
