# 台本：編集部の実機確認（hisa × kmizu さん）

2026-10-27 作成、2026-10-28 改訂。実機確認リストの【束：編集部】を1回通すための台本です。

二人が同時に作業する必要はありません。やり取りは「hisa が渡す」と「kmizu さんが返す」の2回だけで、それ以外はそれぞれの都合のよいときに進めます。

**確かめること**
1. kmizu さん（編集部）が返した提案が、hisa の「編集部からの提案」に届くか
2. hisa が提案を採るか見送るかを選ぶと、そのとおりに効くか（採った提案だけ本文が変わる）
3. hisa が見送ったことが、kmizu さんにも伝わるか

**使う作品**：「たゆたう鉛-実験用」。「パンドラの箱」を区切りまで書いてから渡します

**役割**
- hisa：作品の持ち主。VS Code で作品を渡し、返ってきた提案を採るか見送るかを決める
- kmizu さん：編集部。ご自分のパソコンの VS Code で校閲し、提案を返す
- 母艦（Claude）：段ごとに、GitHub の記録と作品の中の提案・編集履歴のファイルを読んで結果を確かめ、hisa に伝える

---

## 0. 準備

### hisa
- VS Code に統合小説執筆環境が入っている（0.114.0 以降）
- GitHub CLI（`gh`）が使える

### kmizu さん（hisa から事前に伝える）
- GitHub のアカウント（ユーザー名を hisa に知らせてください）
- VS Code と Git が入っている
- VS Code の拡張機能「統合小説執筆環境」（Marketplace の `nonahisa.novel-ai-assistant`）を入れておく
- VS Code の左下の人の形のアイコンから、GitHub にサインインしておく（非公開のリポジトリを取り寄せるため）
- AI は無くてもかまいません。AI を使わない「表記ゆれ検知」でも提案は作れます。手元かクラウドに AI があれば、「誤字脱字検知」や「推敲」も使えます

---

## 1. hisa：作品を渡す

1. hisa が、VS Code の左の「統合小説執筆環境」の作品一覧で「たゆたう鉛-実験用」を選ぶ
2. hisa が、詳細メニュー →「作品管理」→「編集部連携」→「編集部共有」を押す
   - 編集用フォルダーの置き場を訊かれたら、Documents の中の「編集部」フォルダーを選ぶ（作品フォルダーの中は選ばない。中に置くと断られる）
   - リポジトリの名前を訊かれたら、`tayutau-namari-jikken` と打つ
3. 正しい結果：右下に「『たゆたう鉛-実験用』を編集部へ渡せる形にしました。GitHubの『Settings』→『Collaborators』から編集部を招いてください。」と［GitHubで開く］が出る
4. hisa が［GitHubで開く］を押し、GitHub の画面の「Settings」→「Collaborators」→「Add people」で、kmizu さんのユーザー名を入れて招く
5. hisa が kmizu さんに「招待を送りました」と伝える（渡すのはここまで）

**母艦が確かめること**：GitHub に非公開のリポジトリができ、本文と `.aiwriter/proposals/` が送られているか

---

## 2. kmizu さん：受け取って校閲し、提案を返す

都合のよいときに、まとめて進めてください。

1. GitHub から届いた招待のメール（または GitHub の通知）で「Accept invitation」を押す
2. VS Code の詳細メニュー →「作品管理」→「クラウド取得」→「GitHubから追加」を押し、`<hisa のユーザー名>/tayutau-namari-jikken` を選ぶ。置き場はどこでもよい
3. 詳細メニュー →「作品管理」→「編集部連携」→「作者／編集者切替」を押し、「編集者」を選ぶ
   - 切り替える前に、編集者モードで使えなくなる操作の一覧が出ます。切り替えたあとは詳細メニューの多くが押せなくなり、押すと理由が出ます（故障ではありません）
4. 見る話を開き、詳細メニュー →「作品管理」→「編集部連携」→「校閲開始／終了」を押す（その話に校閲中の印がつく）
5. 詳細メニュー →「自己校正」→「校正・校閲」から、「表記ゆれ検知」などを走らせる
6. 「提案」パネルに並んだ指摘のうち、直したほうがよいものに［適用］を押す
   - 正しい結果：本文は変わらない。編集者モードでは、［適用］を押すと提案として置かれる
7. 見終わったら、もう一度「校閲開始／終了」を押して校閲を終える
8. 詳細メニュー →「作品管理」→「GitHub作品管理」→「同期」を押して返す
9. hisa に「返しました」と伝える（返すのはここまで）

**母艦が確かめること**：GitHub のリポジトリに kmizu さんのコミットが届き、`.aiwriter/proposals/proposals.jsonl` に提案が増え、本文が変わっていないか。編集履歴 `.aiwriter/history/edits.jsonl` に編集者（▲）の行があるか

---

## 3. hisa：受け取って、採るか見送るかを決める

1. hisa が、作品「たゆたう鉛-実験用」を選んだまま、詳細メニュー →「作品管理」→「編集部連携」→「編集部提案取込」を押す
2. 詳細メニュー →「作品管理」→「編集部連携」→「編集部提案確認」を押す
   - 正しい結果：「編集部からの提案が N 件あります。『提案』パネルで1件ずつご確認ください。」が出て、提案パネルに kmizu さんの提案が並ぶ
3. 提案を1件ずつ見て、［適用］（採る）か［見送り］を押す。確かめのため、採るものと見送るものを1件以上ずつ選ぶ
   - 正しい結果：採った提案だけ本文が変わる。見送った箇所は本文がそのまま
4. もう一度「編集部共有」を押し、採ったか見送ったかの結果を編集部の側へ送る

**母艦が確かめること**：本文が採った提案のとおりに変わっているか。編集用フォルダーと GitHub の `proposals.jsonl` に、採った・見送ったの行が足されているか（提案の行は書き換えず、決めた行を足す作り）

---

## 4. kmizu さん：見送りが伝わったかを見る（次に開いたときでよい）

1. 詳細メニュー →「作品管理」→「GitHub作品管理」→「同期」を押して取り寄せる
2. 詳細メニュー →「作品管理」→「編集部連携」→「編集部提案確認」を押す
   - 正しい結果：「未決の提案はありません（これまでに N 件の提案がありました）」のように、未決が減っている
3. 詳細メニュー →「執筆データ」→「編集履歴」を開き、hisa（●）が採ったことと見送ったことが並んでいるかを見る
4. 確かめが済んだら、「作者／編集者切替」で「作者」に戻す（ご自分の環境を元に戻すため）

**母艦が確かめること**：kmizu さんの側に、hisa が決めた行が届いているか（GitHub のリポジトリの `proposals.jsonl`）

---

## うまくいかないとき

- 「GitHubへ送るには `gh`（GitHub CLI）が要ります」と出た：編集用フォルダーはできています。母艦に知らせてください
- kmizu さんの側でリポジトリが見つからない：招待を受け入れたか、VS Code で GitHub にサインインしているかを確かめる
- 押しても何も起きない：編集者モードでは押せない操作かもしれません。押したときに出る理由を、そのまま母艦へ伝えてください
- 迷ったら、その場の画面の写しを母艦へ送ってください。母艦が次の一手を伝えます
