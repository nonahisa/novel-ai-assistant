# 台本：編集部の実機確認（作者さん × kmizu さん）

2026-10-27 作成。実機確認リストの【束：編集部】を1回通すための台本です。

**確かめること**
1. kmizu さん（編集部）が送った提案が、作者さんの「編集部からの提案」に届くか
2. 作者さんが採る／見送るを選ぶと、そのとおりに効くか（採ったものだけ本文が変わる）
3. 作者さんが見送ったことが、kmizu さんの側にも伝わるか

**役割**
- 作者さん：作品の持ち主。母艦（このパソコン）の VS Code で操作する
- kmizu さん：編集部。ご自分のパソコンの VS Code で操作する
- 母艦（Claude）：段ごとにファイルと GitHub の記録で結果を確かめ、作者さんに伝える。AI と MCP サーバーは、母艦が結果を読むために使う

**かかる時間**：準備を含めて40分ほど。kmizu さんとは、通話かチャットでつないでおくと進めやすい

---

## 0. 準備（始める前に）

### 作者さん
- 母艦の VS Code に、統合小説執筆環境が入っている（0.113.0 以降）
- GitHub CLI（`gh`）が使える（10-23 に使えることを確かめ済み）
- 確かめに使う作品：`Documents\確認用コピー\編集部確かめ_確認用`（作り物。母艦が用意済み。表記ゆれと誤字を仕込んであり、中身は同じフォルダーの `README_台の中身.md`）

### kmizu さん（作者さんから事前にお伝えください）
- GitHub のアカウント（作者さんに**ユーザー名**を教えてください）
- VS Code と Git が入っている
- VS Code の拡張機能「統合小説執筆環境」（Marketplace の `nonahisa.novel-ai-assistant`）を入れておく
- VS Code の左下の人の形のアイコンから、GitHub にサインインしておく（非公開のリポジトリを取り寄せるため）
- AI は無くてもかまいません（この台本は、AI を使わない「表記ゆれ検知」で提案を作ります。手元の AI かクラウドの AI があれば、「誤字脱字検知」も試せます）

## 1. 作者さん：作品を登録して、編集部へ渡す

1. **作者さん**が、母艦の VS Code の左の「統合小説執筆環境」の作品一覧で、詳細メニュー →「作品管理」→「既存原稿登録」→「フォルダー登録」を押し、`Documents\確認用コピー\編集部確かめ_確認用` を選ぶ
2. **作者さん**が、作品一覧で「編集部確かめ_確認用」を選ぶ（ほかの作品を選んだまま進めない）
3. **作者さん**が、詳細メニュー →「作品管理」→「編集部連携」→「編集部共有」を押す
   - 編集用フォルダーの置き場を訊かれたら、`Documents\確認用コピー\編集部確かめ_編集用` のように、**作品フォルダーの外**を選ぶ
   - リポジトリの名前を訊かれたら、`henshu-test-20261027` など英数字で
4. 正しい結果：右下に「『編集部確かめ_確認用』を編集部へ渡せる形にしました。GitHubの『Settings』→『Collaborators』から編集部を招いてください。」と［GitHubで開く］が出る
5. **作者さん**が［GitHubで開く］を押し、GitHub の画面の「Settings」→「Collaborators」→「Add people」で **kmizu さんのユーザー名**を入れて招く

**母艦が確かめること**：GitHub に非公開のリポジトリができ、本文2話と `.aiwriter/proposals/` が送られているか（`gh api`）

---

## 2. kmizu さん：受け取って、編集者モードにする

1. **kmizu さん**が、GitHub から届いた招待のメール（または GitHub の通知）で「Accept invitation」を押す
2. **kmizu さん**が、ご自分の VS Code の左の「統合小説執筆環境」の詳細メニュー →「作品管理」→「クラウド取得」→「GitHubから追加」を押し、作者さんから聞いたリポジトリ（`<作者さんのユーザー名>/henshu-test-20261027`）を選ぶ。置き場はどこでもよい
3. **kmizu さん**が、詳細メニュー →「作品管理」→「編集部連携」→「作者／編集者切替」を押し、**編集者**を選ぶ
4. 正しい結果：切り替える前に「編集者モードにすると使えなくなる操作」の一覧が出る。切り替えたあと、詳細メニューの多くが押せなくなり、押すと理由が出る（壊れたのではありません）

---

## 3. kmizu さん：校閲して、提案を送る

1. **kmizu さん**が、作品一覧で「第1話」を開く
2. **kmizu さん**が、詳細メニュー →「作品管理」→「編集部連携」→「校閲開始／終了」を押す（第1話に校閲中の印がつく）
3. **kmizu さん**が、詳細メニュー →「自己校正」→「校正・校閲」→「表記ゆれ検知」を押す
   - 「良い／よい」「出来る／できる」の揺れが出る。どちらに揃えるかを選ぶと、少数派の箇所が「提案」パネルに並ぶ
4. **kmizu さん**が、「提案」パネルで**2件以上**に［適用］を押す
   - 正しい結果：**本文は変わらない**。編集者モードでは、［適用］は「提案として置く」になる
   - （AI がある方は、「誤字脱字検知」で「学校えの道」「頭にはいてこなかった」も拾えるか試し、同じく［適用］で提案にしてください）
5. **kmizu さん**が、もう一度「校閲開始／終了」を押して校閲を終える
6. **kmizu さん**が、詳細メニュー →「作品管理」→「GitHub作品管理」→「同期」を押して送る

**母艦が確かめること**：GitHub のリポジトリに kmizu さんのコミットが届き、`.aiwriter/proposals/proposals.jsonl` に提案の行が増え、本文が変わっていないか。編集履歴 `.aiwriter/history/edits.jsonl` に、編集者（▲）の行があるか

---

## 4. 作者さん：受け取って、採る／見送る

1. **作者さん**が、母艦の VS Code で作品「編集部確かめ_確認用」を選んだまま、詳細メニュー →「作品管理」→「編集部連携」→「編集部提案取込」を押す
2. **作者さん**が、詳細メニュー →「作品管理」→「編集部連携」→「編集部提案確認」を押す
   - 正しい結果：「編集部からの提案が N 件あります。『提案』パネルで1件ずつご確認ください。」が出て、提案パネルに kmizu さんの提案が並ぶ
3. **作者さん**が、提案パネルで**1件に［適用］**（採る）、**1件に［見送り］**を押す
   - 正しい結果：採った1件だけ本文が変わる。見送った箇所は本文がそのまま
4. **作者さん**が、もう一度「編集部共有」を押して、決めたことを kmizu さんの側へ送る

**母艦が確かめること**：作品の本文で採った1件だけが変わっているか。編集用フォルダーと GitHub の `proposals.jsonl` に、採った・見送ったの行が足されているか（提案そのものの行は書き換えず、決定の行を足す作り）

---

## 5. kmizu さん：見送りが伝わったかを見る

1. **kmizu さん**が、詳細メニュー →「作品管理」→「GitHub作品管理」→「同期」を押して取り寄せる
2. **kmizu さん**が、詳細メニュー →「作品管理」→「編集部連携」→「編集部提案確認」を押す
   - 正しい結果：「未決の提案はありません（これまでに N 件の提案がありました）」のように、未決が減っている
3. **kmizu さん**が、詳細メニュー →「執筆データ」→「編集履歴」を開き、作者さん（●）が採った・見送ったことが並んでいるかを見る
4. **kmizu さん**が、「作者／編集者切替」で**作者**に戻す（ご自分の環境を元に戻すため）

**母艦が確かめること**：kmizu さんの側に、作者さんの決定の行が届いているか（GitHub のリポジトリの `proposals.jsonl`）

## うまくいかないとき

- 「GitHubへ送るには `gh`（GitHub CLI）が要ります」と出た：編集用フォルダーは作られています。母艦に知らせてください
- kmizu さんの側でリポジトリが見つからない：招待を受け入れたか、VS Code で GitHub にサインインしているかを確かめる
- 押しても何も起きない：編集者モードで押せない操作の可能性があります。押したときに出る理由を、そのまま母艦へ伝えてください
- 迷ったら、その場の画面の写しを母艦へ送ってください。母艦が次の一手を伝えます
