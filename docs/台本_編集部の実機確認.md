# 台本：編集部の実機確認（hisa × kmizu さん）

2026-10-27 作成、2026-10-30 改訂（0.115.0 の編集部連携の自動化と校閲の範囲に合わせ、行う順に並べ直した）。実機確認リストの【束：編集部】を1回通すための台本です。

二人が同時に作業する必要はありません。やり取りは次の順で、それぞれの都合のよいときに進めます。

1. hisa が渡す
2. kmizu さんが参加して、範囲を選んで校閲する
3. hisa が、校閲中の範囲を確かめる（kmizu さんが返す前に行う）
4. kmizu さんが返す
5. hisa が採否を決める（決め終えると自動で送り返る）
6. kmizu さんが受け取る
7. （試すなら最後に）hisa が連携を解除する

**確かめること**
1. hisa の「編集部へ渡す」1回で、非公開のリポジトリができて kmizu さんへの招待まで届くか
2. kmizu さん（編集部）が、リンクを貼るだけで参加でき、範囲を選んで校閲し、提案を返せるか
3. 校閲の範囲の話を hisa が書けず、範囲の外は書けるか
4. 返した提案が、hisa が同期したあとに知らせと一緒に届き、提案パネルが開くか
5. hisa が提案を採るか見送るかを選ぶと、そのとおりに効くか（採った提案だけ本文が変わる）。決め終えると、自動で送り返されるか
6. hisa が見送ったことが、kmizu さんにも伝わるか

**使う作品**：「たゆたう鉛-実験用」。「パンドラの箱」を区切りまで書いてから渡します

**役割**
- hisa：作品の持ち主。VS Code で作品を渡し、返ってきた提案を採るか見送るかを決める
- kmizu さん：編集部。ご自分のパソコンの VS Code で校閲し、提案を返す
- 母艦（Claude）：段ごとに、GitHub の記録と作品の中の提案・鍵・編集履歴のファイルを読んで結果を確かめ、hisa に伝える

---

## 0. 準備

### hisa
- VS Code に統合小説執筆環境の 0.115.0 以降が入っている
- VS Code の GitHub アカウントにサインインしている、または GitHub CLI（`gh`）が使える（どちらか一方でよい。アカウントの道を先に使い、`gh` は代わり）
- kmizu さんの GitHub のユーザー名を聞いている
- kmizu さんと、校閲してもらう話の範囲を決めておく（例：第2話〜第3話）。範囲の外の話も1つ決めておく（例：第5話。手順3で書いてみるため）

### kmizu さん（hisa から事前に伝える）
- GitHub のアカウント（ユーザー名を hisa に知らせてください）
- VS Code と Git が入っている
- VS Code の拡張機能「統合小説執筆環境」（Marketplace の `nonahisa.novel-ai-assistant`）の 0.115.0 以降を入れておく
- VS Code の左下の人の形のアイコンから、GitHub にサインインしておく（非公開のリポジトリを取り寄せるため）
- AI は無くてもかまいません。AI を使わない「表記ゆれ検知」でも提案は作れます。手元かクラウドに AI があれば、「誤字脱字検知」や「推敲」も使えます

---

## 1. hisa：編集部へ渡す（1回）

1. VS Code の左の「統合小説執筆環境」の作品一覧で「たゆたう鉛-実験用」を選ぶ
2. 詳細メニュー →「作品管理」→「編集部連携」→「編集部へ渡す」を押し、確認の窓で進める
   - 置き場とリポジトリの名前は訊かれません（自動で決まります）
   - 初回だけ、編集部の GitHub 名を訊かれるので、kmizu さんのユーザー名を入れる
3. 正しい結果：右下に「『たゆたう鉛-実験用』を編集部へ渡し、kmizu さんを招待しました。」と招待のリンク、［リンクを写す］が出る
4. ［リンクを写す］を押し、写したリンクを kmizu さんへ送る（メールやチャットなど）。渡すのはここまで

**母艦が確かめること**
- GitHub に非公開のリポジトリ（`<英数字の題 or novel-日付>-editing`）ができ、本文と `.aiwriter/proposals/` が送られているか
- 置き場が、既定の置き場の下の `編集部/たゆたう鉛-実験用-編集用`（名前は題による）になっているか
- 作品の `.aiwriter/editing.json` に、送り先の URL と kmizu さんの名前が入っているか

---

## 2. kmizu さん：参加して、範囲を選んで校閲する（まだ返さない）

1. 詳細メニュー →「作品管理」→「編集部連携」→「編集部として参加」を押し、hisa から届いたリンクを貼る
   - 招待の受諾・取り寄せ・登録・編集者モードへの切り替えまでが1回で通る
   - 編集者モードに切り替える前に、使えなくなる操作の一覧が出ます。切り替えたあとは詳細メニューの多くが押せなくなり、押すと理由が出ます（故障ではありません）
   - 作品を既に登録している環境では、切り替える前に「作品は1つまで」の知らせが出て止まります
2. 詳細メニュー →「作品管理」→「編集部連携」→「校閲開始／終了」を押し、**始めの話と終わりの話を選ぶ**（準備で決めた範囲。例：第2話〜第3話）
   - 正しい結果：「第2話〜第3話を校閲中にしました。」が出る。校閲中の印は、そのまま GitHub へ送られる
3. 詳細メニュー →「自己校正」→「校正・校閲」から、「表記ゆれ検知」などを走らせる
4. 「提案」パネルに並んだ指摘のうち、直したほうがよいものに［適用］を押す
   - 正しい結果：本文は変わらない。編集者モードでは、［適用］を押すと提案として置かれる
5. ここで、hisa に「校閲中です」と伝える。**「校閲を終えて返す」は、hisa が手順3を済ませるまで押さない**

**母艦が確かめること**：校閲の範囲の鍵が、GitHub のリポジトリの `.aiwriter/locks/locks.jsonl` に届いているか

---

## 3. hisa：校閲中の範囲を確かめる（kmizu さんが返す前に）

1. 詳細メニュー →「作品管理」→「GitHub作品管理」→「同期」を押す（または VS Code を開き直す）
   - 正しい結果：「編集部が第2話〜第3話を校閲中です。」の知らせが出る（校閲中の印は、同期のあとに hisa の手元へ届く）
2. 範囲の話（例：第2話）を原稿エディターで開き、文字を打つ
   - 正しい結果：「『第2話』は編集部が校閲中のため、書けません」の知らせが出る（［連携を解除…］つき）。打った字は一瞬出て戻り、本文には入らない。エディターの［戻す］に、打った字の控えが残る
3. 同じ話を、VS Code の素のテキストエディターで開く
   - 正しい結果：「編集部が校閲中です」の警告が出る。素のテキストエディターでは書けてしまうが、保存すると「編集部へは送り直されません」と出る（確かめたら、書いた分は元に戻しておく）
4. 提案パネルで、範囲の話への提案があれば［適用］を押す（無ければ飛ばす）
   - 正しい結果：「編集部が校閲中のため、適用できません。」と断られる（「それでも直す」は出ない）
5. 範囲の外の話（例：第5話）を開いて書き、保存して、「同期」を押す
   - 正しい結果：普通に書けて、同期もできる
6. kmizu さんに「確かめ終わりました。返してください」と伝える

**母艦が確かめること**：範囲の話の本文が、打ったあとも元のままか。範囲の外の話が同期されているか

---

## 4. kmizu さん：校閲を終えて返す

1. 詳細メニュー →「作品管理」→「編集部連携」→「校閲を終えて返す」を押し、確認の窓で進める
   - 正しい結果：「校閲を終えて、提案 N 件を作者へ返しました。」が出る。校閲中の印がすべて外れ、提案・鍵・編集履歴だけが送られる
   - 本文に記録していない変更があるときは、何も送らずに止まる（編集者モードは本文を書き換えない作りなので、通常は出ません）
2. hisa に「返しました」と伝える

**母艦が確かめること**
- kmizu さんのコミットが届き、`.aiwriter/proposals/proposals.jsonl` に提案が増え、鍵の解除の行があり、本文が変わっていないか
- 編集履歴 `.aiwriter/history/edits.jsonl` に編集者（▲）の行があるか

---

## 5. hisa：同期すると届く。採否を決めると自動で送り返る

1. 「同期」を押す（または VS Code を開き直す）
   - 正しい結果：「編集部から提案が N 件届きました」と「第2話〜第3話の校閲が終わりました」の知らせが出て、提案パネルが開き、kmizu さんの提案が並ぶ
2. 提案を1件ずつ見て、［適用］（採る）か［見送り］を押す。確かめのため、採るものと見送るものを1件以上ずつ選ぶ
   - 正しい結果：採った提案だけ本文が変わる。見送った箇所は本文がそのまま
3. 最後の1件を決めて、未決が0件になる
   - 正しい結果：「採否を編集部へ送り返しました」が出る（確認の窓は出ない。手で「編集部へ渡す」を押す必要は無い）
4. 範囲だった話（第2話）を、原稿エディターでもう一度打ってみる
   - 正しい結果：校閲が終わったので、普通に書ける

**母艦が確かめること**
- 本文が、採った提案のとおりに変わっているか
- 編集用フォルダーと GitHub の `proposals.jsonl` に、採った・見送ったの行が足されているか（提案の行は書き換えず、決めた行を足す作り）
- 送り返しが1本にまとまっているか（コミットが採否の件数ぶん並んでいない）

---

## 6. kmizu さん：開くと届く（次に開いたときでよい）

1. VS Code を開く（または「同期」を押す）
   - 正しい結果：開いたときに自動で取り寄せられる
2. 詳細メニュー →「作品管理」→「編集部連携」→「編集部提案確認」を押す
   - 正しい結果：「未決の提案はありません（これまでに N 件の提案がありました）。」のように、未決が減っている
3. 詳細メニュー →「執筆データ」→「編集履歴」を開き、hisa（●）が採ったことと見送ったことが並んでいるかを見る
4. 確かめが済んだら、「作者／編集者切替」で「作者」に戻す（ご自分の環境を元に戻すため）

**母艦が確かめること**：kmizu さんの側に、hisa が決めた行が届いているか（GitHub のリポジトリの `proposals.jsonl`）

---

## 7. 最後に（試すなら）：編集部連携を解除する

これは決裂したときの出口です。ここまでの確かめがすべて済んでから、最後に試します。実行すると kmizu さんの権利が外れるので、**試すときは kmizu さんに前もって伝えてください。** 試さない場合は、この節を飛ばします。

範囲を解く様子も見るなら、先に kmizu さんにもう一度「校閲開始／終了」で範囲を選んでもらい、hisa が「同期」で印を受け取ってから進めます。

1. 作品「たゆたう鉛-実験用」を選び、詳細メニュー →「作品管理」→「編集部連携」→「編集部連携を解除」を押し、確認の窓で進める
   - 正しい結果：校閲中の印が作者の名で外れ、GitHub の共同編集者から kmizu さんが外れる。外せなかったときは、「GitHub の Settings→Collaborators で手で外してください」という案内と［GitHubで開く］が出る（印は外れている）
2. 範囲だった話を原稿エディターで打つ
   - 正しい結果：普通に書ける

**母艦が確かめること**：鍵の台帳に解除の行（作者の名）があるか。GitHub の Collaborators から kmizu さんが消えているか。`.aiwriter/editing.json` から kmizu さんの名前が消えているか

---

## うまくいかないとき

- 「編集用フォルダーは用意しました」とだけ出て送られない：VS Code の GitHub アカウントへのサインインか `gh` が要ります。整えてから「編集部へ渡す」をもう一度押してください
- 「編集部へ渡しました。ただし招待はできませんでした」と出た：GitHub の「Settings」→「Collaborators」から手で招いてください（理由が知らせに出ます）
- kmizu さんの側でリポジトリが見つからない：招待を受け入れたか、VS Code で招待を受けた GitHub アカウントにサインインしているかを確かめる
- 手順3で校閲中の知らせが出ない：kmizu さんが範囲を選んだあと、hisa が「同期」を押したかを確かめる
- 「作品フォルダーの中には置けません」と出た：置き場が作品の中か、作品を含む場所になっています。母艦に知らせてください
- 押しても何も起きない：編集者モードでは押せない操作かもしれません。押したときに出る理由を、そのまま母艦へ伝えてください
- 迷ったら、その場の画面の写しを母艦へ送ってください。母艦が次の一手を伝えます
