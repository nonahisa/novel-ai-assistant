# 投稿支援の検討レポート——4サイトへ「手軽に書き込む」方法と、PV・評価の取り込み

2026-08-29 作成。作者の依頼：「なろう、カクヨム、アルファポリス、ネオページに作品をできるだけ手軽に書き込む方法を検討してレポートをください。**ＨＰを機械的にクロールすることは禁止されています。** 拡張機能内でログインして該当ページを開いて自動で入力フォームを埋める。ブックマークレットを経由する。などを考えました。なお、同様の手法で話数ごとのページビュー数や評価ポイント、いいねの数値を取得して分析できるようにしたいです」。

---

## 結論（先にまとめ）

1. **「拡張機能の中でログインして自動入力」は、VS Codeでは作れない**（後述の技術的理由）。いちばん近くて安全なのは、**「拡張機能が全部そろえる → ブラウザで投稿ページを開く → ブックマークレット1クリックで欄が埋まる」**の形。
2. 守る原則はひとつで足りる：**機械がサイトへ触れてよいのは、公式APIだけ。それ以外は、作者が自分で開いた画面から、作者の操作で写す。** クロール禁止はこの原則で自動的に守られる。
3. 分析は**なろうだけが別格**。公式の「なろう小説API」が評価ポイント・ブックマーク・感想数などを機械アクセス公認で返すので、ここだけは全自動の記録・グラフ化が正々堂々と作れる。
4. **話数ごとのPVは、4サイトとも公式の機械経路が無い**（作者用の管理画面のみ。カクヨムのGoogle Analytics連携は2023年6月15日に廃止済み）。ここは「作者が解析ページを開く → ブックマークレットで表を1クリックコピー → 拡張機能へ貼り付け → 解析・グラフは拡張機能」の**半自動**が上限である。
5. 実装は3段に分けるのを推奨：**第1段=投稿の下ごしらえ（クリップボード+ページを開く）**、**第2段=なろうAPIの自動記録**、**第3段=ブックマークレット（投稿の自動入力と解析表の取り込み）**。

## 2. 「手軽に書き込む」4つの案の比較

### 案C（作者の案）：拡張機能内でログインして該当ページを開き、自動でフォームを埋める → **作れない**

VS Codeの画面（WebView）には、次の壁がある。

- **外部サイトをVS Codeの中に表示できない。** 投稿サイトは `X-Frame-Options` / CSP で埋め込みを拒んでおり、WebViewのiframeには出ない
- 仮に表示できても、**WebViewから他サイトのページの中身（フォーム）には触れない**（ブラウザの同一生成元ポリシー。これはVS Codeの制限ではなくWebの原則）
- ログインの**Cookieを拡張機能が持てない**。持てたとしても、それは「資格情報を拡張機能が預かる」ことになり、この拡張機能が守ってきた「APIキーすら資格情報ストアに隔離する」方針と衝突する

つまり「ログイン済みの投稿ページに拡張機能が書き込む」は、**ブラウザの外からは原理的にできない**。できる形にすると案D（ブラウザの遠隔操縦）になる。

### 案D：外部ブラウザの自動操縦（Playwright等でChromeを操作） → **技術的には可能だが、勧めない**

- なろうでは**規約違反が明白**（API以外の自動アクセスの明文禁止に触れる）
- カクヨム・アルファポリスでも「運営を妨害する行為」の解釈次第でアカウント停止の恐れ。**投稿アカウントは作者の資産**であり、失うものが大きすぎる
- 技術的にも脆い：サイトの画面変更・CAPTCHA・二段階認証のたびに壊れ、壊れたことに投稿失敗で気づく

### 案A：クリップボード+ページを開く（**第1段として推奨**）

いまある「投稿用にコピー」（記法変換）を**投稿の一連の流れ**に組み立て直す。

1. 詳細メニュー「この話を投稿する」→ サイトを選ぶ（傍点があるときだけ。既存の `pickEmphasisSite` と同じ）
2. 拡張機能がやること：記法をサイト向けに変換 → **本文をクリップボードへ** → サブタイトル・前書き・後書きも順に写せるよう小さな確認を出す → **そのサイトの新規エピソード投稿URLをブラウザで開く**（`vscode.env.openExternal`）
3. 作者がやること：**貼り付けて、投稿ボタンを押す**だけ

- 規約リスク：**ゼロ**（サイトから見れば手動投稿と完全に同じ）
- 4サイトすべてで同じ形が使える。ログインもサイト側のブラウザ任せ
- 弱点：貼り付ける欄が複数あるとき（サブタイトル＋本文）に、コピーを2回に分ける手間が残る → 案Bで解消

### 案B：ブックマークレット（**第2段として推奨。作者の案そのもの**）

案Aの「貼り付け」を1クリックにする。ブックマークレットは**作者が自分のブラウザに登録し、作者が投稿ページを開いてから、作者が押す**——機械が勝手にアクセスする要素がどこにも無い。

- 仕組み：拡張機能が「投稿へ進む」時に、**タイトル・本文・前書き等をJSONでクリップボードへ**入れる。投稿ページでブックマークレットを押すと、クリップボードを読んで（`navigator.clipboard.readText`。ユーザー操作起点なので許可される）、**そのサイトのフォームの該当欄へ流し込む**。投稿ボタンは押さない——**最後の1押しは必ず作者**（誤爆・重複投稿の防止と、規約上も「投稿したのは人」であることを保つ）
- ブックマークレットの中身はサイトごとに欄のIDが違うので4本作る。**生成と説明は拡張機能が持つ**（「ブックマークレットを設定する」コマンドで、ドラッグ登録用のリンクを含む案内ページを開く）
- 弱点：サイトの画面改修で欄のIDが変わると動かなくなる。ただし壊れ方が安全（**埋まらないだけ**。案Aの手貼りへ自然に戻る）。CSPが厳しいサイトではブックマークレット自体が動かない可能性があり、そのときも案Aへ戻るだけ

**推奨の組み合わせ：案Aを土台に、案Bを上に載せる。** 案Bが動かない環境・タイミングでも案Aとして成立するのが利点。

## 3. PV・評価・いいねの取得と分析

### 3.1 なろう：全自動でよい（公式APIがあるため）

[なろう小説API](https://dev.syosetu.com/man/api/)が**作品単位**で返すもの：総合評価ポイント（global_point）・日間/週間/月間/四半期/年間ポイント・ブックマーク数（fav_novel_cnt）・感想数（impression_cnt）・レビュー数（review_cnt）・評価者数（all_hyoka_cnt）など。

- 拡張機能が1日1回（または「更新」ボタンで）APIを呼び、`.aiwriter/analytics/narou.jsonl` へ**追記だけ**で記録 → 執筆統計と同じ自前SVGでグラフ化（ポイント・ブクマの推移）
- APIはNコード指定で引けるので、作品に「なろうのNコード」を1つ設定してもらうだけで動く
- 注意：APIが返すのは**作品単位**。**話数ごとのPVはAPIでは取れない**（下の3.2へ）
- 節度：キャッシュを持ち、無駄な連打をしない（なろうデベロッパーの流儀。既存のチャンクキャッシュと同じ思想）

### 3.2 話数ごとのPV（4サイト共通）：「作者が開き、1クリックで写す」

話数ごとのPVは、なろうなら[KASASAGI](https://kasasagi.hinaproject.com/)の「部分別」、カクヨムならダッシュボード、アルファポリスなら投稿インセンティブ／アクセス解析、ネオページなら（あれば）解析画面——**すべてログイン必須の作者用画面で、API・エクスポート機能は無い**（カクヨムのGoogle Analytics連携は2023年6月15日に停止済みで、復活していない）。

これを自動で取りに行くことは、原則（機械が触るのは公式APIだけ）に反するのでやらない。代わりに：

1. 詳細メニュー「アクセス数を取り込む」→ 該当サイトの解析ページを**ブラウザで開く**
2. 作者が**取り込み用ブックマークレット**を押す → ページ内の表（話数×PV）を読み取り、JSONにしてクリップボードへ（**ページの外へは何も送らない**。読むのは作者がいま見ている画面だけ）
3. 拡張機能に戻ると貼り付けを検出（または「貼り付ける」ボタン）→ 解析して `.aiwriter/analytics/` へ追記 → 話数別グラフ・「読者がどの話で離脱しているか」（作者の創作論でいう**冒頭脱落率**、設計書6.30）を表示

- ブックマークレットが使えない場合の控え：**ページを全選択してコピー → 貼り付け**でも、表の形をこちらで解析する（雑に貼っても拾える形にしておく。投稿サイトDLファイルのヘッダー解析 `metadataParser.ts` と同じ発想）
- 規約との関係：作者が自分の画面を自分で開き、自分の操作で写している。**自動アクセスもデータ収集ボットも存在しない**。なお厳密には「ブックマークレットによるDOM読み取り」を規約がどう見るかはサイトごとに解釈の余地があるので、案内文に「表示されたページを写す道具であり、サイトへ自動アクセスはしません」と明記し、心配なら全選択コピーの控えを使えるようにしておく

### 3.3 記録の持ち方

- `.aiwriter/analytics/<サイト>.jsonl`（追記だけ。編集履歴・提案と同じ流儀でGit競合に強い）
- 1行 = `{ 日付, 作品, 話数（作品単位ならnull）, 指標名, 値, 取得経路（api/paste） }`
- 表示は執筆統計パネルの隣に「読まれ方」タブ：ポイント・ブクマの推移（なろうはAPI由来で毎日）、話数別PVの棒（貼り付けた日のスナップショット比較）、**話数別の読了率**（前話比）
- 同じ話を複数サイトへ出している作者のために、サイト横断で「この話はどこでも読まれている／なろうでだけ弱い」を並べられるようにする

## 4. 実装ロードマップ（提案）

| 段 | 中身 | 新規性・危うさ |
|---|---|---|
| **第1段** | 「この話を投稿する」：記法変換→クリップボード→投稿ページを開く、の一連化。4サイトのURL定義 | 低。既存の「投稿用にコピー」の組み立て直し |
| **第2段** | なろう小説APIの記録と「読まれ方」タブ（作品単位の推移グラフ） | 低。公式APIのみ。Nコード設定と追記ストアの新設 |
| **第3段** | ブックマークレット2種（投稿の自動入力／解析表の取り込み）と、その設定案内ページ | 中。サイトの画面変更で壊れる前提の設計（壊れても案Aへ戻るだけ）にする |

第1段・第2段は規約リスクが実質ゼロで、効果（毎回の投稿の手間・毎日のエゴサの手間）がすぐ出る。第3段は「壊れたら手動に戻る」を最初から画面に書いておく。

## 5. やらないと決めること（この報告の提案）

- **ブラウザの自動操縦（案D）はやらない**——なろうで明文違反、他サイトでもアカウントを危険に晒す
- **ログイン情報・Cookieを拡張機能で預からない**
- **サイトのHTMLを拡張機能が直接fetchしない**（公開ページであっても。「ログインしていなければ見えるから」はクロール禁止の抜け道にしない）
- **投稿の最後の1押しを自動化しない**（重複投稿・誤サイト投稿の事故は取り返しがつかない）
