# オリジナルIMEの材料

作者の依頼（2026-10-25 未明）「IMEの性能に満足がいかない場合は記録してください。後のオリジナルIME開発で使います」で作った欄。既存の日本語入力（MS-IME など）を使っていて、**小説を書く道具として不満が出た所**を、見た日・入力の種類・起きたこと・製品の側でどう逃げたかの順に1件ずつ置く。

- 置くのは、実機で見たもの・記録に残っているものだけ（推測は「見立て」と書き分ける）
- 製品の側で逃げ道を作れたものも残す（オリジナルIMEなら逃げ道が要らなくなる、という材料になる）
- 新しいものを下に足す

---

## 1. 名前を姓と名で分けて確定すると、まとまった名前として外へ知らせない（MS-IME、2026-10-24〜25）

- 作者の打ち方は「しらかば」→白樺で確定、「あかり」→灯で確定、と**姓と名を分けて確定する**。IME から拡張機能へ届くのは「しらかば→白樺」「あかり→灯」の2回の確定で、「白樺灯＝しらかばあかり」というまとまりはどこにも無い
- 製品の逃げ道：直前の確定のすぐ後ろへ続けて打った確定を、拡張機能の側でつないで名前と照らす（0.111.6〜0.111.7、設計書6.42.2）。位置と15秒の間で「続けて打ったか」を推し量っている
- オリジナルIMEなら：変換の区切り（文節）と読みを、確定のたびに外へそのまま渡せば、つなぐ推し量りが要らない

## 2. 確定の知らせの瞬間のカーソルが、IME の置いた形のまま（Windows の TSF、2026-10-24）

- 確定の知らせ（compositionend）の瞬間に選択範囲を読むと、確定した字が選ばれたまま・カーソルが行の要素の上、などの形で、字の直後に落ち着いていないことがある。画面の外の Chromium で偽の IME 入力を流すと再現しない（本物の TSF でだけ起きる）
- 製品の逃げ道：位置は次の変換の始まり（compositionstart）で1回だけ読む（0.111.7）。直したかどうかは作者の打鍵でしか確かめられない
- オリジナルIMEなら：確定のあとにカーソルを字の直後へ置き終えてから知らせる、を約束できる

## 3. 打ち直しのあと、つながらないことがある（MS-IME、2026-10-25 未明）

- 作者が一度打ち直した回に、「灯」の直前の確定として、本文に残っていない「蓮」が届いていた（記録：前=蓮・始まりの直前の字は「　白樺」）。消した確定は IME からは「取り消し」として知らされないので、拡張機能は直前の確定を「蓮」のまま覚えていて、白樺と灯をつながなかった
- 同じ日の 23:49 には、作者が「すぐに灯で確定した」のに白樺と灯がつながらなかった回が1回ある（このときは診断の記録が無く、原因は分からない）
- 製品の側：誤ってつなぐより、つながない側に倒している（消した字はつながない）
- オリジナルIMEなら：確定した字が消されたことも知らせれば、ひとつ前の確定へ戻ってつなげる

## 4. 学習すると区切りが変わる（MS-IME、2026-10-25 未明）

- 「しらかばあかり」を何度か打つと、4回目には1回の変換で「白樺灯」と確定した（記録：かな=しらかばあかり 字=白樺灯）。同じ作者・同じ名前でも、日によって確定の回数が違う
- 製品の側：1回でまとまったときも、分けて確定したときも拾えるようにした
- オリジナルIMEなら：作品の設定資料にある名前と読みを辞書として最初から持てば、学習を待たずに1回で出る（いまは製品から MS-IME の辞書へ書き出す道がある。設計書6.13）
